# BlockPick 요구사항 정의서

**문서 버전**: 1.0
**작성일**: 2025-11-20
**문서 유형**: 요구사항 명세서 (Requirements Specification)
**프로젝트**: BlockPick - 블록체인 기반 럭키드로우 플랫폼

---

## 1. 문서 개요

### 1.1 문서 목적

본 요구사항 정의서는 BlockPick 프로젝트의 모든 기능적 요구사항과 비기능적 요구사항을 명확하게 정의하고 문서화하기 위해 작성되었습니다. 이 문서는 프로젝트 이해관계자들이 시스템이 무엇을 해야 하는지, 어떤 제약 조건이 있는지, 어떤 품질 수준을 달성해야 하는지를 명확히 이해할 수 있도록 합니다.

이 문서를 통해 개발팀은 구현해야 할 기능의 범위를 파악하고, PM은 프로젝트 일정을 수립하며, QA팀은 테스트 계획을 작성하고, 비즈니스 팀은 시장 요구사항이 제대로 반영되었는지 검증할 수 있습니다. 또한 향후 기능 변경이나 추가가 필요할 때 원래의 요구사항과 비교하여 변경 영향도를 분석하는 기준이 됩니다.

### 1.2 문서 범위

본 문서는 BlockPick 모바일 애플리케이션과 이를 지원하는 백엔드 시스템, 블록체인 레이어, 외부 서비스 연동을 모두 포함합니다. 구체적으로 사용자가 모바일 앱을 통해 경험하는 모든 기능, 서버에서 처리되는 비즈니스 로직, 블록체인 네트워크와의 상호작용, 결제 게이트웨이 및 푸시 알림 서비스와의 통합이 요구사항의 범위에 포함됩니다.

단, 내부 관리자 도구, 데이터 분석 대시보드, 마케팅 자동화 시스템은 별도 프로젝트로 분리되어 이 문서의 범위에 포함되지 않습니다. 또한 iOS 버전은 1차 출시에서 제외되며, Android 버전 출시 후 추가 개발될 예정이므로 iOS 특화 요구사항은 본 문서에 포함되지 않습니다.

### 1.3 대상 독자

본 문서의 주요 독자는 다음과 같습니다.

프로젝트 매니저는 이 문서를 통해 프로젝트의 전체 범위를 파악하고 일정과 리소스를 계획합니다. 개발자는 구현해야 할 기능의 상세 사양을 이해하고 기술적 결정을 내립니다. QA 엔지니어는 테스트 케이스를 작성하고 검증 기준을 수립합니다. UI/UX 디자이너는 사용자 요구사항을 기반으로 인터페이스를 설계합니다. 비즈니스 분석가는 시장 요구사항이 제대로 반영되었는지 확인합니다. 경영진과 투자자는 제품의 가치와 시장 적합성을 평가합니다.

## 2. 프로젝트 개요

### 2.1 프로젝트 배경

현재 국내 경품 및 럭키드로우 시장은 연간 약 6조 원 규모로 성장하고 있지만, 소비자 신뢰도는 매우 낮은 상황입니다. 2024년 실시된 소비자 조사에 따르면 온라인 경품 추첨에 대한 불신도가 77%에 달하며, 응답자의 대다수가 당첨 과정의 투명성을 의심한다고 답했습니다. "내부자가 받는 것 아니냐", "컴퓨터가 조작하는 것 아니냐"는 의심이 SNS와 온라인 커뮤니티에 넘쳐나고 있습니다.

기업 입장에서도 이러한 불신을 해소하기 위해 막대한 비용을 지출하고 있습니다. 공증인을 초빙하거나, 라이브 방송으로 추첨 과정을 공개하거나, 외부 감독 기관을 활용하는 등의 방법을 사용하지만, 이러한 노력에도 불구하고 의심은 쉽게 사라지지 않습니다. 평균적으로 기업은 공정성 증명을 위해 연간 5천만 원 이상을 지출하면서도 만족스러운 결과를 얻지 못하고 있습니다.

또한 기존 럭키드로우 서비스는 높은 참가비로 인해 진입 장벽이 높습니다. 일반적으로 3만 원에서 10만 원 사이의 참가비가 요구되며, 이는 많은 잠재 고객을 배제하는 요인입니다. 소비자 조사에서 67%의 응답자가 현재의 참가비가 부담스럽다고 답했으며, 합리적인 가격대라면 참여 의향이 있다고 밝혔습니다.

BlockPick 프로젝트는 이러한 시장의 문제점을 블록체인 기술로 해결하고자 합니다. 블록체인은 본질적으로 투명하고 변경 불가능한 특성을 가지고 있어, 모든 참여 기록을 공개적으로 검증 가능한 형태로 저장할 수 있습니다. 스마트 컨트랙트를 사용하면 당첨자 선정 로직을 코드로 공개하고, 누구나 그 공정성을 확인할 수 있습니다. 동시에 플랫폼 효율화와 Event Cash 시스템을 통해 참가비를 1,000원 수준으로 낮춰 접근성을 대폭 향상시킬 수 있습니다.

### 2.2 비전 및 목표

BlockPick의 비전은 블록체인 기술을 활용하여 세계에서 가장 투명하고 공정한 럭키드로우 플랫폼을 구축하는 것입니다. 우리는 단순히 경품을 제공하는 서비스를 넘어, 사용자가 신뢰할 수 있고 즐겁게 참여할 수 있는 새로운 형태의 게임 경험을 창조하고자 합니다.

구체적인 목표는 다음과 같습니다. 첫째, 100% 투명한 당첨 과정을 보장합니다. 모든 참여 기록은 블록체인에 저장되며, 당첨자 선정은 검증 가능한 랜덤 알고리즘을 사용합니다. 사용자는 언제든지 자신의 참여 기록과 당첨 과정을 확인할 수 있습니다.

둘째, 게임처럼 즐거운 사용자 경험을 제공합니다. 단순히 버튼을 누르고 기다리는 것이 아니라, 1,000×1,000 그리드에서 전략적으로 블록을 선택하는 능동적 참여를 통해 게임의 재미를 느낄 수 있도록 합니다. 실시간 미니맵, 햅틱 피드백, 부드러운 애니메이션 등으로 몰입감을 높입니다.

셋째, 합리적인 가격으로 누구나 참여할 수 있도록 합니다. 1,000원부터 시작하는 낮은 참가비로 진입 장벽을 낮추고, Event Cash 시스템을 통해 낙첨 시에도 일부 환급을 받아 다음 게임에 재참여할 수 있도록 합니다.

넷째, 1년 내 국내 럭키드로우 시장에서 선도적 위치를 확보합니다. DAU(일일 활성 사용자) 10,000명, 월간 매출 1억 원 이상을 달성하여 지속 가능한 비즈니스 모델을 확립합니다.

### 2.3 성공 기준

BlockPick 프로젝트의 성공은 다음 정량적 지표로 측정됩니다.

사용자 지표 측면에서, 출시 3개월 내 DAU 1,000명을 달성해야 합니다. 6개월 내에는 5,000명, 1년 내에는 10,000명으로 성장해야 합니다. 사용자 유지율(Retention Rate)은 D7 기준 70% 이상, D30 기준 40% 이상을 목표로 합니다. 재참여율은 60% 이상을 유지해야 하며, 이는 Event Cash 시스템의 효과를 검증하는 지표입니다.

비즈니스 지표 측면에서, ARPU(사용자당 평균 매출)는 월 6,000원 이상이어야 합니다. 게임 참여율은 DAU의 50% 이상, 즉 일일 활성 사용자 중 절반 이상이 실제로 게임에 참여해야 합니다. 전환율은 무료 사용자에서 유료 참여자로의 전환이 15% 이상이어야 합니다.

기술 지표 측면에서, 앱 크래시율은 0.5% 미만을 유지해야 합니다. API 응답 시간은 95 백분위수 기준 500ms 이하여야 하며, 그리드 렌더링 성능은 60fps를 안정적으로 유지해야 합니다. 블록체인 트랜잭션 성공률은 99% 이상이어야 합니다.

만족도 지표 측면에서, 앱스토어 평점은 4.5점 이상을 목표로 합니다. NPS(Net Promoter Score)는 50점 이상이어야 하며, 고객 지원 응답 시간은 평균 24시간 이내여야 합니다.

## 3. 기능적 요구사항

### 3.1 사용자 인증 및 관리

**FR-001: 이메일 회원가입**
사용자는 이메일 주소를 사용하여 계정을 생성할 수 있어야 합니다. 회원가입 프로세스는 이메일 입력, 인증 코드 발송, 인증 코드 확인, 비밀번호 설정, 기본 정보 입력의 단계로 진행됩니다. 이메일은 유효한 형식이어야 하며, 이미 등록된 이메일은 사용할 수 없습니다. 인증 코드는 6자리 숫자로 구성되며, 발송 후 10분간 유효합니다. 비밀번호는 최소 8자 이상, 영문 대소문자, 숫자, 특수문자 중 3가지 이상을 포함해야 합니다.

**FR-002: 이메일 로그인**
사용자는 등록된 이메일과 비밀번호로 로그인할 수 있어야 합니다. 로그인 성공 시 JWT 액세스 토큰과 리프레시 토큰이 발급됩니다. 액세스 토큰의 유효기간은 30분이며, 리프레시 토큰은 7일입니다. 연속 5회 로그인 실패 시 계정은 15분간 잠깁니다. 로그인 상태는 디바이스에 안전하게 저장되어 앱 재시작 시에도 유지됩니다.

**FR-003: 소셜 로그인**
사용자는 Google, Apple, Kakao 계정으로 간편하게 로그인할 수 있어야 합니다. 소셜 로그인 시 사용자의 이메일, 이름, 프로필 이미지 정보를 가져오며, 사용자의 동의 하에만 정보를 수집합니다. 소셜 계정과 이메일 계정은 통합할 수 있어야 하며, 한 번 연동된 소셜 계정은 다른 BlockPick 계정과 중복 연결할 수 없습니다.

**FR-004: 비밀번호 재설정**
사용자는 비밀번호를 잊어버린 경우 재설정할 수 있어야 합니다. 등록된 이메일로 비밀번호 재설정 링크가 발송되며, 링크는 1시간 동안 유효합니다. 링크를 통해 접속하면 새로운 비밀번호를 설정할 수 있으며, 이전과 동일한 비밀번호는 사용할 수 없습니다.

**FR-005: 프로필 관리**
사용자는 자신의 프로필 정보를 조회하고 수정할 수 있어야 합니다. 수정 가능한 정보는 이름, 프로필 이미지, 전화번호, 생년월일입니다. 이메일 주소는 보안상 수정할 수 없으며, 변경이 필요한 경우 고객 지원을 통해야 합니다. 프로필 이미지는 최대 5MB까지 업로드 가능하며, JPEG, PNG 형식을 지원합니다.

**FR-006: 계정 탈퇴**
사용자는 언제든지 계정을 삭제할 수 있어야 합니다. 탈퇴 시 보유 중인 Event Cash와 Shopping Cash는 모두 소멸되며, 진행 중인 게임 참여는 취소됩니다. 탈퇴 후 30일간은 계정 복구가 가능하며, 30일 경과 후에는 모든 개인정보가 영구 삭제됩니다. 단, 법적 의무에 따라 거래 기록은 5년간 보관됩니다.

### 3.2 게임 참여

**FR-007: 게임 목록 조회**
사용자는 현재 진행 중인 모든 게임 목록을 조회할 수 있어야 합니다. 게임 목록은 타입별(DAILY, SELECT, VIBE, PRIME), 카테고리별(디지털, 패션, 뷰티, 식품 등), 정렬 기준(인기순, 최신순, 마감임박순, 가격낮은순)으로 필터링하고 정렬할 수 있습니다. 각 게임 카드에는 상품 이미지, 상품명, 참가비, 현재 참여자 수, 최대 참여자 수, 남은 시간이 표시됩니다. 목록은 페이지네이션 방식으로 로드되며, 한 페이지에 20개씩 표시됩니다.

**FR-008: 게임 상세 조회**
사용자는 특정 게임의 상세 정보를 조회할 수 있어야 합니다. 상세 정보에는 상품명, 상품 설명, 상품 이미지(최대 5장), 정가, 참가비, 당첨 확률, 현재 참여자 수, 시작 일시, 종료 일시, 게임 규칙이 포함됩니다. 실시간으로 참여자 수가 업데이트되어야 하며, WebSocket을 통해 변경사항이 즉시 반영됩니다.

**FR-009: 게임 참가**
사용자는 원하는 게임에 참가할 수 있어야 합니다. 게임 참가 프로세스는 다음과 같습니다. 첫째, 사용자가 게임 화면에 진입하여 1,000×1,000 그리드를 봅니다. 둘째, 손가락으로 터치하여 9개의 블록을 선택합니다. 선택된 블록은 시각적으로 강조 표시됩니다. 셋째, 선택 완료 후 참가하기 버튼을 누릅니다. 넷째, 참가비가 Event Cash 또는 Shopping Cash에서 차감됩니다. 잔액이 부족한 경우 충전 화면으로 이동합니다. 다섯째, 선택한 블록의 좌표가 AES-256 알고리즘으로 암호화됩니다. 여섯째, 암호화된 좌표와 지갑 주소 해시가 블록체인 스마트 컨트랙트로 전송됩니다. 일곱째, 트랜잭션이 확인되면 참가 완료 메시지가 표시되고, My Pick에 참여 내역이 추가됩니다.

**FR-010: 블록 선택**
사용자는 게임 참가 시 그리드에서 블록을 선택할 수 있어야 합니다. 그리드는 1,000×1,000 크기이며, 총 1,000,000개의 블록으로 구성됩니다. 사용자는 정확히 9개의 블록을 선택해야 하며, 선택된 블록은 3×3 형태로 인접해 있어야 합니다. 즉, 하나의 섹션을 형성해야 합니다. 이미 다른 사용자가 선택한 블록은 선택할 수 없으며, 회색으로 표시됩니다. 사용자는 확대/축소(pinch to zoom)를 사용하여 그리드를 자세히 볼 수 있으며, 드래그하여 이동할 수 있습니다. 미니맵을 통해 전체 그리드의 현황을 파악하고 빠르게 이동할 수 있습니다.

**FR-011: 참여 취소**
사용자는 게임 종료 1시간 전까지 참여를 취소할 수 있어야 합니다. 취소 시 참가비의 90%가 Event Cash로 환불되며, 10%는 수수료로 차감됩니다. 취소된 블록은 다시 선택 가능 상태가 되어 다른 사용자가 선택할 수 있습니다. 게임 종료 1시간 이내에는 취소가 불가능합니다.

### 3.3 당첨 및 보상

**FR-012: 당첨자 선정**
게임 종료 시각이 되면 자동으로 당첨자가 선정되어야 합니다. 선정 프로세스는 다음과 같습니다. 첫째, 스마트 컨트랙트가 Chainlink VRF를 사용하여 검증 가능한 랜덤 숫자를 생성합니다. 둘째, 생성된 난수를 사용하여 0부터 999,999 사이의 랜덤 블록 좌표를 결정합니다. 셋째, 해당 좌표를 포함하는 3×3 섹션을 선택한 참여자를 찾습니다. 넷째, 만약 해당 블록을 선택한 참여자가 없으면 가장 가까운 블록으로 이동하여 다시 찾습니다. 다섯째, 당첨자가 결정되면 블록체인에 기록되고, 모든 참여자에게 푸시 알림이 발송됩니다.

**FR-013: 당첨 알림**
당첨자는 즉시 푸시 알림, 이메일, SMS를 통해 당첨 사실을 통보받아야 합니다. 알림에는 게임명, 상품명, 당첨 금액 또는 상품 정보가 포함됩니다. 사용자가 앱을 열면 당첨 축하 애니메이션이 표시되며, 상품 수령 방법을 안내받습니다.

**FR-014: 상품 수령**
당첨자는 상품 수령 방식을 선택할 수 있어야 합니다. 실물 상품의 경우 배송지 주소를 입력하면 7일 이내에 배송됩니다. 디지털 상품의 경우 쿠폰 코드 또는 다운로드 링크가 즉시 제공됩니다. 현금성 상품의 경우 Shopping Cash로 자동 적립되거나, 사용자가 선택 시 등록된 계좌로 7일 이내에 입금됩니다. 상품 수령 확인 후 게임은 완료 상태로 변경됩니다.

**FR-015: Event Cash 환급**
낙첨한 사용자는 참가비의 일부를 Event Cash로 환급받아야 합니다. 환급 비율은 게임 타입과 참여자 수에 따라 다릅니다. DAILY 게임은 10% 환급, SELECT는 20%, VIBE는 30%입니다. 환급된 Event Cash는 즉시 사용 가능하며, 다음 게임 참가에 사용할 수 있습니다. 환급 내역은 My 페이지의 거래 내역에서 확인할 수 있습니다.

### 3.4 Event Cash 관리

**FR-016: Event Cash 충전**
사용자는 신용카드, 체크카드, 계좌이체를 통해 Event Cash를 충전할 수 있어야 합니다. 충전 금액은 최소 1,000원부터 최대 500,000원까지이며, 1,000원 단위로 설정할 수 있습니다. 결제는 PG사(토스페이먼츠)를 통해 처리되며, 결제 완료 후 즉시 Event Cash가 적립됩니다. 결제 실패 시 명확한 에러 메시지가 표시되고, 재시도 옵션이 제공됩니다.

**FR-017: Event Cash 사용**
사용자는 Event Cash를 게임 참가비로 사용할 수 있어야 합니다. 참가비 결제 시 Event Cash가 우선 차감되며, 부족한 경우 Shopping Cash를 함께 사용하거나 추가 충전을 요청합니다. 사용 내역은 실시간으로 My 페이지에 반영되며, 거래 내역에 기록됩니다.

**FR-018: Event Cash와 Shopping Cash 전환**
사용자는 Event Cash를 Shopping Cash로 전환할 수 있어야 합니다. 전환 비율은 1:1이며, 수수료는 없습니다. 전환 후에는 되돌릴 수 없으며, Shopping Cash는 게임 참가에 사용할 수 없고 오직 쇼핑몰에서만 사용 가능합니다. 전환은 즉시 처리되며, 전환 내역은 거래 내역에 기록됩니다.

**FR-019: Event Cash 환불**
사용자는 충전한 Event Cash의 환불을 요청할 수 있어야 합니다. 단, 게임 참가 등으로 사용한 금액은 환불 대상에서 제외됩니다. 환불 수수료는 10%이며, 등록된 계좌로 7영업일 이내에 입금됩니다. 환불 요청 후 처리 완료까지는 My 페이지에서 상태를 확인할 수 있습니다.

**FR-020: Event Cash 소멸**
Event Cash는 최종 적립일로부터 5년간 사용하지 않으면 자동으로 소멸됩니다. 소멸 3개월 전, 1개월 전, 1주일 전에 푸시 알림과 이메일로 안내됩니다. 소멸 예정 내역은 My 페이지에서 확인할 수 있습니다.

### 3.5 참여 내역 관리

**FR-021: 참여 내역 조회**
사용자는 My Pick 화면에서 자신이 참여한 모든 게임 내역을 조회할 수 있어야 합니다. 내역은 진행 중, 당첨, 미당첨, 전체의 탭으로 구분됩니다. 각 내역에는 게임명, 상품 이미지, 참가일시, 참가비, 당첨 여부, 환급 금액이 표시됩니다. 특정 게임을 선택하면 상세 정보를 볼 수 있으며, 선택했던 블록 위치와 당첨 블록 위치를 비교할 수 있습니다.

**FR-022: 블록체인 검증**
사용자는 자신의 참여 기록을 블록체인에서 직접 확인할 수 있어야 합니다. 각 참여 내역에는 트랜잭션 해시가 표시되며, 이를 탭하면 Polygon 블록체인 탐색기로 이동하여 트랜잭션 세부사항을 볼 수 있습니다. 이를 통해 참여 시각, 블록 선택 정보(암호화된 형태), 가스비 등을 확인할 수 있습니다.

### 3.6 알림

**FR-023: 푸시 알림 설정**
사용자는 설정 화면에서 푸시 알림을 켜거나 끌 수 있어야 합니다. 알림은 카테고리별로 세분화되어 게임 시작 알림, 마감 임박 알림, 결과 발표 알림, 이벤트 알림을 개별적으로 제어할 수 있습니다. 또한 알림 수신 시간대를 설정하여 야간에는 알림을 받지 않도록 할 수 있습니다.

**FR-024: 게임 시작 알림**
사용자가 관심 있는 카테고리의 새로운 게임이 시작되면 푸시 알림을 받아야 합니다. 알림에는 게임명, 상품 이미지, 참가비, 남은 좌석 수가 포함됩니다. 알림을 탭하면 해당 게임 상세 화면으로 바로 이동합니다.

**FR-025: 마감 임박 알림**
사용자가 참여한 게임의 마감이 1시간 남았을 때 푸시 알림을 받아야 합니다. 알림에는 게임명과 정확한 마감 시각이 표시됩니다. 이를 통해 사용자는 마지막 순간에 블록 선택을 변경하거나 추가 참여를 고려할 수 있습니다.

**FR-026: 결과 발표 알림**
게임 종료 후 당첨자가 선정되면 모든 참여자에게 결과 알림이 발송되어야 합니다. 당첨자에게는 축하 메시지와 함께 상품 수령 안내가 제공되고, 낙첨자에게는 위로 메시지와 함께 환급된 Event Cash 금액이 안내됩니다.

### 3.7 소셜 기능

**FR-027: 게임 공유**
사용자는 마음에 드는 게임을 친구에게 공유할 수 있어야 합니다. 게임 상세 화면에서 공유 버튼을 누르면 카카오톡, 페이스북, 인스타그램, 일반 링크 복사 옵션이 제공됩니다. 공유 링크를 통해 접속한 사용자는 해당 게임 화면으로 바로 이동하며, 공유한 사용자는 친구가 게임에 참여하면 보너스 Event Cash를 받습니다.

**FR-028: 친구 초대**
사용자는 친구를 BlockPick에 초대할 수 있어야 합니다. 초대 링크를 생성하여 전송하고, 친구가 회원가입 후 첫 게임에 참여하면 초대한 사용자와 초대받은 사용자 모두 1,000원의 Event Cash를 받습니다. 한 사용자당 최대 10명까지 초대할 수 있으며, 총 10,000원까지 보너스를 받을 수 있습니다.

### 3.8 게임 타입별 특화 기능

**FR-029: DAILY 게임**
DAILY 게임은 매일 새로운 게임이 시작되며, 참가비는 1,000원, 상품 가치는 50만 원 수준입니다. 최대 참여자 수는 500명이며, 참여자 수가 최대에 도달하거나 24시간이 경과하면 종료됩니다. 낙첨 시 10% Event Cash 환급이 제공됩니다.

**FR-030: SELECT 게임**
SELECT 게임은 프리미엄 상품을 제공하며, 참가비는 3,000원, 상품 가치는 200만 원 이상입니다. 최대 참여자 수는 300명이며, 게임 기간은 3-7일입니다. 낙첨 시 20% Event Cash 환급이 제공됩니다. 메인 홈에서 캐러셀 형태로 강조 표시됩니다.

**FR-031: VIBE 게임**
VIBE 게임은 소셜 요소가 강조된 게임으로, 참가비는 5,000원, 상품 가치는 500만 원 이상입니다. 친구와 함께 참여할 수 있는 그룹 참여 기능이 제공되며, 그룹 참여 시 할인 혜택이 있습니다. 낙첨 시 30% Event Cash 환급이 제공됩니다.

**FR-032: PRIME 게임**
PRIME 게임은 가격 맞추기 방식의 독특한 게임입니다. 사용자는 그리드 대신 상품의 정확한 가격을 예측합니다. 참가비는 1,000원이며, 정답 또는 가장 근접한 가격을 맞춘 사람이 당첨됩니다. 상품 가치는 100만 원 수준이며, 여러 명이 정답을 맞추면 그 중 랜덤으로 당첨자를 선정합니다.

### 3.9 블록체인 지갑

**FR-033: 자동 지갑 생성**
사용자가 처음 게임에 참여할 때 자동으로 블록체인 지갑이 생성되어야 합니다. 지갑은 BIP39 표준을 따르는 12단어 니모닉 문구로 복구 가능하며, 개인키는 디바이스의 보안 저장소에 암호화되어 저장됩니다. 사용자는 복잡한 블록체인 개념을 이해할 필요 없이 자동으로 처리됩니다.

**FR-034: 지갑 백업**
사용자는 My 페이지에서 지갑 백업 기능을 사용할 수 있어야 합니다. 12단어의 니모닉 문구가 표시되며, 사용자는 이를 안전한 곳에 기록해야 합니다. 백업 완료를 확인하기 위해 단어 순서를 맞추는 검증 절차가 있습니다.

**FR-035: 지갑 복구**
사용자가 디바이스를 분실하거나 앱을 재설치한 경우, 니모닉 문구를 사용하여 지갑을 복구할 수 있어야 합니다. 복구 화면에서 12개의 단어를 순서대로 입력하면 지갑이 복원되며, 이전의 모든 참여 내역과 트랜잭션을 확인할 수 있습니다.

## 4. 비기능적 요구사항

### 4.1 성능 요구사항

**NFR-001: 응답 시간**
모든 API 호출은 95 백분위수 기준 500ms 이하의 응답 시간을 가져야 합니다. 게임 목록 조회는 300ms 이하, 게임 상세 조회는 200ms 이하여야 합니다. 사용자가 체감하는 지연 시간을 최소화하기 위해 로딩 스피너는 500ms 이후에만 표시됩니다.

**NFR-002: 그리드 렌더링 성능**
1,000×1,000 그리드는 60fps를 안정적으로 유지해야 합니다. 확대/축소 및 드래그 인터랙션 중에도 프레임 드롭이 발생하지 않아야 합니다. 메모리 사용량은 500MB 이하로 제한되며, 저사양 디바이스에서도 원활하게 동작해야 합니다.

**NFR-003: 앱 시작 시간**
앱은 스플래시 화면에서 메인 홈 화면까지 3초 이내에 로드되어야 합니다. Cold start는 5초 이내, warm start는 1초 이내여야 합니다. 초기 로딩 시 필수 데이터만 요청하고, 나머지는 백그라운드에서 지연 로딩합니다.

**NFR-004: 동시 사용자 처리**
시스템은 최소 1,000명의 동시 사용자를 처리할 수 있어야 합니다. 피크 시간대에는 5,000명까지 증가할 수 있으므로, Auto Scaling을 통해 자동으로 서버 인스턴스를 증설합니다. 데이터베이스는 초당 1,000 쿼리를 처리할 수 있어야 합니다.

**NFR-005: 블록체인 트랜잭션 속도**
게임 참여 시 블록체인 트랜잭션은 평균 2초 이내에 완료되어야 합니다. Polygon 네트워크의 블록 생성 시간이 약 2초이므로, 가스비를 적절히 설정하여 다음 블록에 포함되도록 합니다.

### 4.2 보안 요구사항

**NFR-006: 데이터 암호화**
모든 네트워크 통신은 TLS 1.3을 사용하여 암호화되어야 합니다. 저장 시 민감한 데이터(개인정보, 결제 정보)는 AES-256으로 암호화됩니다. 블록체인 개인키는 디바이스의 하드웨어 보안 모듈(Android KeyStore, iOS Keychain)에 저장됩니다.

**NFR-007: 인증 보안**
JWT 토큰은 HMAC-SHA256 알고리즘으로 서명됩니다. 토큰 페이로드에는 최소한의 정보만 포함하며, 민감한 정보는 포함하지 않습니다. 리프레시 토큰은 데이터베이스에 저장되며, 로그아웃 시 즉시 무효화됩니다.

**NFR-008: 비밀번호 보안**
사용자 비밀번호는 bcrypt 알고리즘으로 해싱되며, 솔트는 자동으로 생성됩니다. 비밀번호는 평문으로 저장되지 않으며, 관리자도 볼 수 없습니다. 비밀번호 재설정은 이메일 인증을 통해서만 가능합니다.

**NFR-009: API 보안**
모든 API는 인증된 사용자만 호출할 수 있으며, 인증 없이 접근 가능한 엔드포인트는 최소화합니다. Rate Limiting을 적용하여 분당 60회, 시간당 1,000회로 요청을 제한합니다. SQL Injection, XSS 공격을 방지하기 위해 입력을 검증하고 이스케이프합니다.

**NFR-010: 개인정보 보호**
GDPR 및 국내 개인정보보호법을 준수합니다. 사용자의 동의 없이 개인정보를 수집하거나 제3자에게 제공하지 않습니다. 사용자는 언제든지 자신의 데이터를 조회, 수정, 삭제할 수 있습니다. 데이터 처리 방침은 명확하게 공개되며, 변경 시 사용자에게 알립니다.

### 4.3 가용성 요구사항

**NFR-011: 시스템 가동률**
시스템은 99.9% 이상의 가동률(uptime)을 유지해야 합니다. 이는 연간 최대 8.76시간의 다운타임만 허용됨을 의미합니다. 계획된 유지보수는 사전 공지 후 사용자가 적은 시간대(새벽 2-4시)에 진행됩니다.

**NFR-012: 장애 복구**
서버 장애 발생 시 4시간 이내에 복구되어야 합니다(RTO). 데이터 손실은 최대 1시간 이전 시점까지 허용됩니다(RPO). 이를 위해 데이터베이스는 실시간으로 복제되며, 백업은 매시간 자동으로 수행됩니다.

**NFR-013: 다중 가용 영역**
서버와 데이터베이스는 서로 다른 가용 영역(Availability Zone)에 배포됩니다. 한 영역에 장애가 발생해도 다른 영역의 서버가 서비스를 계속 제공합니다. 로드 밸런서는 자동으로 건강한 인스턴스로만 트래픽을 라우팅합니다.

### 4.4 확장성 요구사항

**NFR-014: 수평 확장**
시스템은 수평 확장이 가능해야 합니다. 사용자 수가 증가하면 서버 인스턴스를 추가하여 부하를 분산합니다. 무상태(stateless) 아키텍처를 사용하여 어떤 서버라도 모든 요청을 처리할 수 있습니다.

**NFR-015: 데이터베이스 확장**
데이터베이스는 샤딩과 파티셔닝을 지원해야 합니다. 사용자 데이터는 userId 기준으로 샤딩되며, 거래 내역은 날짜별로 파티셔닝됩니다. 읽기 부하는 복제본으로 분산하고, 쓰기는 마스터 데이터베이스에서 처리합니다.

**NFR-016: 글로벌 확장**
향후 글로벌 서비스를 위해 다중 리전 배포를 지원해야 합니다. 사용자는 지리적으로 가까운 서버로 자동 연결되며, 데이터는 리전 간 동기화됩니다. CDN을 사용하여 정적 파일은 전 세계에 분산 제공됩니다.

### 4.5 사용성 요구사항

**NFR-017: 직관적 UI**
사용자는 별도 설명 없이도 앱의 핵심 기능을 사용할 수 있어야 합니다. 첫 화면 진입 후 3번의 탭 이내에 원하는 기능에 접근할 수 있어야 합니다. 아이콘과 색상은 직관적으로 의미를 전달해야 합니다.

**NFR-018: 접근성**
시각, 청각 장애인도 앱을 사용할 수 있도록 접근성을 지원합니다. 스크린 리더를 지원하며, 모든 UI 요소에 적절한 레이블이 제공됩니다. 색상만으로 정보를 전달하지 않으며, 텍스트와 아이콘을 함께 사용합니다. 최소 글자 크기는 14pt이며, 사용자가 글자 크기를 조정할 수 있습니다.

**NFR-019: 오류 메시지**
오류 발생 시 사용자가 이해할 수 있는 명확한 메시지를 표시해야 합니다. "서버 오류"와 같은 모호한 메시지 대신, "네트워크 연결을 확인해주세요" 또는 "잔액이 부족합니다. 충전하시겠습니까?"와 같이 구체적이고 해결 방법을 제시하는 메시지를 사용합니다.

### 4.6 유지보수성 요구사항

**NFR-020: 코드 품질**
코드는 일관된 스타일 가이드를 따라야 하며, 린터(Linter)를 통과해야 합니다. 함수와 클래스에는 주석이 포함되어 의도를 명확히 합니다. 복잡도가 높은 코드는 리팩토링되어야 하며, 순환 복잡도는 10 이하로 유지됩니다.

**NFR-021: 테스트 커버리지**
유닛 테스트 커버리지는 80% 이상이어야 합니다. 모든 비즈니스 로직은 테스트로 검증되며, 크리티컬한 기능(결제, 당첨 선정)은 100% 커버리지를 목표로 합니다. 통합 테스트는 주요 사용자 플로우를 커버합니다.

**NFR-022: 로깅**
모든 중요한 이벤트는 로그로 기록되어야 합니다. 로그는 타임스탬프, 레벨(DEBUG, INFO, WARN, ERROR), 사용자 ID, 요청 ID, 메시지를 포함합니다. 에러 로그는 스택 트레이스를 포함하며, Sentry로 자동 전송됩니다.

**NFR-023: 모니터링**
시스템의 핵심 지표는 실시간으로 모니터링되어야 합니다. CPU, 메모리, 네트워크 사용률, 데이터베이스 연결 수, API 응답 시간, 에러율 등이 대시보드에 표시됩니다. 임계값을 초과하면 자동으로 알람이 발생합니다.

## 5. 제약사항

### 5.1 기술적 제약사항

**C-001: 모바일 플랫폼**
1차 출시는 Android만 지원합니다. 최소 지원 버전은 Android 8.0 (API 레벨 26)이며, 이는 2024년 기준 95% 이상의 디바이스를 커버합니다. iOS 버전은 2차 출시에서 개발될 예정이며, 동일한 Flutter 코드베이스를 사용합니다.

**C-002: 블록체인 네트워크**
현재는 Polygon Amoy 테스트넷을 사용하며, 정식 출시 전에 Polygon 메인넷으로 전환합니다. Ethereum 메인넷은 높은 가스비로 인해 사용하지 않습니다. 향후 다른 EVM 호환 체인(Arbitrum, Optimism 등)도 지원을 고려할 수 있습니다.

**C-003: 결제 게이트웨이**
결제는 국내 PG사인 토스페이먼츠를 사용합니다. 신용카드, 체크카드, 계좌이체, 가상계좌를 지원하며, 해외 카드는 1차 출시에서 지원하지 않습니다. 암호화폐 결제는 향후 검토될 예정입니다.

**C-004: 데이터 저장**
사용자의 참여 내역과 트랜잭션 기록은 법적 의무에 따라 5년간 보관됩니다. 계정 탈퇴 후에도 거래 기록은 익명화되어 보관되며, 5년 경과 후 자동 삭제됩니다.

### 5.2 비즈니스 제약사항

**C-005: 법적 규제**
BlockPick은 경품 제공 서비스로, 사행행위 규제 및 처벌 특례법을 준수해야 합니다. 경품 가액은 5만 원을 초과할 수 없다는 규제가 있지만, 블록체인 기반 추첨은 기술적 복권으로 해석될 수 있어 법무팀과 협의 중입니다. 최종 결정 전까지는 보수적으로 50만 원 이하의 상품만 제공합니다.

**C-006: 개인정보 보호**
개인정보보호법에 따라 수집하는 개인정보는 최소화되어야 합니다. 사용자의 동의 없이 마케팅 목적으로 정보를 사용할 수 없으며, 제3자 제공 시 명시적 동의가 필요합니다. 14세 미만 아동의 가입은 법정대리인 동의가 필요하므로, 1차 출시에서는 14세 이상만 가입할 수 있습니다.

**C-007: 세금 처리**
당첨 상품의 가액이 5만 원을 초과하는 경우 기타소득세(22%)가 원천징수됩니다. 사용자는 당첨 시 주민등록번호를 제공해야 하며, 제공하지 않으면 상품 수령이 불가능합니다. 세금 신고는 분기별로 국세청에 제출됩니다.

### 5.3 시간적 제약사항

**C-008: 개발 일정**
1차 MVP는 2024년 12월 말까지 완료되어야 합니다. 핵심 기능(게임 참가, 당첨 선정, Event Cash)은 우선적으로 개발되며, 부가 기능(소셜, 쇼핑몰)은 2차 출시로 연기될 수 있습니다.

**C-009: 블록체인 전환**
Polygon Amoy 테스트넷에서 메인넷으로의 전환은 정식 출시 1개월 전까지 완료되어야 합니다. 스마트 컨트랙트 감사(audit)는 외부 전문 기관에 의뢰하며, 최소 2주가 소요됩니다.

## 6. 의존성

### 6.1 외부 서비스 의존성

**D-001: Polygon 네트워크**
게임 참여와 당첨자 선정은 Polygon 블록체인에 의존합니다. 네트워크 다운타임이나 높은 가스비는 서비스에 직접적인 영향을 미칩니다. 이를 완화하기 위해 네트워크 상태를 모니터링하고, 문제 발생 시 사용자에게 안내합니다.

**D-002: Chainlink VRF**
당첨자 선정의 랜덤성은 Chainlink VRF 서비스에 의존합니다. Chainlink 노드의 가용성과 응답 시간이 당첨 선정 속도에 영향을 미칩니다. 백업 솔루션으로 on-chain 난수 생성 방법도 준비합니다.

**D-003: 토스페이먼츠**
모든 결제 처리는 토스페이먼츠 PG에 의존합니다. PG 장애 시 결제가 불가능하므로, 대체 PG(카카오페이, 네이버페이)를 백업으로 준비합니다.

**D-004: Firebase Cloud Messaging**
푸시 알림은 FCM에 의존합니다. FCM 다운타임은 드물지만, 발생 시 사용자가 중요 알림을 놓칠 수 있습니다. 이메일과 SMS를 보조 채널로 사용합니다.

**D-005: AWS 인프라**
모든 서버와 데이터베이스는 AWS에 호스팅됩니다. AWS 리전 장애에 대비하여 다중 리전 배포를 준비합니다. S3는 이미지 저장에, CloudFront는 CDN에 사용됩니다.

### 6.2 라이브러리 의존성

**D-006: Flutter 프레임워크**
모바일 앱은 Flutter 3.35.6에 의존합니다. Flutter의 버그나 호환성 문제는 앱에 영향을 미칠 수 있습니다. 안정적인 버전을 사용하고, 업그레이드 전 충분한 테스트를 수행합니다.

**D-007: web3dart**
블록체인 통합은 web3dart 라이브러리에 의존합니다. 이 라이브러리는 커뮤니티가 유지보수하며, 업데이트가 느릴 수 있습니다. 필요 시 자체 패치를 적용하거나 대체 라이브러리를 검토합니다.

**D-008: Riverpod**
상태 관리는 Riverpod에 의존합니다. Riverpod의 API 변경은 전체 앱에 영향을 미칠 수 있으므로, 메이저 버전 업그레이드는 신중하게 진행합니다.
