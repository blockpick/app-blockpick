## 1. 문서 개요

### 1.1 목적

본 문서는 BlockPick 시스템의 모든 데이터베이스 테이블, 관계, 인덱스, 제약조건을 정의합니다. 개발자는 이 문서를 기반으로 데이터베이스를 구축하고 유지보수할 수 있습니다.

### 1.2 데이터베이스 선택 이유

**PostgreSQL**을 사용하는 이유:
- **강력한 ACID 보장**: 금융 거래(Event Cash) 처리에 필수
- **JSON/JSONB 지원**: 유연한 데이터 구조 (알림 데이터, 게임 설정 등)
- **Full-text Search**: 상품 검색 기능
- **파티셔닝**: 대량의 트랜잭션 데이터 효율적 관리
- **성숙한 생태계**: 다양한 도구 및 확장 기능
- **오픈소스**: 라이선스 비용 없음

### 1.3 명명 규칙

- **테이블명**: snake_case, 복수형 (예: `users`, `game_participations`)
- **컬럼명**: snake_case (예: `user_id`, `created_at`)
- **인덱스명**: `idx_<table>_<columns>` (예: `idx_games_status_end_date`)
- **외래키명**: `fk_<table>_<referenced_table>` (예: `fk_participations_users`)
- **제약조건명**: `chk_<table>_<description>` (예: `chk_users_email_format`)

## 4. 테이블 정의

### 4.1 users (사용자)

사용자 계정 정보를 저장하는 테이블입니다.

```sql
CREATE TYPE user_role AS ENUM ('USER', 'ADMIN', 'SYSTEM');

CREATE TABLE users (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email                 VARCHAR(255) UNIQUE NOT NULL,
  password_hash         VARCHAR(255),  -- 소셜 로그인 시 NULL
  name                  VARCHAR(100) NOT NULL,
  profile_image_url     TEXT,
  phone_number          VARCHAR(20),
  birth_date            DATE,
  event_cash            INTEGER NOT NULL DEFAULT 0 CHECK (event_cash >= 0),
  shopping_cash         INTEGER NOT NULL DEFAULT 0 CHECK (shopping_cash >= 0),
  wallet_address        VARCHAR(42) UNIQUE,  -- Ethereum 주소 (0x + 40자)
  email_verified        BOOLEAN NOT NULL DEFAULT FALSE,
  role                  user_role NOT NULL DEFAULT 'USER',
  failed_login_count    INTEGER NOT NULL DEFAULT 0,
  locked_until          TIMESTAMP,
  last_login_at         TIMESTAMP,
  created_at            TIMESTAMP NOT NULL DEFAULT NOW(),
  updated_at            TIMESTAMP NOT NULL DEFAULT NOW(),
  deleted_at            TIMESTAMP,  -- Soft delete

  CONSTRAINT chk_users_email_format CHECK (email ~* '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$'),
  CONSTRAINT chk_users_phone_format CHECK (phone_number IS NULL OR phone_number ~* '^010-\d{4}-\d{4}$')
);

-- 인덱스
CREATE INDEX idx_users_email ON users(email) WHERE deleted_at IS NULL;
CREATE INDEX idx_users_wallet_address ON users(wallet_address) WHERE wallet_address IS NOT NULL;
CREATE INDEX idx_users_created_at ON users(created_at);

-- 코멘트
COMMENT ON TABLE users IS '사용자 계정 정보';
COMMENT ON COLUMN users.event_cash IS 'Event Cash 잔액 (단위: 원)';
COMMENT ON COLUMN users.shopping_cash IS 'Shopping Cash 잔액 (단위: 원)';
COMMENT ON COLUMN users.wallet_address IS '블록체인 지갑 주소 (Polygon)';
```

### 4.2 social_accounts (소셜 계정)

소셜 로그인 연동 정보를 저장하는 테이블입니다.

```sql
CREATE TYPE social_provider AS ENUM ('GOOGLE', 'APPLE', 'KAKAO');

CREATE TABLE social_accounts (

  user_id           UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,

  created_at        TIMESTAMP NOT NULL DEFAULT NOW(),

  UNIQUE(provider, provider_user_id)
);

CREATE INDEX idx_social_accounts_user_id ON social_accounts(user_id);
CREATE INDEX idx_social_accounts_provider_user_id ON social_accounts(provider, provider_user_id);

COMMENT ON TABLE social_accounts IS '소셜 로그인 연동 정보';
```

### 4.3 games (게임)

럭키드로우 게임 정보를 저장하는 테이블입니다.

```sql
CREATE TYPE game_type AS ENUM ('DAILY', 'SELECT', 'VIBE', 'PRIME');
CREATE TYPE game_category AS ENUM ('DIGITAL', 'FASHION', 'BEAUTY', 'FOOD', 'GIFT', 'HOME_LIVING');
CREATE TYPE game_status AS ENUM ('UPCOMING', 'ONGOING', 'ENDED', 'CANCELLED');

CREATE TABLE games (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  title                 VARCHAR(200) NOT NULL,
  description           TEXT,
  game_type             game_type NOT NULL,
  category              game_category NOT NULL,
  status                game_status NOT NULL DEFAULT 'UPCOMING',

  -- Product Info
  product_name          VARCHAR(200) NOT NULL,
  product_description   TEXT,
  product_image_url     TEXT NOT NULL,
  product_images        TEXT[] NOT NULL DEFAULT '{}',
  retail_price          INTEGER NOT NULL CHECK (retail_price > 0),

  -- Game Settings
  entry_fee             INTEGER NOT NULL CHECK (entry_fee >= 1000),
  max_participants      INTEGER NOT NULL CHECK (max_participants > 0),
  current_participants  INTEGER NOT NULL DEFAULT 0 CHECK (current_participants >= 0),
  refund_rate           DECIMAL(5,2) NOT NULL CHECK (refund_rate >= 0 AND refund_rate <= 100),

  -- Dates
  start_date            TIMESTAMP NOT NULL,
  end_date              TIMESTAMP NOT NULL,

  -- Winner Info (populated after game ends)
  winner_id             UUID REFERENCES users(id),
  winning_blocks        JSONB,  -- [{"x": 500, "y": 500}, ...]
  random_seed           VARCHAR(66),  -- Chainlink VRF seed

  created_at            TIMESTAMP NOT NULL DEFAULT NOW(),
  updated_at            TIMESTAMP NOT NULL DEFAULT NOW(),

  CONSTRAINT chk_games_dates CHECK (end_date > start_date),
  CONSTRAINT chk_games_participants CHECK (current_participants <= max_participants)
);

-- 인덱스
CREATE INDEX idx_games_status_end_date ON games(status, end_date DESC);
CREATE INDEX idx_games_game_type_status ON games(game_type, status);
CREATE INDEX idx_games_category_status ON games(category, status);
CREATE INDEX idx_games_end_date ON games(end_date) WHERE status = 'ONGOING';
CREATE INDEX idx_games_winner_id ON games(winner_id) WHERE winner_id IS NOT NULL;

COMMENT ON TABLE games IS '럭키드로우 게임 정보';
COMMENT ON COLUMN games.refund_rate IS '낙첨 시 환급 비율 (%)';
COMMENT ON COLUMN games.winning_blocks IS '당첨 블록 좌표 (3x3)';
COMMENT ON COLUMN games.random_seed IS 'Chainlink VRF 난수 시드';
```

### 4.4 participations (게임 참여)

사용자의 게임 참여 기록을 저장하는 테이블입니다.

```sql
CREATE TYPE prize_delivery_status AS ENUM ('PENDING', 'SHIPPED', 'DELIVERED', 'FAILED');

CREATE TABLE participations (
  id                      UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id                 UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  game_id                 UUID NOT NULL REFERENCES games(id) ON DELETE CASCADE,

  -- Block Selection
  selected_blocks         JSONB NOT NULL,  -- [{"x": 500, "y": 500}, ...]
  entry_fee               INTEGER NOT NULL CHECK (entry_fee > 0),

  -- Winner Info
  is_winner               BOOLEAN NOT NULL DEFAULT FALSE,
  refund_amount           INTEGER NOT NULL DEFAULT 0 CHECK (refund_amount >= 0),

  -- Blockchain
  transaction_hash        VARCHAR(66) UNIQUE,  -- 0x + 64자
  encrypted_coordinates   TEXT NOT NULL,  -- AES-256 암호화된 좌표

  -- Prize Delivery (for winners)
  prize_delivery_status   prize_delivery_status,
  prize_delivery_address  JSONB,  -- {recipient, phone, address, ...}
  prize_delivered_at      TIMESTAMP,

  created_at              TIMESTAMP NOT NULL DEFAULT NOW(),
  updated_at              TIMESTAMP NOT NULL DEFAULT NOW(),
  cancelled_at            TIMESTAMP,

  UNIQUE(user_id, game_id),  -- 한 게임에 한 번만 참여 가능
  CONSTRAINT chk_participations_blocks_count CHECK (jsonb_array_length(selected_blocks) = 9)
);

-- 인덱스
CREATE INDEX idx_participations_user_id ON participations(user_id);
CREATE INDEX idx_participations_game_id ON participations(game_id);
CREATE INDEX idx_participations_is_winner ON participations(is_winner) WHERE is_winner = TRUE;
CREATE INDEX idx_participations_transaction_hash ON participations(transaction_hash);
CREATE INDEX idx_participations_created_at ON participations(created_at DESC);

COMMENT ON TABLE participations IS '게임 참여 기록';
COMMENT ON COLUMN participations.selected_blocks IS '선택한 9개 블록의 좌표';
COMMENT ON COLUMN participations.encrypted_coordinates IS 'AES-256 암호화된 블록 좌표 (블록체인 저장용)';
```

### 4.5 transactions (거래 내역)

Event Cash 및 Shopping Cash 거래 내역을 저장하는 테이블입니다.

```sql
CREATE TYPE transaction_type AS ENUM (
  'CHARGE',           -- 충전
  'USE',              -- 사용 (게임 참가비)
  'REFUND',           -- 환불
  'CASH_BACK',        -- 낙첨 환급
  'CONVERSION',       -- Event ↔ Shopping 전환
  'BONUS',            -- 보너스
  'PRIZE_CASH'        -- 현금성 상품 당첨
);

CREATE TABLE transactions (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  type            transaction_type NOT NULL,
  amount          INTEGER NOT NULL,  -- 양수: 증가, 음수: 감소
  balance_before  INTEGER NOT NULL,  -- 거래 전 잔액
  balance_after   INTEGER NOT NULL,  -- 거래 후 잔액
  description     TEXT NOT NULL,
  related_id      UUID,  -- 관련 엔티티 ID (게임 ID, 참여 ID 등)
  metadata        JSONB,  -- 추가 정보 (PG 결제 ID, 전환 방향 등)
  created_at      TIMESTAMP NOT NULL DEFAULT NOW()
);

-- 파티셔닝을 위한 인덱스 (월별 파티셔닝)
CREATE INDEX idx_transactions_user_id_created_at ON transactions(user_id, created_at DESC);
CREATE INDEX idx_transactions_type ON transactions(type);
CREATE INDEX idx_transactions_related_id ON transactions(related_id) WHERE related_id IS NOT NULL;
CREATE INDEX idx_transactions_created_at ON transactions(created_at DESC);

COMMENT ON TABLE transactions IS 'Event Cash 및 Shopping Cash 거래 내역';
COMMENT ON COLUMN transactions.amount IS '거래 금액 (양수: 증가, 음수: 감소)';
COMMENT ON COLUMN transactions.metadata IS '추가 정보 (JSON 형식)';

-- 월별 파티셔닝 (2025년 1월부터)
CREATE TABLE transactions_2025_01 PARTITION OF transactions
  FOR VALUES FROM ('2025-01-01') TO ('2025-02-01');

CREATE TABLE transactions_2025_02 PARTITION OF transactions
  FOR VALUES FROM ('2025-02-01') TO ('2025-03-01');

-- ... 계속 생성 (자동화 스크립트로 관리)
```

### 4.6 wallets (블록체인 지갑)

사용자의 블록체인 지갑 정보를 저장하는 테이블입니다.

```sql
CREATE TABLE wallets (
  id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id           UUID UNIQUE NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  address           VARCHAR(42) UNIQUE NOT NULL,  -- 0x + 40자
  encrypted_private_key TEXT,  -- 서버에는 저장하지 않음 (클라이언트에서 관리)
  network_name      VARCHAR(50) NOT NULL DEFAULT 'Polygon Mainnet',
  chain_id          INTEGER NOT NULL DEFAULT 137,  -- Polygon Mainnet
  has_backed_up     BOOLEAN NOT NULL DEFAULT FALSE,
  created_at        TIMESTAMP NOT NULL DEFAULT NOW(),
  updated_at        TIMESTAMP NOT NULL DEFAULT NOW(),

  CONSTRAINT chk_wallets_address_format CHECK (address ~* '^0x[a-fA-F0-9]{40}$')
);

CREATE INDEX idx_wallets_user_id ON wallets(user_id);
CREATE INDEX idx_wallets_address ON wallets(address);

COMMENT ON TABLE wallets IS '블록체인 지갑 정보';
COMMENT ON COLUMN wallets.encrypted_private_key IS '개인키 (사용 안 함 - 클라이언트에서 관리)';
COMMENT ON COLUMN wallets.has_backed_up IS '사용자가 복구 문구를 백업했는지 여부';
```

### 5.1 인덱스 설계 원칙

1. **WHERE 절 최적화**: 자주 조회되는 조건에 인덱스 생성
2. **조인 최적화**: 외래키에 인덱스 생성
3. **정렬 최적화**: ORDER BY에 사용되는 컬럼 인덱스
4. **복합 인덱스**: 여러 컬럼을 함께 조회하는 경우
5. **부분 인덱스**: WHERE 조건을 추가하여 인덱스 크기 축소

### 5.2 주요 인덱스 목록

| 테이블 | 인덱스명 | 컬럼 | 타입 | 목적 |
|--------|----------|------|------|------|

## 6. 파티셔닝 전략

### 6.1 transactions 테이블 파티셔닝

거래 내역은 시간이 지날수록 데이터가 급증하므로 월별 파티셔닝을 적용합니다.

```sql
-- 부모 테이블 (파티셔닝)
CREATE TABLE transactions (
  id              UUID NOT NULL DEFAULT gen_random_uuid(),
  user_id         UUID NOT NULL,
  type            transaction_type NOT NULL,
  amount          INTEGER NOT NULL,
  balance_before  INTEGER NOT NULL,
  balance_after   INTEGER NOT NULL,
  description     TEXT NOT NULL,
  related_id      UUID,
  metadata        JSONB,
  created_at      TIMESTAMP NOT NULL DEFAULT NOW(),

  PRIMARY KEY (id, created_at)  -- 파티션 키 포함
) PARTITION BY RANGE (created_at);

-- 월별 파티션 생성 (자동화)
CREATE TABLE transactions_2025_01 PARTITION OF transactions
  FOR VALUES FROM ('2025-01-01') TO ('2025-02-01');

CREATE TABLE transactions_2025_02 PARTITION OF transactions
  FOR VALUES FROM ('2025-02-01') TO ('2025-03-01');

-- 자동 파티션 생성 함수
CREATE OR REPLACE FUNCTION create_monthly_partition(
  table_name TEXT,
  partition_date DATE
) RETURNS VOID AS $$
DECLARE
  partition_name TEXT;
  start_date DATE;
  end_date DATE;
BEGIN
  partition_name := table_name || '_' || TO_CHAR(partition_date, 'YYYY_MM');
  start_date := DATE_TRUNC('month', partition_date);
  end_date := start_date + INTERVAL '1 month';

  EXECUTE format(
    'CREATE TABLE IF NOT EXISTS %I PARTITION OF %I FOR VALUES FROM (%L) TO (%L)',
    partition_name, table_name, start_date, end_date
  );
END;
$$ LANGUAGE plpgsql;

-- 다음 3개월치 파티션 미리 생성
SELECT create_monthly_partition('transactions', CURRENT_DATE + (i || ' months')::INTERVAL)
FROM generate_series(0, 2) AS i;
```

### 6.2 파티션 유지보수

**자동 파티션 생성** (매월 1일 실행):
```sql
-- Cron 작업 (pg_cron 확장 사용)
SELECT cron.schedule(
  'create-next-month-partitions',
  '0 0 1 * *',  -- 매월 1일 00:00
  $$
    SELECT create_monthly_partition('transactions', CURRENT_DATE + INTERVAL '2 months');
  $$
);
```

**오래된 파티션 삭제** (5년 후):
```sql
-- 5년 이상 오래된 파티션 삭제
DROP TABLE IF EXISTS transactions_2020_01;
```

### 7.1 체크 제약조건

```sql
-- Event Cash는 항상 0 이상

  CHECK (event_cash >= 0);
```

#### 7.2.1 updated_at 자동 업데이트

```sql
-- ... 다른 테이블도 동일하게 적용
```

#### 7.2.2 거래 내역 자동 생성

```sql
-- Event Cash 충전/사용 시 자동으로 transactions 테이블에 기록
CREATE OR REPLACE FUNCTION log_cash_transaction()
RETURNS TRIGGER AS $$
BEGIN
  -- Event Cash 변경 시
  IF NEW.event_cash != OLD.event_cash THEN
    INSERT INTO transactions (user_id, type, amount, balance_before, balance_after, description)
    VALUES (
      NEW.id,
      CASE
        WHEN NEW.event_cash > OLD.event_cash THEN 'CHARGE'
        ELSE 'USE'
      END,
      NEW.event_cash - OLD.event_cash,
      OLD.event_cash,
      NEW.event_cash,
      'Event Cash 변경'
    );
  END IF;

  -- Shopping Cash 변경 시
  IF NEW.shopping_cash != OLD.shopping_cash THEN
    INSERT INTO transactions (user_id, type, amount, balance_before, balance_after, description)
    VALUES (
      NEW.id,
      'CONVERSION',
      NEW.shopping_cash - OLD.shopping_cash,
      OLD.shopping_cash,
      NEW.shopping_cash,
      'Shopping Cash 변경'
    );
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_log_cash_transaction AFTER UPDATE ON users
  FOR EACH ROW
  WHEN (NEW.event_cash != OLD.event_cash OR NEW.shopping_cash != OLD.shopping_cash)
  EXECUTE FUNCTION log_cash_transaction();
```

#### 7.2.3 게임 참여 시 참여자 수 증가

```sql
CREATE OR REPLACE FUNCTION increment_game_participants()
RETURNS TRIGGER AS $$
BEGIN
  UPDATE games
  SET current_participants = current_participants + 1
  WHERE id = NEW.game_id;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_increment_participants AFTER INSERT ON participations
  FOR EACH ROW EXECUTE FUNCTION increment_game_participants();
```

#### 7.2.4 게임 참여 취소 시 참여자 수 감소

```sql
CREATE OR REPLACE FUNCTION decrement_game_participants()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.cancelled_at IS NOT NULL AND OLD.cancelled_at IS NULL THEN
    UPDATE games
    SET current_participants = current_participants - 1
    WHERE id = NEW.game_id;
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_decrement_participants AFTER UPDATE ON participations
  FOR EACH ROW EXECUTE FUNCTION decrement_game_participants();
```

## 8. 백업 및 복구

### 8.1 백업 전략

**백업 주기**:
- **전체 백업**: 매일 새벽 2시 (자동)
- **증분 백업**: 매 6시간마다
- **WAL(Write-Ahead Logging) 아카이빙**: 실시간

**백업 보관 정책**:
- 일일 백업: 30일 보관
- 주간 백업: 3개월 보관
- 월간 백업: 1년 보관

### 8.2 백업 명령어

```bash
# 전체 데이터베이스 백업
pg_dump -h localhost -U postgres -F c -b -v -f blockpick_backup_$(date +%Y%m%d).dump blockpick_prod

# 특정 테이블만 백업
pg_dump -h localhost -U postgres -t users -t games -F c -f tables_backup.dump blockpick_prod

# SQL 형식으로 백업
pg_dump -h localhost -U postgres -F p -f blockpick_backup.sql blockpick_prod
```

### 8.3 복구 명령어

```bash
# 전체 데이터베이스 복구
pg_restore -h localhost -U postgres -d blockpick_prod -v blockpick_backup.dump

# 특정 테이블만 복구
pg_restore -h localhost -U postgres -d blockpick_prod -t users blockpick_backup.dump

# SQL 파일로 복구
psql -h localhost -U postgres -d blockpick_prod -f blockpick_backup.sql
```

### 8.4 Point-in-Time Recovery (PITR)

```bash
# WAL 아카이빙 설정 (postgresql.conf)
wal_level = replica
archive_mode = on
archive_command = 'cp %p /mnt/backup/wal/%f'

# 특정 시점으로 복구
restore_command = 'cp /mnt/backup/wal/%f %p'
recovery_target_time = '2025-11-20 14:30:00'
```
