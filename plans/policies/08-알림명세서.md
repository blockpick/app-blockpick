## 1. 문서 개요

### 1.1 목적

본 문서는 BlockPick 플랫폼의 알림 시스템을 상세히 정의합니다. 푸시 알림, 인앱 알림, 이메일 알림 등 모든 알림 유형의 발송 조건, 내용, 타이밍, 형식을 명확히 기술하여 일관되고 효과적인 사용자 커뮤니케이션을 보장합니다.

### 1.2 범위

본 문서는 BlockPick에서 발송하는 모든 알림을 다룹니다. 여기에는 게임 관련 알림(시작, 종료, 당첨), Event Cash 관련 알림(충전, 출금), 계정 관련 알림(로그인, 보안), 마케팅 알림(프로모션, 이벤트)이 포함됩니다. 각 알림의 발송 조건, 제목, 본문, 딥링크, 우선순위, 발송 시간 등을 상세히 정의합니다.

### 1.3 대상 독자

본 문서의 주요 독자는 다음과 같습니다. 첫째, 개발팀은 알림 발송 로직을 구현합니다. 둘째, 운영팀은 알림 내용을 관리하고 발송을 모니터링합니다. 셋째, 마케팅팀은 프로모션 알림을 기획하고 실행합니다. 넷째, 고객 지원팀은 알림 관련 사용자 문의에 답변합니다.

### 1.4 용어 정의

**푸시 알림(Push Notification)**: 앱이 실행 중이지 않을 때도 사용자의 기기 화면에 표시되는 알림입니다. Firebase Cloud Messaging(FCM)을 통해 발송됩니다.

**인앱 알림(In-App Notification)**: 앱이 실행 중일 때 앱 내에서 표시되는 알림입니다. 일반적으로 상단 바 또는 팝업 형태로 나타납니다.

**이메일 알림(Email Notification)**: 사용자의 이메일 주소로 발송되는 알림입니다.

**알림 센터(Notification Center)**: 앱 내에서 과거 알림 내역을 확인할 수 있는 화면입니다.

**딥링크(Deep Link)**: 알림을 터치했을 때 앱의 특정 화면으로 바로 이동하는 링크입니다.

**알림 채널(Notification Channel, Android)**: Android에서 알림을 분류하는 단위입니다. 사용자는 채널별로 알림을 켜거나 끌 수 있습니다.

**우선순위(Priority)**: 알림의 중요도를 나타냅니다. High, Default, Low로 구분되며, 높은 우선순위 알림은 사용자에게 더 눈에 띄게 표시됩니다.

**배지(Badge)**: 앱 아이콘에 표시되는 숫자로, 읽지 않은 알림의 개수를 나타냅니다.

## 2. 알림 시스템 개요

### 2.1 알림의 역할

BlockPick에서 알림은 다음과 같은 중요한 역할을 합니다.

**정보 전달**: 게임 결과, 상금 지급, Event Cash 충전 완료 등 중요한 정보를 사용자에게 즉시 알립니다.

**참여 유도**: 새로운 게임 시작, 특별 이벤트 등을 알려 사용자의 재방문과 참여를 유도합니다.

**보안 알림**: 새로운 기기에서 로그인, 출금 요청 등 보안 관련 활동을 사용자에게 알려 계정을 보호합니다.

**사용자 유지**: 비활성 사용자에게 알림을 보내 재참여를 유도하고, 플랫폼 이탈을 방지합니다.

**브랜드 커뮤니케이션**: 프로모션, 이벤트, 새 기능 소개 등을 통해 브랜드와 사용자 간의 관계를 강화합니다.

### 2.2 알림 채널 구성

BlockPick은 세 가지 주요 알림 채널을 사용합니다.

**푸시 알림**: 가장 즉각적이고 눈에 띄는 알림입니다. 시간에 민감한 정보(게임 종료, 당첨 등)를 전달하는 데 적합합니다.

**인앱 알림**: 앱 사용 중에 실시간으로 정보를 제공합니다. 게임 참여자 수 업데이트, 친구의 당첨 등 맥락적 정보를 전달합니다.

**이메일 알림**: 상세한 정보를 제공하거나, 중요한 문서(영수증, 약관 변경 등)를 전달하는 데 적합합니다. 푸시 알림을 놓친 사용자에게도 도달할 수 있습니다.

### 2.3 알림 카테고리

모든 알림은 다음 카테고리로 분류됩니다.

**거래 알림(Transactional)**: 사용자의 액션에 대한 응답으로 발송되는 알림입니다. 예: 게임 참가 확인, Event Cash 충전 완료, 상금 지급. 이 알림은 사용자 설정과 관계없이 항상 발송됩니다.

**시스템 알림(System)**: 중요한 시스템 이벤트를 알리는 알림입니다. 예: 게임 종료, 당첨 결과. 이 알림도 일반적으로 사용자 설정과 관계없이 발송됩니다.

**마케팅 알림(Marketing)**: 프로모션, 이벤트, 새 기능 등을 알리는 알림입니다. 사용자는 설정에서 이 알림을 끌 수 있습니다.

**보안 알림(Security)**: 계정 보안 관련 알림입니다. 예: 새 기기 로그인, 비밀번호 변경. 항상 발송됩니다.

**소셜 알림(Social)**: 친구 활동 관련 알림입니다. 예: 친구가 초대 수락, 친구가 당첨. 사용자는 이 알림을 끌 수 있습니다.

### 2.4 알림 우선순위

알림은 중요도에 따라 우선순위가 부여됩니다.

**High (높음)**: 즉시 사용자의 주의를 요하는 알림입니다. 소리와 진동이 함께 발생하며, 헤드업 알림(화면 상단에 떠오르는 형태)으로 표시됩니다. 예: 당첨 알림, 보안 알림.

**Default (기본)**: 일반적인 알림입니다. 알림 센터에 표시되며, 사용자 설정에 따라 소리나 진동이 발생할 수 있습니다. 예: 게임 종료 알림, Event Cash 충전 완료.

**Low (낮음)**: 긴급하지 않은 정보성 알림입니다. 소리나 진동 없이 조용히 알림 센터에 표시됩니다. 예: 새 프로모션 시작, 친구 활동.

## 3. 알림 유형 정의

### 3.1 게임 관련 알림

**NOTIF-001: 게임 시작 알림**

**발송 조건**: 사용자가 관심 표시한 게임 타입의 새 게임이 시작될 때. 예를 들어, 사용자가 PRIME 게임에 자주 참여한다면 새로운 PRIME 게임이 열릴 때 알림을 받습니다.

**발송 시점**: 게임 시작 시각에 즉시 발송.

**제목**: "새로운 [게임타입] 게임이 시작되었습니다!"

**본문**: "[게임타입] 게임이 방금 시작되었어요. 총 상금 [상금액] 캐시! 지금 참여하세요."

**예시**: "새로운 PRIME 게임이 시작되었습니다! PRIME 게임이 방금 시작되었어요. 총 상금 5,000,000 캐시! 지금 참여하세요."

**딥링크**: 해당 게임의 상세 화면으로 이동.

**우선순위**: Default

**채널**: 푸시, 인앱

**설정 가능 여부**: 마케팅 알림으로 분류되어 사용자가 끌 수 있음.

**NOTIF-002: 게임 종료 임박 알림**

**발송 조건**: 사용자가 참여한 게임이 종료 30분 전일 때.

**발송 시점**: 게임 종료 30분 전.

**제목**: "[게임명]이 곧 종료됩니다!"

**본문**: "참여하신 [게임타입] 게임이 30분 후 종료됩니다. 결과를 기대해 주세요!"

**예시**: "DAILY #1234가 곧 종료됩니다! 참여하신 DAILY 게임이 30분 후 종료됩니다. 결과를 기대해 주세요!"

**딥링크**: 해당 게임의 상세 화면 또는 내 참가 목록.

**우선순위**: Default

**채널**: 푸시

**설정 가능 여부**: 시스템 알림으로 항상 발송.

**NOTIF-003: 게임 종료 알림**

**발송 조건**: 사용자가 참여한 게임이 종료되었을 때.

**발송 시점**: 게임 종료 직후, 당첨자 선정 전.

**제목**: "[게임명]이 종료되었습니다"

**본문**: "참여하신 [게임타입] 게임이 종료되었습니다. 곧 당첨 결과가 발표됩니다."

**예시**: "SELECT #567이 종료되었습니다. 참여하신 SELECT 게임이 종료되었습니다. 곧 당첨 결과가 발표됩니다."

**딥링크**: 해당 게임의 결과 화면.

**우선순위**: Default

**채널**: 푸시

**설정 가능 여부**: 시스템 알림으로 항상 발송.

**NOTIF-004: 당첨 알림**

**발송 조건**: 사용자가 게임에서 당첨되었을 때.

**발송 시점**: 당첨자 선정 및 상금 지급 직후.

**제목**: "축하합니다! [게임명]에서 당첨되셨습니다! 🎉"

**본문**: "당첨을 축하드립니다! [상금액] 캐시가 지급되었습니다. 지금 바로 확인하세요!"

**예시**: "축하합니다! DAILY #1234에서 당첨되셨습니다! 🎉 당첨을 축하드립니다! 200,000 캐시가 지급되었습니다. 지금 바로 확인하세요!"

**딥링크**: 당첨 내역 화면 또는 해당 게임의 결과 화면.

**우선순위**: High

**채널**: 푸시, 이메일

**설정 가능 여부**: 항상 발송 (중요 알림).

**추가 효과**: 앱 아이콘에 배지 표시, 축하 사운드 재생 (앱 내).

**NOTIF-005: 낙첨 알림**

**발송 조건**: 사용자가 게임에서 당첨되지 않았을 때.

**발송 시점**: 당첨자 선정 직후.

**제목**: "[게임명] 결과가 발표되었습니다"

**본문**: "아쉽게도 이번에는 당첨되지 않으셨습니다. 다음 게임에 도전해 보세요!"

**예시**: "VIBE #789 결과가 발표되었습니다. 아쉽게도 이번에는 당첨되지 않으셨습니다. 다음 게임에 도전해 보세요!"

**딥링크**: 게임 목록 화면.

**우선순위**: Low

**채널**: 푸시 (선택 사항)

**설정 가능 여부**: 사용자가 끌 수 있음. 기본적으로는 꺼져 있으며, 사용자가 원하면 켤 수 있습니다.

**NOTIF-006: 게임 참가 확인**

**발송 조건**: 사용자가 게임에 성공적으로 참가했을 때.

**발송 시점**: 블록체인에 참여 기록이 확인된 직후.

**제목**: "[게임명] 참가가 완료되었습니다"

**본문**: "[게임타입] 게임 참가가 완료되었습니다. 행운을 빕니다!"

**예시**: "PRIME #999 참가가 완료되었습니다. PRIME 게임 참가가 완료되었습니다. 행운을 빕니다!"

**딥링크**: 내 참가 목록.

**우선순위**: Default

**채널**: 인앱, (선택 사항) 푸시

**설정 가능 여부**: 거래 알림으로 기본 발송, 푸시는 끌 수 있음.

### 3.2 Event Cash 관련 알림

**NOTIF-007: Event Cash 충전 완료**

**발송 조건**: Event Cash 충전이 성공적으로 완료되었을 때.

**발송 시점**: 결제 승인 및 Event Cash 지급 직후.

**제목**: "Event Cash 충전이 완료되었습니다"

**본문**: "[충전액] 캐시가 충전되었습니다. 현재 잔액: [잔액] 캐시"

**예시**: "Event Cash 충전이 완료되었습니다. 10,000 캐시가 충전되었습니다. 현재 잔액: 25,000 캐시"

**딥링크**: Event Cash 화면 또는 거래 내역.

**우선순위**: Default

**채널**: 푸시, 인앱, 이메일 (영수증 첨부)

**설정 가능 여부**: 거래 알림으로 항상 발송.

**NOTIF-008: Event Cash 충전 실패**

**발송 조건**: Event Cash 충전이 실패했을 때.

**발송 시점**: 결제 실패가 확인된 직후.

**제목**: "Event Cash 충전에 실패했습니다"

**본문**: "결제 처리 중 문제가 발생했습니다. 다시 시도해 주세요. [오류 메시지]"

**예시**: "Event Cash 충전에 실패했습니다. 결제 처리 중 문제가 발생했습니다. 다시 시도해 주세요. 카드 승인이 거부되었습니다."

**딥링크**: Event Cash 충전 화면.

**우선순위**: High

**채널**: 푸시, 인앱

**설정 가능 여부**: 거래 알림으로 항상 발송.

**NOTIF-009: 출금 신청 접수**

**발송 조건**: 사용자가 출금을 신청했을 때.

**발송 시점**: 출금 신청이 시스템에 접수된 직후.

**제목**: "출금 신청이 접수되었습니다"

**본문**: "[출금액] 캐시 출금 신청이 접수되었습니다. 처리까지 최대 3일 소요됩니다."

**예시**: "출금 신청이 접수되었습니다. 100,000 캐시 출금 신청이 접수되었습니다. 처리까지 최대 3일 소요됩니다."

**딥링크**: 거래 내역.

**우선순위**: Default

**채널**: 푸시, 이메일

**설정 가능 여부**: 거래 알림으로 항상 발송.

**NOTIF-010: 출금 완료**

**발송 조건**: 출금이 성공적으로 완료되어 계좌에 입금되었을 때.

**발송 시점**: 은행 이체 완료 확인 직후.

**제목**: "출금이 완료되었습니다"

## 4. 푸시 알림 명세

### 4.1 푸시 알림 기술 스택

BlockPick의 푸시 알림은 Firebase Cloud Messaging(FCM)을 사용하여 구현됩니다.

**FCM 버전**: FCM HTTP v1 API를 사용합니다. 레거시 API는 사용하지 않습니다.

**플랫폼 지원**: iOS (APNs를 통해) 및 Android (FCM 직접)를 모두 지원합니다.

**토큰 관리**: 사용자가 앱을 설치하고 푸시 알림 권한을 허용하면 FCM 토큰이 생성됩니다. 이 토큰은 서버에 저장되며, 사용자별로 최대 5개의 기기 토큰을 저장할 수 있습니다(여러 기기 사용 지원).

### 4.2 푸시 알림 페이로드 구조

FCM 푸시 알림의 페이로드는 다음과 같은 구조를 가집니다.

```json
{
  "message": {
    "token": "사용자의 FCM 토큰",
    "notification": {
      "title": "알림 제목",
      "body": "알림 본문"
    },
    "data": {
      "notificationId": "고유 알림 ID",
      "type": "알림 유형 (예: GAME_WIN)",
      "deepLink": "딥링크 URL",
      "timestamp": "발송 시각 (Unix timestamp)",
      "additionalData": "추가 데이터 (JSON 문자열)"
    },
    "android": {
      "priority": "high",
      "notification": {
        "channel_id": "게임 알림 채널 ID",
        "sound": "default",
        "color": "#FF5722"
      }
    },
    "apns": {
      "headers": {
        "apns-priority": "10"
      },
      "payload": {
        "aps": {
          "alert": {
            "title": "알림 제목",
            "body": "알림 본문"
          },
          "sound": "default",
          "badge": 1
        }
      }
    }
  }
}
```

### 4.3 Android 알림 채널

Android 8.0(API 레벨 26) 이상에서는 알림 채널을 정의해야 합니다. BlockPick은 다음 채널을 사용합니다.

**게임 알림 (game_notifications)**: 게임 시작, 종료, 당첨 등 게임 관련 알림. 중요도: High. 소리: 활성화. 진동: 활성화.

**거래 알림 (transaction_notifications)**: Event Cash 충전, 출금 등 거래 관련 알림. 중요도: Default. 소리: 활성화. 진동: 비활성화.

**보안 알림 (security_notifications)**: 로그인, 비밀번호 변경 등 보안 관련 알림. 중요도: High. 소리: 활성화. 진동: 활성화.

**마케팅 알림 (marketing_notifications)**: 프로모션, 이벤트 등 마케팅 관련 알림. 중요도: Low. 소리: 비활성화. 진동: 비활성화.

**소셜 알림 (social_notifications)**: 친구 활동 관련 알림. 중요도: Low. 소리: 비활성화. 진동: 비활성화.

사용자는 Android 설정에서 각 채널을 개별적으로 켜거나 끌 수 있습니다.

### 4.4 iOS 알림 권한

iOS에서는 앱이 처음 실행될 때 푸시 알림 권한을 요청합니다.

**권한 요청 시점**: 온보딩 완료 직후, 사용자가 첫 번째 화면을 볼 때.

**권한 요청 메시지**: "BlockPick이 중요한 게임 결과와 상금 정보를 알려드립니다. 알림을 허용하시겠습니까?"

**권한 거부 시**: 사용자가 거부하더라도 앱은 정상적으로 사용 가능합니다. 단, 설정 화면에 "알림 권한이 꺼져 있습니다. 중요한 정보를 놓칠 수 있습니다"라는 안내를 표시하고, 설정 앱으로 이동하는 버튼을 제공합니다.

### 4.5 푸시 알림 딥링크

푸시 알림을 터치하면 앱이 실행되고 특정 화면으로 바로 이동합니다. 딥링크는 다음 형식을 사용합니다.

**형식**: `blockpick://[스크린명]/[파라미터]`

**예시**:
- 게임 상세: `blockpick://game/GAME_ID_123`
- 당첨 내역: `blockpick://win/WIN_ID_456`
- Event Cash 화면: `blockpick://cash`
- 거래 내역: `blockpick://transactions`
- 프로모션 상세: `blockpick://promotion/PROMO_ID_789`

앱은 딥링크를 파싱하여 해당 화면으로 내비게이션합니다.

### 4.6 푸시 알림 우선순위 및 타이밍

**High 우선순위 알림**: 즉시 발송됩니다. 사용자의 Do Not Disturb 설정을 무시하고 표시될 수 있습니다(iOS 15+에서는 "Time Sensitive" 플래그 사용).

**Default 우선순위 알림**: 일반적인 타이밍에 발송됩니다. Do Not Disturb 설정을 존중합니다.

**Low 우선순위 알림**: 사용자의 활동이 적은 시간대(예: 오후 2시-5시)를 선택하여 발송합니다. 배치로 묶어서 발송할 수 있습니다.

**조용한 시간대 설정**: 사용자는 알림을 받지 않을 시간대를 설정할 수 있습니다(예: 밤 10시 ~ 아침 8시). 이 시간대에는 Low 우선순위 알림이 발송되지 않습니다. High와 Default 우선순위는 예외적으로 발송됩니다.

## 5. 인앱 알림 명세

### 5.1 인앱 알림 개요

인앱 알림은 사용자가 앱을 사용 중일 때 앱 내에서 표시되는 알림입니다. 푸시 알림과 달리 앱이 포그라운드 상태일 때만 표시됩니다.

### 5.2 인앱 알림 표시 방식

인앱 알림은 다음 두 가지 방식으로 표시됩니다.

**스낵바(Snackbar)**: 화면 하단에서 잠깐 나타났다가 사라지는 간단한 메시지입니다. 일반적으로 3-5초간 표시됩니다. 거래 완료, 게임 참가 확인 등에 사용됩니다.

**배너(Banner)**: 화면 상단에서 슬라이드되어 나타나는 알림입니다. 더 중요한 정보를 전달하며, 사용자가 터치하여 관련 화면으로 이동할 수 있습니다. 당첨 알림, 친구 활동 등에 사용됩니다.

### 5.3 인앱 알림 우선순위

여러 인앱 알림이 동시에 발생하면 우선순위에 따라 순차적으로 표시됩니다.

**우선순위 1 (최고)**: 당첨 알림, 보안 경고

**우선순위 2**: Event Cash 충전/출금 완료, 게임 종료

**우선순위 3**: 친구 활동, 프로모션

인앱 알림 큐에 쌓이며, 하나가 사라진 후 다음 알림이 표시됩니다.

### 5.4 인앱 알림 상호작용

**터치**: 알림을 터치하면 관련 화면으로 이동합니다. 딥링크 로직은 푸시 알림과 동일합니다.

**스와이프**: 스낵바나 배너를 옆으로 스와이프하면 알림을 즉시 닫을 수 있습니다.

**자동 소멸**: 사용자가 아무 액션을 취하지 않으면 3-5초 후 자동으로 사라집니다.

## 6. 이메일 알림 명세

### 6.1 이메일 알림 개요

이메일 알림은 사용자의 이메일 주소로 발송되는 알림입니다. 상세한 정보를 제공하거나 공식 문서(영수증, 약관 등)를 전달하는 데 적합합니다.

### 6.2 이메일 발송 시스템

**이메일 서비스 프로바이더**: AWS SES(Simple Email Service)를 사용하여 이메일을 발송합니다.

**발신 주소**: noreply@blockpick.com을 발신 주소로 사용합니다. 사용자는 이 주소로 회신할 수 없으며, 문의는 support@blockpick.com으로 안내합니다.

**도메인 인증**: DKIM과 SPF를 설정하여 이메일이 스팸으로 분류되지 않도록 합니다.

### 6.3 이메일 템플릿

모든 이메일은 HTML 템플릿을 사용하여 발송됩니다. 템플릿은 다음 요소를 포함합니다.

**헤더**: BlockPick 로고와 브랜드 색상.

**본문**: 알림 내용. 간결하고 명확한 문장으로 작성.

**Call-to-Action (CTA) 버튼**: 관련 작업을 수행할 수 있는 버튼. 예: "앱 열기", "거래 내역 확인", "고객센터 문의".

**푸터**: 회사 정보, 주소, 고객센터 연락처, 수신 거부 링크.

### 6.4 주요 이메일 알림

**당첨 축하 이메일**: 당첨 시 상세한 정보와 함께 축하 메시지를 발송합니다. 당첨 게임 이름, 상금액, 선택한 블록, 당첨 블록, 블록체인 트랜잭션 해시 등이 포함됩니다.

**충전 영수증 이메일**: Event Cash 충전 완료 시 결제 영수증을 첨부하여 발송합니다. PDF 형식의 영수증이 첨부됩니다.

**출금 확인 이메일**: 출금 완료 시 출금 내역을 발송합니다. 출금 금액, 수수료, 실제 입금액, 입금 계좌가 포함됩니다.

**월간 리포트 이메일**: 매월 초, 지난 달의 활동 요약을 발송합니다. 총 참여 게임 수, 총 사용 캐시, 총 당첨 횟수, 총 상금 등이 포함됩니다.

**약관 변경 공지 이메일**: 이용약관이나 개인정보 처리방침 변경 시 발송합니다. 변경 내용 요약과 전문 링크가 포함됩니다.

### 6.5 수신 거부

사용자는 언제든지 마케팅 이메일 수신을 거부할 수 있습니다.

**수신 거부 링크**: 모든 마케팅 이메일의 하단에 "수신 거부" 링크가 포함됩니다. 이 링크를 클릭하면 수신 거부 페이지로 이동하며, 한 번의 클릭으로 수신 거부가 완료됩니다.

**거래 및 시스템 이메일**: 중요한 거래 알림(충전, 출금)이나 시스템 알림(약관 변경)은 수신 거부할 수 없습니다. 이는 법적 요구사항이며, 이메일에 그 사유가 명시됩니다.

**수신 거부 처리 시간**: 수신 거부 요청은 24시간 이내에 처리됩니다.

## 7. 알림 설정 및 관리

### 7.1 알림 설정 화면

사용자는 앱 내 설정 화면에서 알림 옵션을 관리할 수 있습니다.

**설정 메뉴 위치**: 메인 메뉴 → 설정 → 알림 설정

**카테고리별 설정**: 각 알림 카테고리(게임, 거래, 보안, 마케팅, 소셜)별로 켜거나 끌 수 있는 토글 스위치가 제공됩니다.

**채널별 설정**: 푸시, 인앱, 이메일 각각에 대해 설정할 수 있습니다. 예를 들어, "게임 알림은 푸시로만 받고 이메일로는 받지 않음"으로 설정할 수 있습니다.

**조용한 시간대 설정**: 알림을 받지 않을 시간대를 설정할 수 있습니다. 시작 시간과 종료 시간을 슬라이더로 선택합니다.

**세부 알림 설정**: 고급 사용자를 위해 개별 알림 유형별로 설정할 수도 있습니다. 예: "게임 시작 알림은 끄고, 당첨 알림만 받기"

### 7.2 기본 설정

신규 사용자의 기본 알림 설정은 다음과 같습니다.

**게임 알림**: 푸시 켜짐, 인앱 켜짐, 이메일 꺼짐

**거래 알림**: 푸시 켜짐, 인앱 켜짐, 이메일 켜짐

**보안 알림**: 푸시 켜짐, 인앱 켜짐, 이메일 켜짐 (변경 불가)

**마케팅 알림**: 푸시 켜짐, 인앱 켜짐, 이메일 켜짐

**소셜 알림**: 푸시 꺼짐, 인앱 켜짐, 이메일 꺼짐

**조용한 시간대**: 설정 안 함 (24시간 알림 수신)

사용자는 언제든지 이 설정을 변경할 수 있습니다.

### 7.3 알림 센터

앱 내에서 과거 알림 내역을 확인할 수 있는 알림 센터가 제공됩니다.

**위치**: 상단 바의 종 아이콘을 터치하면 알림 센터로 이동합니다.

**알림 목록**: 최근 30일간의 모든 알림이 시간순으로 나열됩니다. 읽지 않은 알림은 굵은 글씨로 표시됩니다.

**읽음 표시**: 알림을 터치하면 읽음으로 표시되고, 해당 알림의 딥링크로 이동합니다.

**삭제**: 개별 알림을 스와이프하여 삭제하거나, "모두 읽음" 또는 "모두 삭제" 버튼으로 일괄 처리할 수 있습니다.

**필터링**: 알림 유형별로 필터링하여 특정 유형의 알림만 볼 수 있습니다.

**배지**: 읽지 않은 알림이 있으면 앱 아이콘과 종 아이콘에 숫자 배지가 표시됩니다.

## 8. 알림 발송 로직

### 8.1 알림 발송 프로세스

알림은 다음 프로세스를 거쳐 발송됩니다.

**1단계: 이벤트 발생**
시스템에서 알림이 필요한 이벤트가 발생합니다. 예: 게임 종료, 충전 완료, 친구 가입.

**2단계: 알림 생성**
이벤트에 따라 적절한 알림 템플릿을 선택하고, 사용자별 데이터를 채워 넣어 알림 메시지를 생성합니다.

**3단계: 사용자 설정 확인**
대상 사용자의 알림 설정을 확인합니다. 해당 알림 유형이 꺼져 있으면 발송하지 않습니다. 단, 보안 및 거래 알림은 설정과 관계없이 발송됩니다.

**4단계: 조용한 시간대 확인**
사용자가 설정한 조용한 시간대인지 확인합니다. 조용한 시간대이고 알림 우선순위가 Low라면 발송을 연기합니다.

**5단계: 알림 큐에 추가**
알림을 발송 큐에 추가합니다. 우선순위가 높은 알림은 우선 큐에, 낮은 알림은 일반 큐에 추가됩니다.

**6단계: 알림 발송**
큐 워커가 알림을 꺼내어 FCM, 이메일 서비스로 발송합니다. FCM은 즉시 발송되고, 이메일은 배치로 묶어 발송될 수 있습니다.

**7단계: 발송 결과 기록**
알림 발송 성공/실패 여부를 데이터베이스에 기록합니다. 실패 시 재시도 로직을 실행합니다.

**8단계: 알림 센터에 저장**
발송된 알림은 사용자의 알림 센터에도 저장되어 나중에 확인할 수 있습니다.

### 8.2 알림 재시도 로직

알림 발송이 실패할 경우 재시도 로직이 실행됩니다.

**FCM 실패**: 네트워크 오류나 FCM 서버 오류로 발송이 실패하면 5분 후 재시도합니다. 최대 3회까지 재시도하며, 모두 실패하면 알림을 폐기하고 로그에 기록합니다. 단, 토큰이 유효하지 않거나 만료된 경우는 재시도하지 않고 해당 토큰을 데이터베이스에서 제거합니다.

**이메일 실패**: 이메일 주소가 잘못되었거나 메일 서버가 거부한 경우 재시도하지 않습니다. 일시적인 네트워크 오류는 10분 후 재시도하며, 최대 3회까지 재시도합니다.

### 8.3 알림 병합 및 요약

같은 유형의 알림이 짧은 시간 내에 여러 개 발생하면 병합하여 하나의 알림으로 발송할 수 있습니다.

**예시**: 사용자가 5개의 게임에 동시에 참가했다면, "5개의 게임 참가가 완료되었습니다"라는 하나의 알림으로 병합합니다.

**병합 조건**: 같은 유형의 알림이 1분 이내에 3개 이상 발생했을 때.

**요약 알림**: 친구 여러 명이 동시에 초대를 수락했다면, "3명의 친구가 초대를 수락했습니다"로 요약합니다.

### 8.4 알림 발송 빈도 제한

과도한 알림으로 사용자가 피로감을 느끼지 않도록 발송 빈도를 제한합니다.

**마케팅 알림**: 주 최대 2회로 제한합니다.

**소셜 알림**: 일일 최대 5회로 제한합니다.

**재참여 유도 알림**: 30일 동안 최대 3회로 제한합니다.

**거래 및 시스템 알림**: 빈도 제한 없음 (실제 이벤트가 발생할 때마다 발송).

## 9. 알림 성능 및 모니터링

### 9.1 알림 발송 성능 목표

알림 시스템은 다음 성능 목표를 충족해야 합니다.

**발송 지연 시간**: High 우선순위 알림은 이벤트 발생 후 10초 이내에 발송되어야 합니다. Default 우선순위는 1분 이내, Low 우선순위는 5분 이내입니다.

**처리량**: 초당 최소 1,000개의 알림을 처리할 수 있어야 합니다. 피크 시간(예: 대규모 게임 종료 시)에는 초당 5,000개까지 처리 가능해야 합니다.

**전달률**: FCM 푸시 알림의 전달률은 95% 이상이어야 합니다. 이메일 알림의 전달률은 98% 이상이어야 합니다.

**응답 시간**: 사용자가 알림을 터치한 후 앱이 열리고 해당 화면으로 이동하는 시간은 3초 이내여야 합니다.

### 9.2 알림 성공률 모니터링

알림 발송 성공률을 실시간으로 모니터링합니다.

**대시보드**: 운영팀은 Grafana 대시보드를 통해 알림 발송 현황을 모니터링합니다. 전송 대기 중, 전송 중, 성공, 실패 상태별로 알림 수를 확인할 수 있습니다.

**알림 유형별 통계**: 각 알림 유형별로 발송 수, 성공률, 실패율, 평균 발송 시간을 확인할 수 있습니다.

**사용자 반응률**: 알림을 클릭한 사용자 비율(Click-Through Rate, CTR)을 측정합니다. 이를 통해 알림의 효과성을 평가하고 개선합니다.

**오류 로그**: 발송 실패한 알림은 상세한 오류 로그와 함께 기록됩니다. 오류 유형별로 집계하여 시스템 문제를 조기에 발견합니다.

### 9.3 A/B 테스트

알림 내용과 타이밍을 최적화하기 위해 A/B 테스트를 수행합니다.

**테스트 항목**: 알림 제목, 본문 내용, 발송 시각, CTA 문구 등을 변경하여 어느 것이 더 높은 CTR을 보이는지 테스트합니다.

**테스트 그룹 분할**: 사용자를 무작위로 두 그룹(A, B)으로 나누고, 각 그룹에 다른 버전의 알림을 발송합니다.

**결과 분석**: 일정 기간 후 CTR, 전환율, 사용자 피드백 등을 비교하여 더 효과적인 버전을 선택합니다.

**예시**: "당첨되셨습니다!" vs "축하합니다! 당첨!" 중 어느 제목이 더 높은 클릭률을 보이는지 테스트합니다.

## 10. 알림 관련 규정

### 10.1 개인정보 보호

알림 발송 시 개인정보 보호를 준수합니다.

**최소한의 정보**: 알림에는 필요한 최소한의 정보만 포함됩니다. 예를 들어, "100,000 캐시가 충전되었습니다"는 포함하지만, 결제에 사용한 카드 번호는 포함하지 않습니다.

**민감 정보 제외**: 비밀번호, 카드 정보, 주민등록번호 등 민감한 정보는 알림에 절대 포함하지 않습니다.

**암호화 전송**: 푸시 알림 페이로드는 HTTPS를 통해 암호화되어 전송됩니다.

### 10.2 스팸 방지

알림이 스팸으로 분류되지 않도록 주의합니다.

**적절한 빈도**: 과도한 알림은 사용자를 피곤하게 하고 스팸으로 신고될 수 있습니다. 빈도 제한을 엄격히 준수합니다.

**명확한 발신자**: 모든 알림은 BlockPick에서 발송됨을 명확히 표시합니다.

**수신 거부 옵션**: 마케팅 알림에는 항상 수신 거부 옵션을 제공합니다.

### 10.3 법적 준수

알림 발송 시 관련 법규를 준수합니다.

**전자상거래법**: 광고성 정보 전송 시 사용자의 사전 동의를 받아야 합니다. 회원가입 시 마케팅 수신 동의를 받습니다.

**정보통신망법**: 영리 목적의 광고성 정보는 제목에 "(광고)"를 표시하고, 발신자 정보와 수신 거부 방법을 포함해야 합니다.

**개인정보보호법**: 알림 발송을 위해 수집한 개인정보(이메일, FCM 토큰)는 안전하게 관리하고, 사용자 동의 범위 내에서만 사용합니다.

**해외 규정**: GDPR(유럽), CCPA(캘리포니아) 등 해외 규정도 고려합니다. 향후 글로벌 서비스 확장 시 준수해야 합니다.
