## 1. 문서 개요

### 1.1 목적

본 관리자 가이드는 BlockPick 플랫폼을 운영하고 관리하는 관리자와 운영팀을 위한 실무 지침서입니다. 일상적인 운영 업무부터 긴급 상황 대응까지 관리자가 알아야 할 모든 내용을 포함합니다.

### 1.2 대상 독자

- **슈퍼 관리자**: 전체 시스템 관리 및 설정
- **운영 관리자**: 게임 생성, 사용자 관리, 일상 운영
- **고객 지원 관리자**: 고객 문의 처리, 환불 승인
- **재무 관리자**: 정산 관리, 거래 내역 확인

### 1.3 필수 요구사항

- 관리자 계정 및 권한
- 관리자 대시보드 접근 권한
- VPN 연결 (보안을 위해 프로덕션 접근 시)
- 2단계 인증 (2FA) 활성화

### 1.4 연락처

## 2. 관리자 로그인 및 권한

### 2.1 관리자 대시보드 접근

**URL**: https://admin.blockpick.io

**로그인**:
1. 이메일과 비밀번호 입력
2. 2FA 코드 입력 (Google Authenticator)
3. 로그인 성공

**VPN 필수**: 프로덕션 관리자 대시보드는 VPN 연결 필수

### 2.2 권한 레벨

BlockPick 관리자 시스템은 역할 기반 접근 제어 (RBAC)를 사용합니다.

**슈퍼 관리자 (Super Admin)**:
- 모든 권한
- 시스템 설정 변경
- 다른 관리자 계정 생성/삭제
- 데이터베이스 직접 접근 (백업/복구)

**운영 관리자 (Operations Admin)**:
- 게임 생성/수정/종료
- 사용자 조회/정지/복구
- 주문 조회
- 통계 및 리포트 조회

**고객 지원 관리자 (Support Admin)**:
- 사용자 조회 (읽기 전용)
- 고객 문의 처리
- 환불 승인/거부 (한도 내)
- 캐시 조정 (승인 필요)

**재무 관리자 (Finance Admin)**:
- 캐시 거래 내역 조회
- 정산 내역 조회 및 다운로드
- 정산 승인
- 재무 리포트 생성

**읽기 전용 (Read-Only)**:
- 모든 데이터 조회만 가능
- 변경 불가

### 2.3 관리자 계정 생성

**Step 1**: 슈퍼 관리자로 로그인

**Step 2**: 설정 > 관리자 관리 > "새 관리자 추가"

**Step 3**: 정보 입력:
- 이메일
- 이름
- 역할 선택
- 권한 설정

**Step 4**: "생성" 버튼 클릭

**Step 5**: 이메일로 초대 링크 발송, 비밀번호 설정 안내

**보안**:
- 2FA 필수
- 강력한 비밀번호 정책 적용
- 정기적인 권한 검토 (분기 1회)

## 3. 관리자 대시보드

### 3.1 대시보드 개요

관리자 대시보드는 BlockPick 플랫폼의 현재 상태를 한눈에 볼 수 있는 중앙 허브입니다.

### 3.2 주요 메트릭 카드

**실시간 메트릭**:
- 현재 활성 사용자 수
- 진행 중인 게임 수
- 금일 신규 가입자 수
- 금일 총 거래액

**어제 대비**:
- 증감률 표시 (▲/▼)
- 색상 코딩 (녹색/빨간색)

### 3.3 그래프 및 차트

**일일 활성 사용자 (DAU)**:
- 지난 30일 추이 라인 그래프

**게임 참여 현황**:
- 게임 타입별 참여 수 (DAILY, SELECT, VIBE, PRIME)
- 파이 차트

**매출 추이**:
- Event Cash 충전 금액
- Shopping Cash 충전 금액
- 상품 판매 금액
- 지난 7일/30일 라인 그래프

**사용자 증가 추이**:
- 일일 신규 가입자
- 누적 사용자 수

### 3.4 최근 활동

**최근 게임**:
- 게임 제목, 상태, 참여자 수
- "상세 보기" 링크

**최근 주문**:
- 주문 번호, 사용자, 상품, 금액, 상태

**최근 고객 문의**:
- 문의 제목, 사용자, 상태
- "답변하기" 링크

### 3.5 알림 센터

**중요 알림**:
- 에러 발생
- 시스템 이상
- 대기 중인 승인 요청
- 긴급 고객 문의

**우선순위 표시**: 빨간색 (긴급), 주황색 (높음), 파란색 (일반)

## 4. 게임 관리

### 4.1 게임 목록 조회

**메뉴**: 게임 관리 > 게임 목록

**필터링**:
- 게임 타입: DAILY, SELECT, VIBE, PRIME
- 상태: 예정, 진행 중, 종료
- 날짜 범위

**테이블 정보**:
- 게임 ID
- 제목
- 게임 타입
- 상태
- 참여자 수 / 최대 참여자 수
- 시작 시간 / 종료 시간
- 작업: [상세 보기] [수정] [종료]

### 4.2 새 게임 생성

**Step 1**: 게임 관리 > "새 게임 생성" 버튼 클릭

**Step 2**: 게임 기본 정보 입력:
- 게임 제목
- 게임 타입: DAILY / SELECT / VIBE / PRIME
- 상품 이미지 (최대 5장)
- 상품 설명

**Step 3**: 게임 설정:
- 참가비 (Event Cash)
- 총 상금 (Event Cash)
- 그리드 크기 (기본 9×9)
- 최대 참여자 수
- 시작 시간 (예약 가능)
- 종료 시간 (또는 자동 종료 조건)

**Step 4**: 당첨 규칙 설정:
- DAILY/SELECT/PRIME: 랜덤 블록 당첨
- VIBE: 최다 선택 블록 당첨
- 공동 당첨 시 상금 분배 방식

**Step 5**: 미리 보기로 확인

**Step 6**: "게임 생성" 버튼 클릭

**Step 7**: 생성 완료! 게임 ID 부여

**자동화**: 정기 게임 (DAILY)은 자동 생성 스크립트 실행 가능

### 4.3 게임 수정

**제한 사항**: 진행 중인 게임은 일부 정보만 수정 가능

**수정 가능 항목** (진행 전):
- 제목
- 설명
- 이미지
- 시작/종료 시간
- 최대 참여자 수

**수정 불가 항목** (진행 중):
- 게임 타입
- 참가비
- 총 상금
- 그리드 크기

**Step 1**: 게임 목록에서 [수정] 버튼 클릭

**Step 2**: 정보 수정

**Step 3**: "저장" 버튼 클릭

**로그**: 모든 수정 사항은 감사 로그에 기록

### 4.4 게임 종료 및 당첨 처리

**자동 종료**: 설정된 종료 시간에 자동 종료

**수동 종료**:

**Step 1**: 게임 상세 페이지에서 "게임 종료" 버튼 클릭

**Step 2**: 종료 확인 팝업에서 "확인" 클릭

**Step 3**: 당첨 처리 시작:
1. 블록체인에서 모든 참여 데이터 조회
2. 당첨 블록 선정 (랜덤 또는 최다 선택)
3. 당첨자 확인
4. 상금 분배 계산
5. Event Cash 지급
6. 당첨자에게 알림 발송

**Step 4**: 당첨 결과 확인:
- 당첨 블록 좌표
- 당첨자 목록
- 각 당첨자의 상금

**문제 발생 시**:
- 자동 처리 실패 시 수동 처리
- 블록체인 트랜잭션 확인
- DevOps 팀 연락

### 4.5 게임 복제

기존 게임을 복제하여 빠르게 새 게임 생성:

**Step 1**: 게임 상세 페이지에서 "복제" 버튼 클릭

**Step 2**: 새 게임 정보 수정 (제목, 시간 등)

**Step 3**: "복제 완료" 클릭

## 5. 사용자 관리

### 5.1 사용자 검색

**메뉴**: 사용자 관리 > 사용자 검색

**검색 옵션**:
- 이메일
- 이름
- 사용자 ID
- 전화번호

**고급 필터**:
- 가입 날짜 범위
- 마지막 로그인 날짜
- Event Cash 잔액 범위
- 상태: 활성, 휴면, 정지

### 5.2 사용자 상세 정보

**기본 정보**:
- 사용자 ID
- 이메일
- 이름
- 전화번호
- 가입일
- 마지막 로그인
- 상태

**캐시 정보**:
- Event Cash 잔액
- Shopping Cash 잔액
- 총 충전 금액
- 총 사용 금액
- 총 출금 금액

**활동 내역**:
- 참여한 게임 목록
- 당첨 내역
- 구매한 상품
- 고객 문의 내역

**작업**:
- [캐시 조정]
- [계정 정지]
- [계정 복구]
- [비밀번호 재설정]
- [메시지 보내기]

### 5.3 계정 정지

**사유**:
- 규정 위반
- 부정 행위 (다중 계정, 매크로)
- 사기 의심
- 사용자 요청

**Step 1**: 사용자 상세 페이지에서 "계정 정지" 버튼 클릭

**Step 2**: 정지 사유 선택 및 설명 입력

**Step 3**: 정지 기간 선택:
- 7일
- 30일
- 영구

**Step 4**: "정지" 버튼 클릭

**효과**:
- 로그인 불가
- 사용자에게 이메일 발송
- 감사 로그 기록

### 5.4 캐시 조정

**주의**: 캐시 조정은 매우 민감한 작업이므로 신중하게 처리

**사유**:
- 시스템 오류로 인한 손실 보상
- 프로모션 보너스 수동 지급
- 환불 처리

**권한**: 고객 지원 관리자는 10,000 캐시 이하만 조정 가능, 그 이상은 슈퍼 관리자 승인 필요

**Step 1**: 사용자 상세 페이지에서 "캐시 조정" 버튼 클릭

**Step 2**: 캐시 종류 선택 (Event Cash / Shopping Cash)

**Step 3**: 조정 유형 선택:
- 추가 (+)
- 차감 (-)

**Step 4**: 금액 입력

**Step 5**: 사유 입력 (필수, 상세히 기재)

**Step 6**: "조정" 버튼 클릭

**Step 7**: (10,000 캐시 이상) 슈퍼 관리자 승인 대기

**Step 8**: 완료 후 사용자에게 알림 발송

**로그**: 모든 캐시 조정은 감사 로그에 영구 기록

## 6. 캐시 관리

### 6.1 캐시 거래 내역 조회

**메뉴**: 캐시 관리 > 거래 내역

**필터**:
- 캐시 종류: Event Cash / Shopping Cash
- 거래 유형: 충전 / 사용 / 출금 / 환불
- 날짜 범위
- 사용자 검색

**테이블 정보**:
- 거래 ID
- 사용자
- 캐시 종류
- 거래 유형
- 금액
- 거래 전 잔액
- 거래 후 잔액
- 날짜 및 시간

**내보내기**: CSV, Excel 다운로드

### 6.2 충전 내역 모니터링

**이상 거래 탐지**:
- 단시간 대량 충전
- 도난 카드 의심
- 비정상 패턴

**의심 거래 플래그**:
- 자동 플래그: 빨간색 표시
- 수동 검토 필요

**조치**:
- 사용자 확인 요청
- 계정 일시 정지
- 결제 취소 (PG사 연락)

### 6.3 출금 요청 승인

**메뉴**: 캐시 관리 > 출금 요청

**자동 승인**: 정상 거래는 자동 승인 및 처리

**수동 검토 필요**:
- 고액 출금 (100만 원 이상)
- 첫 출금
- 충전 직후 출금 (의심 거래)

**Step 1**: 대기 중인 출금 요청 목록 확인

**Step 2**: 출금 상세 정보 확인:
- 사용자 정보
- 출금 금액
- 수수료
- 실제 입금액
- 계좌 정보
- 사용자 거래 내역 (의심스러운 패턴 확인)

**Step 3**: 승인 또는 거부 선택:
- **승인**: 은행 API로 이체 실행
- **거부**: 거부 사유 입력, Event Cash 환원

**Step 4**: 완료 후 사용자에게 알림

**테이블 정보**:
- 주문 번호

### 7.2 주문 상세 정보

- 배송 상태

**파트너사 정산**:
- 파트너사명

- 정산 상태

**작업**:
- [운송장 번호 입력]
- [배송 상태 업데이트]
- [취소 승인]
- [환불 승인]

### 7.3 취소 및 환불 처리

- **승인**: 취소수수료 계산, Shopping Cash 복원, PG 결제 취소, 파트너사 알림

## 14. 문제 해결 가이드

### 14.1 자주 발생하는 이슈

**"사용자가 충전했는데 캐시가 반영 안 됐어요"**:

**Step 1**: 사용자 캐시 거래 내역 확인

**Step 2**: PG사 결제 내역 확인 (결제는 완료되었는지)

**Step 3**: 시스템 로그 확인 (에러 발생 여부)

**해결**:
- Case 1: 결제 완료, 캐시 미지급 → 캐시 수동 조정
- Case 2: 결제 실패 → 사용자에게 재시도 안내
- Case 3: 시스템 오류 → DevOps 팀 에스컬레이션

**"게임이 종료되었는데 당첨 처리가 안 됐어요"**:

**Step 1**: 게임 상세 페이지 확인 (상태: 종료/당첨 처리 중/완료)

**Step 2**: 블록체인 트랜잭션 확인

**Step 3**: 에러 로그 확인

**해결**:
- Case 1: 자동 처리 지연 → 30분 대기
- Case 2: 블록체인 오류 → 수동 당첨 처리
- Case 3: 시스템 버그 → DevOps 팀 에스컬레이션

**"출금이 안 돼요"**:

**Step 1**: 출금 요청 상태 확인 (신청/승인/처리 중/완료/실패)

**Step 2**: 출금 조건 확인:
- 최소 출금 금액 충족?
- 본인인증 완료?
- 계좌 정보 올바른가?

**Step 3**: 실패 사유 확인

**해결**:
- Case 1: 계좌 정보 오류 → 사용자에게 수정 요청
- Case 2: 은행 시스템 오류 → 재시도
- Case 3: 의심 거래 → 추가 본인 확인 요청

### 14.2 에스컬레이션

**Level 1**: 고객 지원 관리자 (일반 문의)

**Level 2**: 운영 관리자 (복잡한 운영 이슈)

**Level 3**: 슈퍼 관리자 (시스템 설정 필요)

**Level 4**: DevOps 팀 (기술적 문제)

**Level 5**: CTO (긴급 시스템 장애)

**에스컬레이션 기준**:
- 15분 내 해결 안 될 시
- 기술적 지식 필요 시
- 다수 사용자 영향 시
- 금전적 손실 발생 시

### 15.2 고객 응대 가이드

**신속한 응답**: 문의 접수 후 4시간 이내 답변

**친절하고 명확하게**: 전문 용어 최소화, 단계별 설명

**공감 표현**: 사용자의 불편을 이해하고 공감

**문제 해결 중심**: 빠른 해결책 제시

**후속 조치**: 문제 해결 후 사용자 만족도 확인

### 15.3 데이터 관리

**개인정보 보호**: 개인정보 최소한만 조회, 외부 유출 절대 금지

**권한 최소화**: 필요한 권한만 부여

**정기적인 권한 검토**: 분기 1회 관리자 권한 리뷰

**로그 확인**: 민감한 작업 후 감사 로그 확인

### 15.4 긴급 상황 대응

**서비스 장애 발생 시**:
1. 상황 파악 (무엇이 문제인가?)
2. 영향 범위 확인 (몇 명 영향받는가?)
3. 즉시 DevOps 팀 연락
4. 상태 페이지 업데이트
5. 사용자 공지
6. 문제 해결 후 사후 분석

**보안 침해 의심 시**:
1. 즉시 CTO 연락
2. 의심 계정 정지
3. 로그 수집 (삭제 금지)
4. 보안 팀 소집
5. 조사 및 대응
