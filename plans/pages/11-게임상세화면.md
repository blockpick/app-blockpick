## 🎯 페이지 목적

게임 상세 화면은 사용자가 **특정 게임의 세부 정보를 확인하고 참가하기 전에 의사결정**을 할 수 있도록 돕는 핵심 화면입니다.

주요 목적:
- **제품 정보 제공**: 상품 이미지, 브랜드, 가격, 배송 정보 등 상세 정보 제공
- **게임 현황 표시**: 참가자 수, 당첨자 수, 남은 시간, 참가 비용 등 실시간 정보 제공
- **블록 선택 인터페이스**: 게임 그리드에서 블록을 선택하고 참가할 수 있는 UI 제공
- **공유 기능**: 게임을 친구에게 공유할 수 있는 기능 제공

```dart
final List<BlockModel> _selectedBlocks = [];

void _handleBlockTap(BlockModel block) {
  setState(() {
    final index = _selectedBlocks.indexWhere((b) => b.id == block.id);
    if (index >= 0) {
      _selectedBlocks.removeAt(index); // 선택 해제
    } else {
      _selectedBlocks.add(block); // 선택 추가
    }
  });
}
```

## 🎯 주요 이슈 및 해결 방안

### Issue 1: 이미지 로딩 최적화

**문제**:
- 고해상도 제품 이미지 로딩 시 성능 저하
- 네트워크 상태에 따라 로딩 시간 변동

**해결 방안**:
- [ ] `CachedNetworkImage` 패키지 사용
- [ ] 이미지 플레이스홀더 (Shimmer 효과)
- [ ] Progressive JPEG 지원
- [ ] 썸네일 → 고해상도 순차 로딩

**Story Points**: 5pt

---

### Issue 2: 그리드 성능 최적화

**문제**:
- 큰 그리드 (100×100 등) 렌더링 시 렉 발생
- 블록 선택 시 전체 리렌더링

**해결 방안**:
- [ ] `CustomPainter` 사용하여 Canvas 직접 그리기
- [ ] Viewport 기반 부분 렌더링
- [ ] `RepaintBoundary`로 리렌더링 영역 제한
- [ ] `shouldRepaint` 최적화

**Story Points**: 8pt

---

### Issue 3: 실시간 데이터 동기화

**문제**:
- 참가자 수, 남은 시간 등 실시간 업데이트 필요
- 여러 사용자가 동시에 블록 선택 시 충돌

**해결 방안**:
- [ ] WebSocket 연결로 실시간 업데이트
- [ ] Firestore 실시간 리스너 사용
- [ ] 낙관적 업데이트 (Optimistic UI)
- [ ] 충돌 시 서버 데이터 우선 (Server-side validation)

**Story Points**: 13pt

---

### Issue 4: 블록 선택 UX 개선

**문제**:
- 작은 화면에서 블록 선택이 어려움
- 실수로 블록 선택 취소

**해결 방안**:
- [ ] 확대/축소 제스처 지원 (Pinch to zoom)

## 📝 개발 노트

### 버전 1 vs 버전 2

**V1 (game_detail_screen.dart)**:
- 모바일 최적화 레이아웃
- 오버레이 정보 패널
- 간단한 참가 버튼

**V2 (game_detail_screen_v2.dart)**:
- 반응형 디자인 (모바일/데스크톱)
- 우측 패널 (380px 고정)
- 블록 선택 리스트 관리
- 상세 제품 정보
- 선택 블록 실시간 업데이트

**권장**: V2를 기본으로 사용하고, V1은 레거시 지원 또는 특정 케이스용

### 디자인 결정 사항

1. **배경 이미지**: 제품 이미지를 그리드 배경으로 사용하여 시각적 몰입감 증대
2. **반투명 패널**: 정보 패널을 반투명(95% opacity)으로 하여 배경 이미지가 비치도록 설정
3. **고정 우측 패널**: 데스크톱에서 380px 고정 너비로 일관된 정보 레이아웃 제공
4. **블록 선택 피드백**: 선택된 블록을 리스트로 표시하여 명확한 현황 파악
