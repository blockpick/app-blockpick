## 🎯 페이지 목적

BlockPick 앱의 **첫 진입점**이자 **핵심 콘텐츠 허브**입니다. 사용자가 앱을 실행하면 가장 먼저 보게 되는 화면으로, 다음과 같은 주요 목적을 가집니다:

- **게임 발견**: 프리미엄 SELECT 게임, STAGE/VIBE 게임 등을 시각적으로 매력적인 방식으로 제시
- **사용자 참여 유도**: 이벤트 배너, 실시간 참가 현황 등을 통해 활동적인 커뮤니티 분위기 조성
- **정보 제공**: BlockPick 작동 방식, 튜토리얼, 공지사항 등을 통한 사용자 교육
- **자산 관리**: 이벤트 캐시 잔액 및 통계 정보 제공으로 사용자의 게임 자산 현황 파악

## ⚙️ 기능 요구사항

### 기능 1: Event Cash Widget (이벤트 캐시 위젯)

**설명**: 사용자의 이벤트 캐시 잔액과 통계를 표시하는 접이식 위젯입니다.

**기술 상세**:
- **상태 관리**: `_isExpanded` (bool)
- **애니메이션**: `AnimatedSize` (400ms, easeInOutCubic)
- **차트**: Syncfusion Treemap
- **데이터 소스**:
  - AuthProvider (사용자 잔액)
  - MockEventCashData (히스토리)

**접힘/펼침 토글**:
1. 사용자가 위젯 전체 영역 터치
2. `_isExpanded` 상태 토글
3. `AnimatedSize`가 높이 자동 조절
4. 차트 및 통계가 부드럽게 나타남/사라짐

**차트 데이터 구조**:
```dart
- 참가 횟수 (파란색)
- 당첨 횟수 (초록색)
- 당첨률 (핑크색)
- ROI (보라색)
```

**기간 선택**:
- 1D, 1W, 1M, 6M 버튼
- 선택 시 차트 데이터 필터링
- 선택된 버튼: 핑크 그라데이션 + 그림자

**완료 조건**:
- ✅ 접힘/펼침 토글 동작
- ✅ 차트 렌더링 (Treemap)
- ✅ 기간 선택 버튼 동작
- ✅ 통계 박스 4개 표시
- ✅ 애니메이션 부드러움

---

### 기능 2: Event Banner Carousel (이벤트 배너 캐러셀)

**설명**: 이벤트 배너를 자동으로 슬라이드하는 캐러셀입니다.

**기술 상세**:
- **위젯**: `PageController` + `PageView.builder`
- **데이터 소스**: `MockEventBannerData`
- **자동 슬라이드**: `Timer.periodic` (3초)

**자동 슬라이드 로직**:
1. 3초마다 `_currentPage` 증가
2. 마지막 페이지 도달 시 0으로 리셋
3. `PageController.animateToPage()` 호출
4. 350ms 애니메이션 (easeInOut)

**배너 디자인**:
- 각 배너마다 다른 그라데이션 색상
- 제목 + 부제목
- 둥근 모서리 + 그림자

**인디케이터**:
- 활성 페이지: 24×8dp, 파란색
- 비활성 페이지: 8×8dp, 회색
- `AnimatedContainer` (300ms)

**완료 조건**:
- ✅ 자동 슬라이드 동작 (3초)
- ✅ 무한 반복
- ✅ 인디케이터 업데이트
- ✅ 부드러운 애니메이션

## 📝 기술 노트

### 애니메이션 성능 최적화

메인 홈 화면은 여러 애니메이션이 동시에 실행되므로 성능 최적화가 중요합니다:

1. **AnimationController 최적화**:
   - 각 위젯에 독립적인 컨트롤러 사용
   - `vsync: this` (TickerProviderStateMixin)
   - `dispose()`에서 반드시 정리

2. **CustomPaint 최적화**:
   - `shouldRepaint()` 신중하게 구현
   - 불필요한 리페인트 방지
   - `RepaintBoundary`로 격리

3. **이미지 캐싱**:
   - `cached_network_image` 패키지 사용
   - 메모리 캐시 + 디스크 캐시
   - 적절한 이미지 크기 사용

4. **위젯 트리 최적화**:
   - `const` 생성자 최대한 사용
   - 불필요한 `setState()` 호출 방지
   - `Consumer` 대신 `ConsumerWidget` 사용 (필요 시)

### 반응형 디자인 고려사항

1. **화면 크기별 레이아웃**:
   - 모바일: 세로 스크롤
   - 태블릿: 일부 섹션 2열 레이아웃
   - 데스크톱: 3열 레이아웃 (필요 시)

2. **가로 모드**:
   - 배너 높이 조절
   - 카드 크기 조절
   - 스크롤 경험 유지

3. **SafeArea 처리**:
   - 상단 노치 고려
   - 하단 홈 인디케이터 고려

### Mock 데이터 구조

현재 Mock 데이터 사용 중이며, 추후 실제 API로 교체 예정:

- `MockEventCashData`: 이벤트 캐시 히스토리
- `MockEventBannerData`: 이벤트 배너 데이터
- `MockAnnouncementData`: 공지사항 데이터
- `MockParticipationFeedData`: 참가 현황 데이터
