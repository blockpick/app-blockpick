# 블록픽 파트너 대시보드 화면 구성서

---

# 1. 공통 UI 원칙

## 1-1. 핵심 원칙

- 파트너가 **빠르게 블록픽을 생성**할 수 있어야 한다.
- 운영 중인 블록픽의 상태와 성과를 **한눈에 확인**할 수 있어야 한다.
- 각 화면은 반드시 다음 행동으로 이어지는 **명확한 CTA**를 가져야 한다.
- 실무자가 자주 사용하는 기능은 **리스트 + 필터 + 상세 + 다운로드** 구조가 기본이어야 한다.

## 1-2. 공통 UI 레이아웃

- **좌측 사이드바**
    - 1차 메뉴 이동
- **상단 바**
    - 현재 브랜드/워크스페이스명
    - 검색
    - 알림
    - 도움말
    - 계정 메뉴
- **본문 영역**
    - KPI 카드 / 리스트 / 차트 / 폼 / 테이블
- **우측 보조 영역(선택)**
    - 팁, 운영 가이드, 최근 활동

## 1-3. 공통 UI 요소

- KPI 카드
- 상태 배지
    - 진행중 / 예약됨 / 종료 / 임시저장
    - 지급 대기 / 지급 완료 / 입력 필요
- 리스트 테이블
- 필터 바
- 검색창
- 날짜 필터
- CSV 다운로드 버튼
- 상단 주 CTA 버튼
- Empty 상태 / 오류 상태 / 로딩 상태

## 1-4. 공통 CTA 문구 원칙

- 생성: **새 블록픽 만들기**
- 발행: **지금 발행하기**
- 저장: **임시저장**
- 수정: **수정하기**
- 종료: **종료하기**
- 확인: **자세히 보기**
- 다운로드: **내보내기**
- 공유: **링크 복사**
- 업셀: **플랜 업그레이드**

# 2. 홈 화면 구성

## 2-1. 대시보드 홈

### 화면 목적

- 파트너가 전체 운영 현황을 가장 빠르게 파악
- 자주 쓰는 핵심 액션으로 바로 이동
- 오늘/이번주 기준 주요 성과를 확인

### 주요 UI 요소

- 상단 헤더
    - 브랜드명
    - 기간 선택
    - 검색
- KPI 카드 영역
    - 총 방문 수
    - 총 참여 수
    - 무료 → 추가 참여 전환율
    - 친구 초대 성공 수
    - 광고 시청 수
    - 진행 중 블록픽 수
- 최근 블록픽 리스트
- 최근 알림 / 운영 이슈
- 빠른 실행 영역
    - 새 블록픽 만들기
    - 당첨자 확인
    - 공유 링크 확인
    - 플랜 업그레이드
- 간단 성과 차트
    - 일별 참여 추이
    - 블록픽별 참여 수

### CTA

- **새 블록픽 만들기**
- **전체 블록픽 보기**
- **당첨자 관리 가기**
- **전체 성과 보기**
- **플랜 업그레이드**

### 비고

- 홈은 “요약 + 바로가기” 성격이 강해야 함
- 너무 많은 테이블보다 KPI 카드와 최근 상태 요약이 중요

# 3. 블록픽 메뉴 화면 구성

---

## 3-1. 전체 블록픽 리스트

### 화면 목적

- 파트너가 생성한 모든 블록픽을 상태별로 관리
- 빠르게 수정, 복제, 종료, 상세 진입 가능하게 함

### 주요 UI 요소

- 상단 헤더
    - 제목: 전체 블록픽
    - 주 CTA: 새 블록픽 만들기
- 필터 바
    - 상태
    - 기간
    - 작성자
    - 보상 유형
- 검색창
    - 캠페인명 / 파트너 표기명 검색
- 정렬 옵션
    - 최신순 / 참여 많은순 / 종료 임박순
- 블록픽 리스트 테이블 또는 카드형 리스트

### 리스트 컬럼 예시

- 썸네일
- 블록픽 제목
- 상태
- 기간
- 참여 수
- 친구 초대 수
- 당첨자 수
- 마지막 수정일
- 액션
    - 보기
    - 수정
    - 복제
    - 종료

### CTA

- **새 블록픽 만들기**
- **상세 보기**
- **수정하기**
- **복제하기**
- **종료하기**
- **내보내기**

### 비고

- MVP에서는 테이블형이 운영 효율이 가장 좋음
- 상태 배지는 색상으로 명확하게 구분하는 것이 좋음

---

## 3-2. 새 블록픽 만들기

### 화면 목적

- 파트너가 가장 쉽게 새 캠페인을 생성
- 입력 부담을 줄이면서도 필수 설정은 빠짐없이 받기

### 권장 구조

- **Step Wizard 방식**

### 단계 구성

### Step 1. 기본 정보

- 블록픽 제목
- 대표 이미지 업로드
- 설명 문구
- 파트너 노출명
- 공개 범위
- 참여 기간 / 종료 일시

### Step 2. 게임 설정

- 그리드 크기
- 무료 참여 수
- 1인 최대 참여 수
- 추가 참여 방식 선택
    - 친구 초대
    - 광고 시청
    - 미션 수행
- 중복 당첨 허용 여부

### Step 3. 보상 설정

- 경품명
- 보상 유형
- 수량
- 유효기간
- 지급 방식
- 글로벌 배송/국가 설정
- 당첨자 정보 수집 항목

### Step 4. 공유/리퍼럴 설정

- 기본 공유 문구
- 초대 링크 기준
- 초대 성공 인정 조건
- 보상 지급 조건

### Step 5. 검토 및 발행

- 전체 요약
- 에러/누락 항목 표시
- 임시저장 / 예약발행 / 즉시발행

### CTA

- **다음 단계**
- **이전 단계**
- **임시저장**
- **미리보기**
- **지금 발행하기**
- **예약 발행하기**

### 비고

- 모든 설정을 한 페이지에 몰아넣기보다 단계형이 훨씬 나음
- 각 단계 우측에 가이드 박스를 넣으면 이탈이 줄어듦

---

## 3-3. 진행중 / 예약됨 / 종료됨 / 임시저장

### 화면 목적

- 상태별 빠른 운영
- 실무자가 필요한 것만 분리 조회

### 주요 UI 요소

- 상태별 필터 기본 적용 리스트
- 검색
- 기간 필터
- 상태별 주요 액션 버튼

### CTA

- **상세 보기**
- **수정하기**
- **발행하기**
- **종료하기**
- **복제하기**

### 비고

- 전체 블록픽과 거의 동일한 UI를 재사용하고, 상태만 고정 필터로 처리하면 효율적

# 13. 최종 정리

이 파트너 대시보드 화면 구성서는 아래 흐름을 중심으로 설계된다.

## 핵심 흐름

- **생성**
    - 새 블록픽 만들기
- **운영**
    - 블록픽 상세 / 참여자 / 당첨자
- **분석**
    - 전체 성과 / 블록픽별 성과 / 리퍼럴 성과
- **브랜딩**
    - 로고 / 문구 / 유의사항
- **과금**
    - 현재 플랜 / 사용량 / 업그레이드
- **협업**
    - 팀 / 권한 / 로그

## 핵심 원칙

- 파트너 실무자가 바로 이해할 수 있어야 한다.
- 자주 쓰는 액션은 반드시 상단/우측 상단에 보여야 한다.
- 블록픽 운영과 당첨자 후처리가 끊기지 않아야 한다.
- 구독 업셀 포인트가 자연스럽게 노출되어야 한다.
