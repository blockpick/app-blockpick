# 결제 및 재화 시스템 기획서

## 1. 개요

블록픽 앱의 결제 시스템은 **1:1:1 비율**로 두 가지 독립적인 재화를 제공합니다.

---

## 2. 결제 프로세스

### 2.1 결제 수단
- **Stripe** (스프라이트)
- **토스페이먼츠**

### 2.2 충전 비율 (1:1:1)
```
충전 금액 X원 입력
  ↓
이벤트 캐시 X원 + 쇼핑 캐시 X원 지급
  ↓
총 2배의 재화 획득
```

### 2.3 충전 예시
| 충전 금액 | 이벤트 캐시 | 쇼핑 캐시 | 총 재화 |
|----------|------------|----------|---------|
| 10,000원 | 10,000원   | 10,000원 | 20,000원 |
| 50,000원 | 50,000원   | 50,000원 | 100,000원 |
| 100,000원 | 100,000원  | 100,000원 | 200,000원 |

## 3. 재화 시스템

### 3.1 재화 종류

#### 1) 이벤트 캐시
- **용도**: 블록픽 게임 참가
- **사용처**: 게임 라운드 참가비 결제
- **독립성**: 쇼핑 캐시와 완전히 독립적으로 차감

#### 2) 쇼핑 캐시
- **용도**: 쇼핑몰 상품 구매
- **사용처**: 앱 내 쇼핑몰 상품 결제
- **독립성**: 이벤트 캐시와 완전히 독립적으로 차감

### 3.2 재화 사용 규칙

```
블록픽 게임 참가 (3,000원)
  ↓
이벤트 캐시만 -3,000원 차감
쇼핑 캐시는 변동 없음 ✅
```

```
쇼핑몰 상품 구매 (5,000원)
  ↓
쇼핑 캐시만 -5,000원 차감
이벤트 캐시는 변동 없음 ✅
```

### 3.3 재화 사용 예시

**초기 상태 (10,000원 충전)**
```
이벤트 캐시: 10,000원
쇼핑 캐시: 10,000원
```

**시나리오 1: 게임만 참가**
```
게임 참가 (3,000원)
→ 이벤트 캐시: 7,000원
→ 쇼핑 캐시: 10,000원 (유지)
```

**시나리오 2: 쇼핑만 사용**
```
상품 구매 (5,000원)
→ 이벤트 캐시: 10,000원 (유지)
→ 쇼핑 캐시: 5,000원
```

**시나리오 3: 둘 다 사용**
```
게임 참가 (3,000원) → 이벤트 캐시: 7,000원
상품 구매 (5,000원) → 쇼핑 캐시: 5,000원

최종 잔액:
→ 이벤트 캐시: 7,000원
→ 쇼핑 캐시: 5,000원
```

## 4. 환불 정책

### 4.1 환불 가능 조건 (AND 조건)
```
이벤트 캐시 사용 내역 == 0
AND
쇼핑 캐시 사용 내역 == 0
```

✅ **환불 가능**: 충전 후 **두 캐시 모두 미사용** 상태일 때만

### 4.2 환불 불가 조건 (OR 조건)
```
이벤트 캐시 사용 > 0
OR
쇼핑 캐시 사용 > 0
```

❌ **환불 불가**: 둘 중 **하나라도 사용**한 경우

### 4.3 환불 시나리오

| 이벤트 캐시 사용 | 쇼핑 캐시 사용 | 환불 가능 여부 |
|----------------|---------------|---------------|
| 0원            | 0원           | ✅ 가능        |
| 3,000원        | 0원           | ❌ 불가        |
| 0원            | 5,000원       | ❌ 불가        |
| 3,000원        | 5,000원       | ❌ 불가        |

## 5. 데이터베이스 구조 (예시)

### 5.1 사용자 재화 테이블
```graphql
type UserWallet {
  userId: ID!
  eventCash: Int!           # 이벤트 캐시 잔액
  shoppingCash: Int!        # 쇼핑 캐시 잔액
  totalEventCashUsed: Int!  # 이벤트 캐시 누적 사용액
  totalShoppingCashUsed: Int! # 쇼핑 캐시 누적 사용액
  createdAt: DateTime!
  updatedAt: DateTime!
}
```

### 5.2 충전 내역 테이블
```graphql
type PaymentHistory {
  id: ID!
  userId: ID!
  paymentMethod: String!    # "stripe" | "tosspayments"
  amount: Int!              # 충전 금액
  eventCashGiven: Int!      # 지급된 이벤트 캐시
  shoppingCashGiven: Int!   # 지급된 쇼핑 캐시
  isRefundable: Boolean!    # 환불 가능 여부
  isRefunded: Boolean!      # 환불 완료 여부
  createdAt: DateTime!
}
```

### 5.3 사용 내역 테이블
```graphql
type CashUsageHistory {
  id: ID!
  userId: ID!
  cashType: String!         # "event" | "shopping"
  amount: Int!              # 사용 금액
  purpose: String!          # "game_entry" | "shopping_purchase"
  referenceId: ID!          # 게임 ID 또는 주문 ID
  createdAt: DateTime!
}
```

## 6. 핵심 비즈니스 로직

### 6.1 충전 로직
```dart
// 충전 처리
Payment charge(int amount) {
  eventCash += amount;
  shoppingCash += amount;

  return Payment(
    amount: amount,
    eventCashGiven: amount,
    shoppingCashGiven: amount,
    isRefundable: true,
  );
}
```

### 6.2 게임 참가 로직
```dart
// 게임 참가 시 이벤트 캐시 차감
bool enterGame(int gameFee) {
  if (eventCash < gameFee) {
    return false; // 잔액 부족
  }

  eventCash -= gameFee;
  totalEventCashUsed += gameFee;

  // 모든 충전 내역의 환불 가능 여부 업데이트
  updateRefundability();

  return true;
}
```

### 6.3 쇼핑 구매 로직
```dart
// 상품 구매 시 쇼핑 캐시 차감
bool purchaseProduct(int productPrice) {
  if (shoppingCash < productPrice) {
    return false; // 잔액 부족
  }

  shoppingCash -= productPrice;
  totalShoppingCashUsed += productPrice;

  // 모든 충전 내역의 환불 가능 여부 업데이트
  updateRefundability();

  return true;
}
```

### 6.4 환불 가능 여부 체크
```dart
bool isRefundable() {
  return totalEventCashUsed == 0 && totalShoppingCashUsed == 0;
}

void updateRefundability() {
  // 한 번이라도 사용했으면 모든 충전 내역 환불 불가 처리
  if (totalEventCashUsed > 0 || totalShoppingCashUsed > 0) {
    // 모든 미환불 충전 내역의 isRefundable을 false로 업데이트
    PaymentHistory.updateAll(
      where: (p) => p.userId == this.userId && !p.isRefunded,
      set: (p) => p.isRefundable = false,
    );
  }
}
```

## 10. 참고사항

- **재화 분리 원칙**: 이벤트 캐시와 쇼핑 캐시는 절대 혼용되지 않음
- **환불 정책 엄격성**: 한 번이라도 사용 시 전액 환불 불가
- **투명성**: 사용자에게 재화 사용 내역을 명확히 표시
- **법적 준수**: 전자상거래법, 전자금융거래법 준수 필요
