# 암호화 키 조회/생성 최적화 방식

## 개요

게임당 한 번만 암호화 키를 생성하여 서버 가스비를 절약하는 최적화된 방식을 구현했습니다.

**핵심 원칙**: 먼저 블록체인에서 기존 키를 조회하고, 없을 때만 서버를 통해 새로 생성합니다.

## 배경

### 문제 상황
- **가스비 비용**: 매번 암호화 키를 생성하면 서버가 가스비를 계속 지불해야 함
- **불필요한 중복**: 같은 게임에 여러 번 참여할 때마다 새 키를 생성할 필요 없음

### 해결책
- **게임별 고정 키**: `userIndex = "지갑주소-게임ID"` 형식으로 게임당 하나의 키 사용
- **조회 우선**: 블록체인에서 먼저 키를 조회하고, 없을 때만 생성

## 구현 방식

### 1. 최적화된 프로세스

```
┌─────────────────────────────────────────────────────────┐
│ [Step 1] 블록체인에서 기존 키 조회 (View 함수)          │
│   - SmartContractService.getEncryptionKey()             │
│   - userIndex: "지갑주소-게임ID" (게임별 고정)          │
│   - 가스비 없음 (읽기 전용)                             │
└─────────────────────────────────────────────────────────┘
                          ↓
                    키가 있나요?
                          ↓
                   ┌──────┴──────┐
                   │             │
                  YES            NO
                   ↓             ↓
┌──────────────────────┐  ┌──────────────────────────────┐
│ ✅ 기존 키 재사용    │  │ [Step 2] 서버를 통한 키 생성 │
│ - 서버 호출 없음     │  │ - requestEncryptionKey       │
│ - 가스비 절약        │  │ - 서버가 가스비 지불         │
│ - 즉시 사용 가능     │  │ - 블록체인에 키 저장         │
└──────────────────────┘  └──────────────────────────────┘
         ↓                           ↓
         └───────────┬───────────────┘
                     ↓
         ┌───────────────────────────┐
         │ 암호화 키 획득 완료       │
         │ → 좌표 암호화 진행        │
         └───────────────────────────┘
```

### 2. 코드 구현

#### SmartContractService 추가 메서드

`lib/services/smart_contract_service.dart`에 `getEncryptionKey()` 메서드 추가:

```dart
/// 암호화 키 조회 (View 함수 - 가스비 없음)
Future<String> getEncryptionKey({
  required String contractAddress,
  required String userIndex,
  required String userAddress,
}) async {
  // View 함수 호출 (가스비 없음, 트랜잭션 서명 불필요)
  final contract = DeployedContract(
    ContractAbi.fromJson(
      '''
      [
        {
          "inputs": [
            {"internalType": "string", "name": "_index", "type": "string"},
            {"internalType": "address", "name": "_owner", "type": "address"}
          ],
          "name": "getEncryptionKey",
          "outputs": [
            {"internalType": "string", "name": "", "type": "string"}
          ],
          "stateMutability": "view",
          "type": "function"
        }
      ]
      ''',
      'BlockpickContract',
    ),
    EthereumAddress.fromHex(contractAddress),
  );

  final function = contract.function('getEncryptionKey');

  final result = await _client.call(
    contract: contract,
    function: function,
    params: [userIndex, EthereumAddress.fromHex(userAddress)],
  );

  return result[0] as String;
}
```

#### GameParticipationProvider 수정

`lib/providers/game_participation_provider.dart`:

```dart
// userIndex: 게임별로 고정 (wallet-gameId 형식)
final userIndex = '$walletAddress-$gameId';

final contractService = SmartContractService();
String encryptionKey;

// Step 1: 먼저 블록체인에서 키가 이미 있는지 조회
try {
  encryptionKey = await contractService.getEncryptionKey(
    contractAddress: contractAddress,
    userIndex: userIndex,
    userAddress: walletAddress,
  );

  print('✅ 기존 암호화 키 발견! (블록체인 조회 성공)');
  print('   ℹ️  서버 요청 없이 기존 키 재사용');
} catch (e) {
  // Step 2: 키가 없으면 서버를 통해 생성
  print('ℹ️  기존 키 없음 - 서버를 통한 새 키 생성...');

  final client = await ref.read(graphqlClientProvider.future);

  final keyResult = await client.mutate(
    MutationOptions(
      document: gql(_requestEncryptionKeyMutation),
      variables: {
        'input': {
          'gameId': gameId,
          'userAddress': walletAddress,
          'index': userIndex,
        },
      },
    ),
  );

  // 서버 응답에서 키를 받거나, 없으면 블록체인에서 다시 조회
  if (keyData['encryptionKey'] != null) {
    encryptionKey = keyData['encryptionKey'] as String;
  } else {
    // 서버가 키를 반환하지 않으면 블록체인에서 조회
    encryptionKey = await contractService.getEncryptionKey(
      contractAddress: contractAddress,
      userIndex: userIndex,
      userAddress: walletAddress,
    );
  }
}
```

## 장점

### 1. 비용 절감 (핵심 이점)
- **게임당 1회만 생성**: 같은 게임에 여러 번 참여해도 키는 한 번만 생성
- **서버 가스비 절약**: 불필요한 중복 트랜잭션 방지
- **조회 비용 0원**: View 함수는 가스비 없음 (읽기 전용)
- **예시**:
  - 첫 참여: 서버 가스비 1회 발생
  - 2~N번째 참여: 가스비 0원 (블록체인에서 조회만)

### 2. 성능 향상
- **빠른 응답**: 기존 키는 즉시 조회 (트랜잭션 대기 불필요)
- **서버 부하 감소**: 중복 요청 제거

### 3. 보안 강화
- **소유권 검증**: 사용자 지갑 주소로만 키 조회 가능
- **블록체인 투명성**: 모든 키 생성 기록이 블록체인에 영구 저장
- **키 재사용 안전성**: 동일 게임 내에서만 재사용 (게임별 격리)

### 4. 신뢰성
- **백업 메커니즈**: 서버 응답 실패 시 블록체인에서 직접 조회 가능
- **탈중앙화**: 서버에 의존하지 않고 블록체인에서 직접 확인

## 스마트 컨트랙트 요구사항

백엔드 스마트 컨트랙트는 다음 함수를 구현해야 합니다:

```solidity
/// @notice 암호화 키 조회 (View 함수)
/// @param _index 사용자 인덱스 (예: "지갑주소-타임스탬프")
/// @param _owner 소유자 지갑 주소
/// @return 암호화 키 (16진수 문자열)
function getEncryptionKey(
    string memory _index,
    address _owner
) public view returns (string memory) {
    // 소유권 확인
    require(
        encryptionKeys[_index].owner == _owner,
        "Not the owner"
    );

    return encryptionKeys[_index].key;
}
```

## 테스트 시나리오

### 시나리오 1: 첫 게임 참여 (키 없음)
```
1. 블록체인에서 getEncryptionKey() 호출
   → 에러 발생 (키 없음)
2. 서버에 requestEncryptionKey mutation 호출
   → 서버가 가스비 지불하여 키 생성
3. 서버 응답에서 키를 받거나, 블록체인에서 다시 조회
4. 키로 좌표 암호화 → joinGame
```

### 시나리오 2: 두 번째 이후 게임 참여 (키 있음)
```
1. 블록체인에서 getEncryptionKey() 호출
   → ✅ 성공! 기존 키 반환
2. 서버 호출 없이 즉시 키 사용
3. 키로 좌표 암호화 → joinGame

💰 가스비 절약: 서버 요청 없음, 조회만 (0원)
⚡ 성능 향상: 트랜잭션 대기 없음
```

### 시나리오 3: 다른 게임 참여
```
1. userIndex = "지갑주소-다른게임ID"로 조회
   → 에러 발생 (새 게임이므로 키 없음)
2. 서버에 새 키 생성 요청
3. 게임별로 독립적인 키 사용

🔒 보안: 게임별 키 격리
```

### 에러 케이스
```
1. 블록체인 조회 실패: 소유권 미일치 또는 네트워크 에러
2. 서버 트랜잭션 실패: success: false → 에러 처리
3. 키 생성 후 조회 실패: 드물지만 재시도 로직 필요
```

## 결론

이 최적화된 방식은 다음을 달성합니다:

1. **비용 효율성**: 게임당 1회만 키 생성 → 서버 가스비 대폭 절감
2. **사용자 경험**: 빠른 응답 속도, 가스비 없는 게임 참여
3. **보안**: 게임별 키 격리, 소유권 검증
4. **신뢰성**: 블록체인 기반 키 조회, 서버 의존성 최소화

### 핵심 차이점

**기존 방식** (매번 생성):
```
첫 참여:  서버 가스비 발생 ❌
두번째:   서버 가스비 발생 ❌
세번째:   서버 가스비 발생 ❌
총 비용:  가스비 x N회
```

**최적화 방식** (조회 우선):
```
첫 참여:  서버 가스비 발생 ❌
두번째:   블록체인 조회 (무료) ✅
세번째:   블록체인 조회 (무료) ✅
총 비용:  가스비 x 1회 + 조회 비용 0원
```

**결과**: 같은 게임에 여러 번 참여할수록 비용 절감 효과 극대화!
