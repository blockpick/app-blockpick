# 게임 참가 프로세스 (Pick 제출 시스템)

## 개요
사용자가 게임판에서 좌표(픽)를 선택하고 "참가하기" 버튼을 누를 때 실행되는 전체 프로세스를 설명합니다.

## 핵심 보안 원칙

**중요**: Blockpick의 핵심 보안 원칙은 다음과 같습니다:

1. **백엔드도 사용자의 픽(원본 좌표)을 알 수 없어야 함**
   - 백엔드가 누가 어디를 선택했는지 알면 조작 가능
   - 공정성 보장을 위해 백엔드는 암호화된 데이터만 저장

2. **서버 가스비 대납 방식**
   - 사용자는 가스비를 지불하지 않음 (UX 개선)
   - 서버가 GraphQL을 통해 트랜잭션을 대신 생성하고 가스비 지불
   - 스마트 컨트랙트에 사용자 지갑 주소(userAddress)를 기록하여 소유권 보장
   - 서버는 암호화 키를 응답으로 반환하지만, 원본 좌표는 알 수 없음

3. **클라이언트 측 암호화**
   - 좌표는 클라이언트에서만 암호화
   - 암호화 키는 스마트 컨트랙트에서 생성 (서버가 트랜잭션 실행)
   - 백엔드는 암호화된 데이터(coordCiphertext)만 저장

4. **소유권 분리**
   - 트랜잭션 발신자(msg.sender): 서버 지갑 (가스비 지불)
   - 키 소유자(sender 필드): 사용자 지갑 주소
   - 블록체인 컨트랙트에서 userAddress 기반으로 권한 관리

## 스마트 컨트랙트 정보
- **네트워크**: Polygon Amoy Testnet
- **컨트랙트 주소**: GraphQL의 `game.onchainContractAddr`에서 가져옴
  - 예시 1: `0x63d469d778f46eaa870b3ea689ad980bac94c6ad`
  - 예시 2: `0x0281716790532a1aa3e692285a502b3e40cb7da7`
  - 예시 3: `0x2f78ab6d5f84fbf594ea273e4cf4a00b4ad2033f`
- **컨트랙트 이름**: BlockpickContract
- **주요 기능**: 경매용 라운드별 암호화 키 생성 및 암호화된 좌표 저장

**중요**: 각 게임마다 별도의 스마트 컨트랙트가 배포됩니다!

### 주요 필드 설명

#### 게임 그리드 정보
- `gridRows`: 게임판 행 수 (예: 1000)
- `gridCols`: 게임판 열 수 (예: 1000)
- 총 좌표 개수: `gridRows × gridCols` = 1,000,000개

#### 참가 제한
- `entryFee`: 참가비 (1000 CASH)
- `minEntries`: 최소 참가자 수 (50명)
- `maxEntries`: 최대 참가자 수 (100명)
- `maxEntriesPerUser`: 사용자당 최대 참가 횟수 (10회)

#### 중복 설정
- `allowDuplicate`: false → 같은 좌표 중복 선택 불가

#### 자동 종료 조건
- `autoEndOnMax`: true → 최대 참가자 도달 시 자동 종료
- `autoEndOnTime`: true → 종료 시간 도달 시 자동 종료

#### 블록체인 정보
- `onchainContractAddr`: 이 게임 전용 스마트 컨트랙트 주소
- `onchainTxHash`: 컨트랙트 배포 트랜잭션 해시

## 데이터 흐름 요약

| 단계 | 클라이언트가 아는 것 | 백엔드가 아는 것 | 블록체인에 기록된 것 |
|------|---------------------|-----------------|---------------------|
| 게임 조회 | ✅ 게임 정보 전체 | ✅ 게임 정보 전체 | ✅ 컨트랙트 주소 |
| 픽 선택 | ✅ 원본 좌표 (row, col) | ❌ 모름 | ❌ 없음 |
| 키 생성 | ✅ 암호화 키 | ❌ 모름 | ✅ 암호화 키 (인덱스별) |
| 암호화 | ✅ 원본 + 암호화 좌표 | ❌ 모름 | ❌ 없음 |
| 전송 | ✅ coordCiphertext 전송 | ✅ coordCiphertext만 저장 | ❌ 없음 |
| 게임 종료 후 | ✅ 원본 좌표 (기억) | ✅ 블록체인에서 키 조회 → 복호화 | ✅ 모든 암호화 키 공개 |

## 단계별 상세 설명

### 1단계: 암호화 키 생성 요청 (GraphQL)

#### 클라이언트 동작
- 사용자가 게임판에서 좌표 선택 완료
- "참가하기" 버튼 클릭
- GraphQL Mutation `requestEncryptionKey` 호출

#### GraphQL Mutation: `requestEncryptionKey`

**GraphQL Schema:**
```graphql
mutation RequestEncryptionKey($input: RequestEncryptionKeyInput!) {
  requestEncryptionKey(input: $input) {
    success
    code
    message
    encryptionKey
    contractAddress
    txHash
    userAddress
    index
  }
}
```

**Input Parameters:**
```graphql
input RequestEncryptionKeyInput {
  gameId: String!        # 게임 ID
  userAddress: String!   # 사용자 지갑 주소
  index: String         # 고유 인덱스 (옵션, 기본값은 userId)
}
```

**Request Example:**
```json
{
  "input": {
    "gameId": "01a18547-64cc-4e9e-9816-3161f0278018",
    "userAddress": "0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb1",
    "index": "user-123-1699999999"
  }
}
```

**Response Example:**
```json
{
  "data": {
    "requestEncryptionKey": {
      "success": true,
      "code": "SUCCESS",
      "message": "암호화 키가 성공적으로 생성되었습니다.",
      "encryptionKey": "a3f7c2e1b9d4f6e8",
      "contractAddress": "0x63d469d778f46eaa870b3ea689ad980bac94c6ad",
      "txHash": "0xabc123def456...",
      "userAddress": "0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb1",
      "index": "user-123-1699999999"
    }
  }
}
```

#### 백엔드 처리 흐름
1. **게임 정보 조회**: gameId로 게임 및 컨트랙트 주소 확인
2. **서버 지갑으로 트랜잭션 생성**: 서버가 가스비 지불
3. **스마트 컨트랙트 호출**: `requestEncryptionKey(index, userAddress)` 함수 호출
4. **이벤트 파싱**: `EncryptionKeyGenerated` 이벤트에서 암호화 키 추출
5. **응답 반환**: 생성된 키와 트랜잭션 정보 반환

#### 스마트 컨트랙트 함수: `requestEncryptionKey`
```solidity
function requestEncryptionKey(
    string memory _index,
    address _userAddress
) public returns (string memory)
```

**파라미터:**
- `_index`: 참가자 고유 인덱스 (문자열)
- `_userAddress`: 사용자 지갑 주소 (소유권 기록용)

**검증 조건:**
- 인덱스가 비어있지 않아야 함
- userAddress가 zero address가 아니어야 함
- 해당 인덱스로 이미 키가 생성되지 않았어야 함
- 현재 참가자 수가 최대 참가자 수 미만이어야 함

**키 생성 방식:**
```solidity
uint256 randomSeed = uint256(
    keccak256(
        abi.encodePacked(
            block.prevrandao,      // 블록 랜덤값
            block.timestamp,       // 타임스탬프
            _userAddress,          // 사용자 주소
            _index,                // 인덱스
            currentParticipantCount  // 현재 참가자 수
        )
    )
);
```

**생성되는 데이터:**
- 16자리 hex 문자열 형태의 암호화 키
- `ParticipantData` 구조체 생성:
  - `encryptionKey`: 생성된 암호화 키
  - `encryptedCoordinates`: "" (아직 비어있음)
  - `sender`: userAddress (사용자 주소 기록)
  - `timestamp`: 생성 시각
  - `hasEncryptedData`: false

**이벤트 발생:**
```solidity
emit EncryptionKeyGenerated(_index, _userAddress, key);
```

**반환값:**
- 생성된 암호화 키 (16자 hex 문자열)

**중요: 가스비 처리**
- 트랜잭션 발신자(msg.sender): 서버 지갑
- 키 소유자(sender): 사용자 지갑 주소
- 가스비: 서버가 부담
- 소유권: 사용자에게 귀속

### 2단계: 좌표 암호화 (클라이언트)

#### 클라이언트 동작
- 1단계에서 받은 암호화 키를 사용
- 사용자가 선택한 좌표 데이터를 암호화
- 암호화 알고리즘: (클라이언트 구현에 따라 결정 - AES, ChaCha20 등)

**암호화 대상 데이터:**
- 선택한 블록의 좌표 정보
- 형식: (구현에 따라 결정)

### 3단계: 백엔드로 암호화된 데이터 전송

#### API 통신
- **방식**: HTTP POST 요청 (또는 GraphQL Mutation)
- **전송 데이터**:
  - 암호화된 좌표 데이터
  - 참가자 인덱스
  - 기타 메타데이터 (게임 ID, 사용자 ID 등)

#### 백엔드 처리
- 암호화된 데이터 수신
- 데이터베이스에 저장
- 참가 확인 응답 반환

### (선택사항) 4단계: 블록체인에 암호화된 좌표 저장

> **참고**: 이 단계는 선택적으로 사용될 수 있습니다.

#### 스마트 컨트랙트 함수: `storeEncryptedCoordinates`
```solidity
function storeEncryptedCoordinates(
    string memory _index,
    string memory _encryptedCoordinates
) public
```

**파라미터:**
- `_index`: 참가자 인덱스
- `_encryptedCoordinates`: 암호화된 좌표 데이터

**검증 조건:**
- 해당 인덱스로 암호화 키가 생성되어 있어야 함
- 호출자가 키 생성자와 동일해야 함
- 아직 암호화 데이터가 저장되지 않았어야 함
- 암호화된 좌표가 비어있지 않아야 함

**이벤트 발생:**
```solidity
emit EncryptedCoordinatesStored(_index, msg.sender);
```

## 보안 메커니즘

### 1. 암호화 키의 안전성
- **생성 방식**: `block.prevrandao` 기반
  - 이전 블록의 랜덤값 사용 (예측 불가능)
  - 타임스탬프, 호출자 주소, 인덱스 등 추가 엔트로피
- **키 길이**: 16자 hex (64비트)

### 2. 좌표 데이터 보호
- 클라이언트에서 암호화되어 전송
- 중간 경로에서 원본 좌표 노출 방지
- 블록체인에 암호화된 상태로 저장 (선택사항)

### 3. 키 조회 제한
암호화 키는 다음 조건에서만 조회 가능:

```solidity
function getEncryptionKey(string memory _index) public view returns (string memory)
```

**조회 허용 조건:**
1. 키 생성자 본인이 요청하는 경우
2. 공개 지연 시간(`delayInMinutes`)이 경과한 경우
3. 최대 참가자 수(`maxParticipantCount`)에 도달한 경우

### 4. 참가자 수 제한

- 초과 시 추가 참가 불가

### 키 조회 시나리오 (게임 종료 후)

게임이 종료되면 백엔드나 클라이언트가 직접 스마트 컨트랙트에서 암호화 키를 조회합니다.

#### 스마트 컨트랙트 함수: `getEncryptionKey`
```solidity
function getEncryptionKey(
    string memory _index,
    address _userAddress
) public view returns (string memory)
```

**조회 권한 조건**:
1. 본인(userAddress 일치)
2. 지연 시간 경과 (delayInMinutes)
3. 최대 참가자 도달 (maxParticipantCount)

#### 클라이언트에서 직접 조회 예시 (Ethers.js)
```javascript
import { ethers } from 'ethers';

// RPC 연결
const provider = new ethers.JsonRpcProvider(

// 컨트랙트 연결
const contract = new ethers.Contract(
  contractAddress,
  [
    'function getEncryptionKey(string memory _index, address _userAddress) public view returns (string memory)'
  ],
  provider
);

// 키 조회 (view 함수이므로 가스비 없음)
const encryptionKey = await contract.getEncryptionKey(
  "user-123",
  "0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb1"

if (encryptionKey) {
  console.log('암호화 키:', encryptionKey);
  // 이제 coordCiphertext를 복호화할 수 있음
} else {
  console.log('아직 키 조회 권한 없음');
}
```

```

```

#### 시나리오 2: 타인은 시간 경과 후 조회 가능

## 지갑 관리 시스템

### 개요
Blockpick은 **클라이언트에서만 지갑을 생성하고 관리**하는 방식을 사용합니다.

**중요**: 백엔드는 사용자의 지갑 주소나 개인키를 알지 못합니다. 이는 공정성 보장을 위한 핵심 설계입니다.

### 지갑 생성 시점
1. **앱 최초 실행 시**: 자동으로 지갑 생성
2. **웹 첫 방문 시**: 자동으로 지갑 생성 및 localStorage 저장

### 플랫폼별 지갑 저장 방식

#### 모바일 앱 (Flutter)
- **저장 위치**: 디바이스 로컬 스토리지 (오프라인)
- **저장 방법**: Secure Storage 사용
  - iOS: Keychain
  - Android: EncryptedSharedPreferences
- **백업**: 사용자가 시드 구문(Seed Phrase)을 기록하여 수동 백업

```dart
// 모바일 앱 예시
import 'package:flutter_secure_storage/flutter_secure_storage.dart';
import 'package:web3dart/web3dart.dart';

final storage = FlutterSecureStorage();

// 지갑 생성 (앱 최초 실행)
Future<Credentials> generateWallet() async {
  final rng = Random.secure();
  final credentials = EthPrivateKey.createRandom(rng);

  // 디바이스에만 저장
  await storage.write(
    key: 'wallet_private_key',
    value: bytesToHex(credentials.privateKey)
  );
  await storage.write(
    key: 'wallet_address',
    value: credentials.address.hex
  );

  return credentials;
}

// 지갑 불러오기
Future<Credentials?> loadWallet() async {
  final privateKeyHex = await storage.read(key: 'wallet_private_key');
  if (privateKeyHex == null) return null;

  return EthPrivateKey.fromHex(privateKeyHex);
}
```

#### 웹 (Web)
- **문제점**:
  - localStorage: 브라우저 캐시 삭제 시 손실
  - sessionStorage: 탭/윈도우 닫으면 손실
  - Cookie: 만료 시간 있음

- **해결 방법**:
  1. **localStorage 기반 (기본)**
     - localStorage에 암호화하여 저장
     - 사용자에게 시드 구문 백업 안내
     - 캐시 삭제 시 시드로 복구

  2. **선택적 백엔드 암호화 백업**
     - 사용자가 원하는 경우 백엔드에 **암호화된 지갑** 백업
     - 백엔드는 복호화할 수 없는 형태로 저장 (사용자 비밀번호로 암호화)
     - 로그인 시 암호화된 데이터를 받아서 클라이언트에서 복호화

```typescript
// 웹 클라이언트 예시
import { ethers } from 'ethers';

class WalletManager {
  // 지갑 생성
  async createWallet(): Promise<ethers.Wallet> {
    const wallet = ethers.Wallet.createRandom();

    // localStorage에 저장
    localStorage.setItem('wallet_private_key', wallet.privateKey);
    localStorage.setItem('wallet_address', wallet.address);

    // 시드 구문 표시 (사용자가 백업)
    alert(`백업용 시드 구문: ${wallet.mnemonic?.phrase}`);

    return wallet;
  }

  // 지갑 불러오기
  loadWallet(): ethers.Wallet | null {
    const privateKey = localStorage.getItem('wallet_private_key');
    if (!privateKey) return null;

    return new ethers.Wallet(privateKey);
  }

  // 시드로 복구
  recoverFromSeed(seedPhrase: string): ethers.Wallet {
    const wallet = ethers.Wallet.fromPhrase(seedPhrase);

    localStorage.setItem('wallet_private_key', wallet.privateKey);
    localStorage.setItem('wallet_address', wallet.address);

    return wallet;
  }

  // 선택적: 암호화된 백업 (사용자 비밀번호 필요)
  async backupToServer(password: string) {
    const wallet = this.loadWallet();
    if (!wallet) return;

    // 사용자 비밀번호로 암호화
    const encryptedWallet = await wallet.encrypt(password);

    // 백엔드에 암호화된 지갑 저장
    await api.post('/api/wallet/backup', {
      encryptedWallet  // 백엔드는 이것을 복호화할 수 없음
    });
  }

  // 선택적: 백엔드에서 복구
  async recoverFromServer(password: string) {
    const { encryptedWallet } = await api.get('/api/wallet/backup');

    // 클라이언트에서만 복호화 가능
    const wallet = await ethers.Wallet.fromEncryptedJson(
      encryptedWallet,
      password
    );

    localStorage.setItem('wallet_private_key', wallet.privateKey);
    localStorage.setItem('wallet_address', wallet.address);

    return wallet;
  }
}
```

### 백엔드 데이터 구조

**중요**: 백엔드는 지갑 주소를 저장하지 않습니다!

```
사용자 DB:
┌─────────────────────────────────────┐
│ users                               │
├─────────────────────────────────────┤
│ id: UUID                            │
│ email: string                       │
│ nickname: string                    │
│ (wallet_address 필드 없음!)         │
└─────────────────────────────────────┘

선택적 백업 DB (사용자가 원할 경우만):
┌─────────────────────────────────────┐
│ wallet_backups                      │
├─────────────────────────────────────┤
│ user_id: UUID                       │
│ encrypted_wallet_json: text         │ ← 사용자 비밀번호로 암호화됨
│ created_at: timestamp               │
└─────────────────────────────────────┘
```

### 보안 고려사항

#### 1. 개인키 보관
- **클라이언트에만 저장**: 백엔드는 개인키를 알 수 없음
- **디바이스 암호화 저장소 사용**: Keychain, SecureStorage 등
- **시드 구문 백업**: 사용자가 수동으로 기록

#### 2. 백엔드 선택적 백업 (옵션)
- 사용자 비밀번호로 암호화
- 백엔드는 복호화 불가능
- 사용자만 비밀번호로 복구 가능

#### 3. 익명성 보장
- 백엔드는 어떤 지갑 주소가 누구인지 모름
- 블록체인 트랜잭션과 사용자 연결 불가능
- 게임 참가 기록은 암호화된 데이터만 저장

## 클라이언트 구현 예시

### 전체 참가 프로세스 코드 (TypeScript/JavaScript)

```typescript
import { ethers } from 'ethers';
import CryptoJS from 'crypto-js';

// 1. 게임 정보 가져오기
async function getGameInfo(gameId: string) {
  const response = await fetch(GRAPHQL_ENDPOINT, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      query: `
        query GetGame($id: String!) {
          getGame(id: $id) {
            game {
              id
              onchainContractAddr
              gridRows
              gridCols
              maxEntries
              allowDuplicate
            }
          }
        }
      `,
      variables: { id: gameId }
    })
  });

  const { data } = await response.json();
  return data.getGame.game;
}

// 2. 지갑 로드 또는 생성
function loadOrCreateWallet(): ethers.Wallet {
  const privateKey = localStorage.getItem('wallet_private_key');

  if (privateKey) {
    return new ethers.Wallet(privateKey);
  }

  // 새 지갑 생성
  const newWallet = ethers.Wallet.createRandom();
  localStorage.setItem('wallet_private_key', newWallet.privateKey);
  localStorage.setItem('wallet_address', newWallet.address);

  console.log('새 지갑 생성:', newWallet.address);
  console.log('시드 구문 백업:', newWallet.mnemonic?.phrase);

  return newWallet;
}

// 3. GraphQL로 암호화 키 요청 (서버 가스비 대납)
async function requestEncryptionKey(
  gameId: string,
  userAddress: string,
  accessToken: string
): Promise<{ encryptionKey: string; txHash: string; contractAddress: string }> {
  const response = await fetch(GRAPHQL_ENDPOINT, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${accessToken}`
    },
    body: JSON.stringify({
      query: `
        mutation RequestEncryptionKey($input: RequestEncryptionKeyInput!) {
          requestEncryptionKey(input: $input) {
            success
            code
            message
            encryptionKey
            contractAddress
            txHash
            userAddress
            index
          }
        }
      `,
      variables: {
        input: {
          gameId,
          userAddress,
          index: `${userAddress}-${Date.now()}`
        }
      }
    })
  });

  const { data } = await response.json();

  if (!data.requestEncryptionKey.success) {
    throw new Error(data.requestEncryptionKey.message);
  }

  return {
    encryptionKey: data.requestEncryptionKey.encryptionKey,
    txHash: data.requestEncryptionKey.txHash,
    contractAddress: data.requestEncryptionKey.contractAddress
  };
}

// 4. 좌표 암호화
function encryptCoordinates(
  coordinates: { row: number; col: number },
  encryptionKey: string
): string {
  const plaintext = JSON.stringify(coordinates);
  const ciphertext = CryptoJS.AES.encrypt(plaintext, encryptionKey).toString();
  return ciphertext;
}

// 5. GraphQL로 게임 참가
async function joinGameViaGraphQL(
  gameId: string,
  productId: string,
  coordCiphertext: string,
  walletAddress: string,
  contractAddr: string
) {
  // 지갑 주소 해시화 (보안 강화)
  const walletHash = ethers.keccak256(
    ethers.toUtf8Bytes(walletAddress)
  );

  const response = await fetch(GRAPHQL_ENDPOINT, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${accessToken}`
    },
    body: JSON.stringify({
      query: `
        mutation JoinGame($input: JoinGameInput!) {
          joinGame(input: $input) {
            success
            code
            message
            entryId
            status
            txHash
          }
        }
      `,
      variables: {
        input: {
          gameId,
          selectedGameProductId: productId,
          coordCiphertext,
          signerWallet: walletHash,  // 해시된 지갑 주소
          contractAddress: contractAddr,
          idempotencyKey: `${walletAddress}-${Date.now()}`
        }
      }
    })
  });

  const { data } = await response.json();
  return data.joinGame;
}

// 전체 프로세스 실행 (서버 가스비 대납 방식)
async function participateInGame(
  gameId: string,
  selectedCoordinates: { row: number; col: number },
  accessToken: string
) {
  try {
    // 1. 게임 정보 가져오기
    console.log('1. 게임 정보 조회 중...');
    const game = await getGameInfo(gameId);

    // 2. 지갑 로드 (또는 생성)
    console.log('2. 지갑 로드 중...');
    const wallet = loadOrCreateWallet();

    // 3. GraphQL로 암호화 키 요청 (서버가 가스비 지불)
    console.log('3. 서버를 통해 암호화 키 생성 중...');
    const { encryptionKey, txHash, contractAddress } = await requestEncryptionKey(
      gameId,
      wallet.address,
      accessToken
    );
    console.log('✅ 암호화 키 생성 완료:', encryptionKey);
    console.log('트랜잭션 해시:', txHash);

    // 4. 좌표 암호화
    console.log('4. 좌표 암호화 중...');
    const coordCiphertext = encryptCoordinates(
      selectedCoordinates,
      encryptionKey
    );

    // 5. 게임 참가
    console.log('5. 게임 참가 요청 중...');
    const result = await joinGameViaGraphQL(
      gameId,
      game.gameProducts[0].id,
      coordCiphertext,
      wallet.address,
      contractAddress
    );

    console.log('✅ 게임 참가 완료!', result);
    return result;

  } catch (error) {
    console.error('❌ 게임 참가 실패:', error);
    throw error;
  }
}
```

## 클라이언트 구현 시 고려사항

### 1. 서버 가스비 대납 방식의 장점
- **사용자 경험 개선**: 사용자가 가스비를 지불할 필요 없음
- **온보딩 간소화**: MATIC 보유 불필요, 즉시 게임 참가 가능
- **GraphQL API 사용**: HTTP 요청으로 간단히 처리 가능
- **블록체인 복잡성 숨김**: 일반 웹/앱 개발과 동일한 방식

### 2. 지갑 관리
- **지갑 생성**: 앱 최초 실행 시 자동 생성
- **저장 위치**:
  - 모바일: Secure Storage (Keychain/EncryptedSharedPreferences)
  - 웹: localStorage (시드 백업 권장)
- **백업**: 사용자에게 시드 구문 백업 안내
- **복구**: 시드 구문으로 지갑 복구 기능 제공

### 3. 트랜잭션 처리 (서버 대납 방식)
- **가스비**: 서버가 자동으로 처리
- **트랜잭션 확인**: txHash로 블록체인 상태 확인 가능 (옵션)
- **대기 시간**: GraphQL 응답까지 약 3-10초 (블록 확인 시간)
- **UI 처리**: 로딩 인디케이터 표시 권장

### 4. 에러 처리
```javascript
// GraphQL 에러 처리 예시
try {
  const result = await requestEncryptionKey(gameId, userAddress, accessToken);
} catch (error) {
  // GraphQL 응답에서 에러 처리
  if (error.message.includes("Maximum participants reached")) {
    alert("최대 참가자 수에 도달했습니다.");
  } else if (error.message.includes("Key already generated")) {
    alert("이미 참가한 게임입니다.");
  } else if (error.message.includes("Game not found")) {
    alert("게임을 찾을 수 없습니다.");
  } else {
    alert("참가 중 오류가 발생했습니다: " + error.message);
  }
}
```

### 5. 암호화 라이브러리 선택
- AES-256-GCM (권장)
- ChaCha20-Poly1305
- 키 유도: PBKDF2 또는 직접 사용

### 6. UX 개선
- **로딩 상태**: "암호화 키 생성 중..." 표시
- **진행 단계 표시**:
  1. 암호화 키 요청 중
  2. 좌표 암호화 중
  3. 게임 참가 등록 중
- **완료 확인**: 참가 완료 알림 및 entryId 저장
- **트랜잭션 링크**: Polygonscan 링크 제공 (옵션)


**Variables:**
```json
{
  "input": {
    "gameId": "01a18547-64cc-4e9e-9816-3161f0278018",
    "selectedGameProductId": "product-uuid",
    "coordCiphertext": "U2FsdGVkX1...",      // 암호화된 좌표
    "idempotencyKey": "unique-key-12345",     // 중복 방지
    "signerWallet": "0x742d35Cc...",          // ⚠️ 지갑 주소

  }
}
```

**Response:**
```json
{
  "data": {
    "joinGame": {
      "success": true,
      "code": "SUCCESS",
      "message": "게임 참가가 완료되었습니다.",
      "entryId": "entry-uuid",
      "status": "JOINED",
      "txHash": "0xabc123...",
      "errorCode": null
    }
  }
}
```

**보안 고려사항**:

현재 API는 `signerWallet` (지갑 주소)를 평문으로 받습니다. 이는 다음과 같은 트레이드오프가 있습니다:

**현재 방식 (평문 지갑 주소)**:
- ✅ 중복 참가 방지 용이
- ✅ 사용자별 참가 내역 추적 가능
- ⚠️ 백엔드가 지갑 주소를 알게 됨

**개선 옵션 1: 지갑 주소 해시화**
```javascript
import { keccak256, toUtf8Bytes } from 'ethers';

const walletAddress = "0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb1";
const hashedAddress = keccak256(toUtf8Bytes(walletAddress));
// 결과: "0xa8f5f167f44f4964e6c998dee827110c687f5b3e30c68a5f..."

await joinGame({
  gameId: "game-id",
  coordCiphertext: "encrypted-coords",
  signerWallet: hashedAddress,  // 해시값만 전송
  contractAddress: "0x63d469d7..."
});
```

**장점**:
- ✅ 백엔드는 원본 주소를 알 수 없음 (역변환 불가능)
- ✅ 중복 참가 방지 가능 (같은 주소 = 같은 해시)
- ✅ 사용자 익명성 향상

**개선 옵션 2: `signerWallet` 필드 완전 제거**
- txHash로만 블록체인에서 검증
- 완전한 익명성 보장
- 단, 중복 참가 방지는 블록체인 컨트랙트에서만 처리

**처리 과정**:
1. `idempotencyKey`로 중복 요청 확인
2. `txHash`로 블록체인에서 트랜잭션 검증 (선택)
3. `coordCiphertext` (암호화된 좌표)만 DB에 저장
4. 게임 참가자 수 증가
5. 응답 반환

**Input 필드 설명**:
- `gameId`: 참가할 게임 ID
- `selectedGameProductId`: 선택한 상품 ID
- `coordCiphertext`: 암호화된 좌표 (클라이언트에서 암호화)
- `idempotencyKey`: 중복 요청 방지 키 (선택, 권장)
- `signerWallet`: 트랜잭션 서명한 지갑 주소 (⚠️ 보안 고려 필요)
- `contractAddress`: 스마트 컨트랙트 주소
