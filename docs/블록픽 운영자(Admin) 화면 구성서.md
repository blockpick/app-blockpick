# 블록픽 운영자(Admin) 화면 구성서

# 1. 공통 UI 원칙

## 1-1. 핵심 원칙

- 운영자는 **문제 상황을 빠르게 발견하고 조치**할 수 있어야 한다.
- 모든 핵심 화면은 **필터 → 리스트 → 상세 → 상태 변경** 구조를 기본으로 한다.
- Admin 화면은 보기보다 **조치 버튼과 기록 추적**이 중요하다.
- 승인 / 반려 / 제재 / 정지 / 복구 같은 액션은 항상 **근거와 로그**를 남겨야 한다.

## 1-2. 공통 UI 레이아웃

- **좌측 사이드바**
    - 주요 메뉴
- **상단 바**
    - 관리자 역할
    - 통합 검색
    - 긴급 알림
    - 계정 메뉴
- **본문 영역**
    - KPI 카드 / 테이블 / 상세 패널 / 상태 변경 모달 / 로그
- **우측 보조 영역(선택)**
    - 미처리 건수
    - 우선 대응 이슈
    - 운영 메모

## 1-3. 공통 UI 요소

- KPI 카드
- 상태 배지
    - 승인 대기 / 승인 / 반려 / 정지
    - 검수 대기 / 진행중 / 종료 / 강제중지
    - 신고 접수 / 처리중 / 처리완료
    - 결제 실패 / 유예 / 정상 / 해지
- 리스트 테이블
- 검색창
- 다중 필터
- 상세 슬라이드 패널 또는 우측 패널
- 상태 변경 모달
- 관리자 메모 입력창
- 로그 타임라인
- CSV 다운로드 버튼

## 1-4. 공통 CTA 문구 원칙

- 승인: **승인하기**
- 반려: **반려하기**
- 수정 요청: **수정 요청하기**
- 제재: **제재 적용**
- 강제 중지: **즉시 중지**
- 복구: **복구하기**
- 저장: **저장하기**
- 다운로드: **내보내기**
- 확인: **상세 보기**

# 2. 홈 화면 구성

## 2-1. 운영자 홈

### 화면 목적

- 플랫폼 전체 상태를 한눈에 파악
- 오늘 처리해야 할 핵심 이슈를 우선 확인
- 승인 대기 / 신고 / 결제 실패 / 이상 징후를 빠르게 확인

### 주요 UI 요소

- 상단 헤더
    - 제목: Admin Dashboard
    - 기간 선택
    - 통합 검색
- KPI 카드
    - 전체 파트너 수
    - 유료 파트너 수
    - 진행중 블록픽 수
    - 승인 대기 수
    - 신고 처리 대기 수
    - 결제 실패 수
- 긴급 알림 영역
    - 이상 트래픽 급증
    - 신고 다수 발생
    - 고액 파트너 결제 실패
- 최근 처리 필요 리스트
    - 승인 대기 파트너
    - 검수 대기 블록픽
    - 처리 대기 신고
- 플랫폼 성과 요약 차트
    - 전체 방문 / 전체 참여 / 유료 구독 추이
- 빠른 액션 영역
    - 승인 대기 보기
    - 신고 처리 보기
    - 결제 실패 보기
    - 검수 대기 보기

### CTA

- **승인 대기 보기**
- **검수 대기 보기**
- **신고 처리하기**
- **결제 실패 보기**
- **플랫폼 성과 보기**

### 비고

- 홈은 “운영 우선순위 정렬 화면”이어야 함
- 단순 통계보다 “조치 필요 건”이 더 중요

# 14. 최종 정리

이 운영자(Admin) 화면 구성서는 아래 흐름을 중심으로 설계된다.

## 핵심 흐름

- **승인**
    - 파트너 승인 대기 / 블록픽 검수 대기
- **통제**
    - 신고 / 제재 / 강제 중지
- **운영**
    - 파트너 상태 / 블록픽 상태 / 과금 상태 관리
- **정책**
    - 광고 / 미션 / 약관 / 운영 기준
- **모니터링**
    - 플랫폼 전체 성과 / 이상 징후 / 감사 로그

## 핵심 원칙

- 운영자는 즉시 판단하고 조치할 수 있어야 한다.
- 조치에는 항상 근거와 이력이 남아야 한다.
- 국가 기준 분기와 글로벌 정책 관리가 가능해야 한다.
- 파트너 대시보드보다 더 강한 통제 UI가 필요하다.
