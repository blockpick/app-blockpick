# Cross-track 시나리오

> 파트너(partner-blockpick) ↔ Admin(admin-blockpick) ↔ 유저앱(app-blockpick) 전체 연동 흐름  
> 이 문서는 단일 앱 범위를 넘는 멀티 트랙 시나리오를 정의합니다.  
> 자동화: 수동 테스트 기반 (각 앱/대시보드 동시 조작 필요)

---

## 시스템 구성

```
partner-blockpick (Next.js)
    └── 파트너 캠페인 생성 / 통계 확인
          ↓ 검수 요청
admin-blockpick (Next.js)
    └── 캠페인 검수 / 승인·반려 / 추첨 실행 / 배송 관리
          ↓ 승인 후 유저앱 노출
app-blockpick (Flutter)
    └── 유저 탐색 / 참여 / 당첨 확인 / 배송지 입력
```

---

## CX-001 | 파트너 캠페인 생성 → Admin 승인 → 유저앱 노출

**우선순위**: P0  
**예상 소요**: 15분  
**자동화**: 부분 (각 앱 수동 조작 + API 응답 확인)

### Pre-condition
- 파트너 계정 활성화 (partner-blockpick 로그인 가능)
- Admin 계정 활성화 (admin-blockpick 로그인 가능)
- 유저 계정 활성화 (app-blockpick 로그인 가능)

### Steps
| # | 트랙 | 액션 | 확인 포인트 |
|---|------|------|-------------|
| 1 | 파트너 | 파트너 대시보드 → "새 블록픽 생성" | 생성 폼 진입 |
| 2 | 파트너 | 캠페인명·카테고리·기간·경품 정보 입력 → "게시 요청" | 요청 완료 토스트 |
| 3 | Admin | 검수 대기 목록에 해당 캠페인 노출 확인 | 목록 내 캠페인명 표시 |
| 4 | Admin | 캠페인 상세 검토 → "승인" 클릭 | 상태: 승인됨 |
| 5 | 유저앱 | 블록픽 탭 새로고침 | 해당 캠페인 카드 노출 |
| 6 | 유저앱 | 홈 탭 "신규 오픈" 섹션 확인 | 카드 노출 |

### Expected (전체)
- 파트너 → Admin → 유저앱 데이터 전파 지연 < 30초
- 유저앱 카드: 캠페인명 / 파트너명 / 마감일 / 혜택 정보 일치
- Admin 대시보드 상태: "승인됨"

## CX-002 | 파트너 캠페인 반려 → 수정 재요청 → 승인

**우선순위**: P1  
**예상 소요**: 20분  
**자동화**: 수동

### Steps
| # | 트랙 | 액션 | 확인 포인트 |
|---|------|------|-------------|
| 1 | 파트너 | 캠페인 게시 요청 완료 | - |
| 2 | Admin | 검수 → "반려" + 사유 입력 | 반려 처리 완료 |
| 3 | 파트너 | 반려 알림 확인 / 반려 사유 노출 | 사유 텍스트 표시 |
| 4 | 파트너 | 캠페인 수정 (이미지/설명 변경) → "재검수 요청" | 재요청 완료 |
| 5 | Admin | 재검수 목록 확인 → 승인 | 상태: 승인됨 |
| 6 | 유저앱 | 블록픽 탭 확인 | 캠페인 노출 |

### Expected
- 반려 사유가 파트너 대시보드에 명확히 표시
- 수정 후 재요청 가능 (횟수 제한 없음 또는 3회 이내)
- 최종 승인 후 유저앱 노출 정상

## CX-003 | 유저 참여 → 파트너 & Admin 통계 실시간 반영

**우선순위**: P0  
**예상 소요**: 10분  
**자동화**: 부분 (유저앱 자동화 + 대시보드 수동 확인)

### Pre-condition
- CX-001 완료 (캠페인 승인·노출 상태)
- 유저 A 계정 로그인

### Steps
| # | 트랙 | 액션 | 확인 포인트 |
|---|------|------|-------------|
| 1 | 유저앱 | 해당 캠페인 상세 → 블록 선택 → 확정 | 참여 완료 |
| 2 | Admin | 캠페인 상세 → 참여자 목록 | 유저 A 정보 표시 |
| 3 | Admin | 참여 일시, 선택 블록 번호 확인 | 데이터 일치 |
| 4 | 파트너 | 파트너 대시보드 → 캠페인 통계 | 참여자 수 +1 |

### Expected
- 참여 후 통계 반영 지연 < 60초
- Admin·파트너 양쪽 모두 동일한 참여자 수 표시
- 블록체인 기록 확인 (해시값 Admin 화면 노출)

## CX-004 | 캠페인 종료 → Admin 추첨 → 당첨자 알림 발송

**우선순위**: P0  
**예상 소요**: 20분  
**자동화**: 부분

### Pre-condition
- 캠페인 기간 종료 (또는 Admin이 수동 종료)
- 참여자 3명 이상

### Steps
| # | 트랙 | 액션 | 확인 포인트 |
|---|------|------|-------------|
| 1 | Admin | 캠페인 상세 → "추첨 실행" 클릭 | 당첨자 목록 생성 |
| 2 | Admin | 당첨자 정보 (닉네임, 선택 블록) 확인 | 정상 조회 |
| 3 | 유저앱 (당첨) | 푸시 알림 수신 확인 | "축하합니다! 당첨" |
| 4 | 유저앱 (당첨) | 알림함 → 당첨 알림 탭 | 당첨 상세 진입 |
| 5 | 유저앱 (미당첨) | 참여내역 → 해당 캠페인 상태 확인 | "미당첨" 표시 |
| 6 | 파트너 | 파트너 대시보드 → 당첨자 확인 | 당첨자 정보 노출 |

### Expected
- 추첨 후 당첨 유저에게 푸시 알림 발송 < 5분
- 미당첨 유저 참여내역 상태 "미당첨"으로 변경
- 파트너 대시보드에서 당첨자 배송지 입력 대기 상태 표시

## CX-005 | 당첨 유저 배송지 입력 → 파트너 배송 처리 → 완료

**우선순위**: P0  
**예상 소요**: 15분  
**자동화**: 부분

### Pre-condition
- CX-004 완료 (당첨자 알림 발송 완료)

### Steps
| # | 트랙 | 액션 | 확인 포인트 |
|---|------|------|-------------|
| 1 | 유저앱 | 당첨 상세 → "배송지 입력" → 정보 입력 → 저장 | "배송지 저장 완료" |
| 2 | 파트너 | 파트너 대시보드 → 당첨자 배송지 정보 확인 | 수령자명·주소 표시 |
| 3 | 파트너 | "배송 완료" 처리 | 상태: 배송 완료 |
| 4 | 유저앱 | 당첨 상세 → 지급 상태 확인 | "배송 완료" 표시 |
| 5 | 유저앱 | 알림함 | "경품이 발송되었습니다" 알림 |

### Expected
- 파트너 배송 완료 처리 후 유저앱 상태 업데이트 < 30초
- 유저앱 배송 완료 알림 발송
- Admin 대시보드 캠페인 처리 현황 업데이트

## CX-006 | 친구 초대 리퍼럴 → 신규 가입 → 파트너 통계 반영

**우선순위**: P1  
**예상 소요**: 25분  
**자동화**: 수동 (2기기 필요)

### Pre-condition
- 유저 A: 특정 캠페인 참여 완료
- 유저 B: 미가입 상태
- 2대 기기 또는 시뮬레이터/에뮬레이터 2개

### Steps
| # | 트랙 | 액션 | 확인 포인트 |
|---|------|------|-------------|
| 1 | 유저앱 A | 친구초대 탭 → 초대 링크 복사 | 링크 복사 완료 |
| 2 | 유저앱 B | 복사된 링크 접속 → 앱 설치 → 회원가입 | 가입 완료 |
| 3 | 유저앱 B | 해당 캠페인 참여 | 참여 완료 |
| 4 | 유저앱 A | 친구초대 탭 → 초대 성공 수 +1 | 보상 지급 알림 |
| 5 | Admin | 캠페인 참여자 목록 → 리퍼럴 참여 표시 | B 유저 리퍼럴 출처 표시 |
| 6 | 파트너 | 파트너 대시보드 → 리퍼럴 통계 | 친구 초대 참여 +1 |

### Expected
- A 유저 초대 보상 (추가 참여권 또는 포인트) 즉시 지급
- B 유저 신규 가입 혜택 지급
- Admin 리퍼럴 출처 데이터 정확히 추적

## CX-007 | Admin 캠페인 강제 종료 → 유저앱 즉시 참여 차단

**우선순위**: P1  
**예상 소요**: 10분  
**자동화**: 부분

### Pre-condition
- 진행 중인 캠페인 유저앱에 노출 중

### Steps
| # | 트랙 | 액션 | 확인 포인트 |
|---|------|------|-------------|
| 1 | Admin | 캠페인 상세 → "즉시 종료" → 사유 입력 → 확인 | 상태: 강제 종료 |
| 2 | 유저앱 | 해당 블록픽 화면 새로고침 | "종료된 블록픽" 안내 |
| 3 | 유저앱 | "지금 참여하기" 버튼 상태 확인 | 비활성화 |
| 4 | 유저앱 | 기존 참여자 → 참여내역 상태 확인 | "종료" 배지 표시 |
| 5 | 파트너 | 파트너 대시보드 → 캠페인 상태 | "Admin 종료" 표시 |

### Expected
- 강제 종료 후 유저앱 참여 차단 지연 < 60초
- 기존 참여 데이터 유지 (삭제 없음)
- 파트너에게 종료 사유 알림 발송
