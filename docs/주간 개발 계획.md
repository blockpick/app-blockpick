## 0. 한 줄 요약

> 블록픽은 **유저앱 / Admin / 파트너 대시보드 / API** 4트랙으로 구성된 SaaS. 현재 유저앱·Admin·API는 부분 구현, **파트너 대시보드는 미존재**. 가장 큰 신규 갭은 **포인트 시스템 / 출석·오퍼월 / 게임 카테고리 / 파트너 대시보드 신규 구축**. **4인 병렬 약 10주, 1인 직렬 약 26~30주**로 1차 MVP 완성 가능.

## 5. Cross-track 의존성 / Critical Path

```
[D-W1: 검색/카테고리 파라미터]  →  [A-W2: 검색/필터]
[D-W2: 포인트 도메인]           →  [A-W4: 포인트 적립], [C-W4: 포인트 표시]
[D-W3: 출석/미니게임]           →  [A-W4: 적립 흐름]
[D-W4: 오퍼월 콜백]             →  [A-W5: 오퍼월 진입]
[D-W5: 파트너 CRUD]             →  [C-W2~W3: 블록픽 관리]
[D-W5: 승인 워크플로우]         →  [B-W1: 파트너 관리]
[D-W6: Admin 검수/제재]         →  [B-W2: 블록픽 검수], [B-W3: 신고/제재]
[D-W6: 과금]                    →  [B-W4: 과금/구독], [C-W6: 구독결제]
[D-W7: 분석 집계]               →  [B-W7: 분석], [C-W5: 분석]
```

> **Critical Path는 Track D (API)**. API 스펙 합의가 모든 트랙의 선행 조건. W1에 4트랙 합동 스펙 회의 필수.

## 7. 리스크 / 가정

1. **인원 가정**: 4트랙 동시 진행 위해 **최소 4인** (Mobile Flutter / Frontend Next.js × 2 / Backend Kotlin) 또는 풀스택 3인. 1인 직렬 시 **26~30주**.
2. **파트너 대시보드 결정 지연** 시 Track C 시작 자체가 지연 → 전체 기간 +2~3주.
3. **API 스펙 미합의** 시 클라이언트 트랙 mock 진행 후 통합 (위험).
4. **외부 SDK/계약** (오퍼월·PG·광고·푸시) 지연 시 해당 주차 일감 미뤄짐.
5. **iOS 인증서/프로비저닝**, **카카오 비즈앱 심사**는 항상 변수.
6. **블록체인 통합** (`b2c2610` Ronin Mainnet 이전) 운영 안정성 — Track D 분석 작업과 별개로 모니터링 필요.
