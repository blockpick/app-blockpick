## 1.1 BlockpickScreen (메인 컨테이너)

### 화면 구성
- 상단에 MainAppBar 또는 SubAppBar가 있다
- 좌측에 드로어(AppDrawer)가 있다
- 중앙에 6개 화면 중 하나가 표시된다 (IndexedStack)
- 하단에 BottomNavBar가 있다 (BlockPick 모드일 때만)
- 플랫폼 모드에 따라 화면 구조가 달라진다 (Official / BlockPick / Mall)

### 사용자 행동 시나리오

#### 시나리오 1: 앱 최초 실행
1. 사용자가 앱을 실행한다
2. 시스템은 platformModeNotifierProvider를 확인한다
3. 시스템은 기본적으로 BlockPick 모드로 설정한다
4. 시스템은 _currentIndex를 2로 설정한다 (PICK 탭)
5. 시스템은 HomeScreen을 표시한다
6. 시스템은 하단 네비게이션 바를 표시한다
7. 시스템은 MainAppBar를 표시한다

#### 시나리오 2: 하단 네비게이션 탭 클릭
1. 사용자가 하단 네비게이션 바에서 "My Pick" 아이콘을 클릭한다
2. 시스템은 _currentIndex를 1로 변경한다
3. 시스템은 IndexedStack을 사용하여 MyPickScreen을 표시한다
4. 시스템은 AppBar를 SubAppBar로 변경한다
5. 시스템은 AppBar 타이틀을 "My Pick"으로 표시한다

#### 시나리오 3: 메인 페이지와 서브 페이지 구분
- 메인 페이지 (MainAppBar 표시):
  - OFFICIAL 모드
  - MALL 모드
  - BlockPick의 HOME 탭 (index 0)
  - BlockPick의 PICK 탭 (index 2)
- 서브 페이지 (SubAppBar 표시):
  - BlockPick의 My Pick 탭 (index 1)
  - BlockPick의 Winners 탭 (index 3)
  - BlockPick의 MALL 탭 (index 4)
  - BlockPick의 MY 탭 (index 5)

#### 시나리오 4: 플랫폼 모드 전환
1. 사용자가 MainAppBar의 플랫폼 드롭다운을 클릭한다
2. 시스템은 3가지 옵션을 표시한다 (Official / BlockPick / Mall)
3. 사용자가 "OFFICIAL"을 선택한다
4. 시스템은 platformModeNotifierProvider를 PlatformMode.official로 변경한다
5. 시스템은 OfficialScreen을 표시한다
6. 시스템은 하단 네비게이션 바를 숨긴다
7. 시스템은 MainAppBar를 표시한다

#### 시나리오 5: 드로어 열기
1. 사용자가 MainAppBar의 메뉴 아이콘을 클릭한다
2. 시스템은 좌측에서 AppDrawer를 슬라이드 인한다
3. 시스템은 드로어 내용을 표시한다

#### 시나리오 6: 알림 아이콘 클릭
1. 사용자가 AppBar의 알림 아이콘을 클릭한다
2. 시스템은 알림 기능을 실행한다 (TODO: 미구현)

#### 시나리오 7: 사용자 아이콘 클릭 (로그인 상태)
1. 사용자가 MainAppBar의 사용자 아이콘을 클릭한다
2. 시스템은 isAuthenticatedProvider를 확인한다
3. 시스템은 사용자가 로그인되어 있음을 감지한다
4. 시스템은 _currentIndex를 5로 변경한다
5. 시스템은 MyScreen을 표시한다

#### 시나리오 8: 사용자 아이콘 클릭 (비로그인 상태)
1. 사용자가 MainAppBar의 사용자 아이콘을 클릭한다
2. 시스템은 사용자가 로그인하지 않았음을 감지한다
3. 시스템은 showLoginDialog()를 호출한다
4. 시스템은 로그인 다이얼로그를 표시한다

#### 시나리오 9: MY 페이지에서 설정 아이콘 클릭
1. 사용자가 MY 탭으로 이동한다 (index 5)
2. 시스템은 SubAppBar를 표시한다
3. 시스템은 알림 아이콘 대신 설정 아이콘을 표시한다
4. 사용자가 설정 아이콘을 클릭한다
5. 시스템은 context.push('/settings')를 호출한다
6. 시스템은 SettingsScreen을 표시한다

## 2.1 HomeScreen (홈 - 게임 목록)

### 화면 구성
- 상단에 4개의 탭이 있다 (DAILY / SELECT / VIBE / OPTIMAL)
- 각 탭 아래에 해당 타입의 게임 목록이 표시된다
- TabBar와 TabBarView를 사용한다

### 사용자 행동 시나리오

#### 시나리오 1: 화면 진입
1. 사용자가 하단 네비게이션 바에서 PICK 아이콘을 클릭한다
2. 시스템은 HomeScreen을 표시한다
3. 시스템은 기본적으로 'DAILY' 탭을 활성화 상태로 표시한다
4. 시스템은 파란색 인디케이터를 DAILY 탭 하단에 표시한다
5. 시스템은 DAILY 타입 게임 목록을 로드한다

#### 시나리오 2: SELECT 탭 클릭
1. 사용자가 'SELECT' 탭을 클릭한다
2. 시스템은 TabController의 인덱스를 1로 변경한다
3. 시스템은 SELECT 탭을 파란색으로 표시한다
4. 시스템은 인디케이터를 SELECT 탭으로 이동한다
5. 시스템은 GameListScreen(gameType: GameType.select)를 표시한다
6. 시스템은 SELECT 타입 게임 목록을 로드한다

#### 시나리오 3: VIBE 탭 클릭
1. 사용자가 'VIBE' 탭을 클릭한다
2. 시스템은 TabController의 인덱스를 2로 변경한다
3. 시스템은 VIBE 탭을 활성화 상태로 표시한다
4. 시스템은 GameListScreen(gameType: GameType.vibe)를 표시한다

#### 시나리오 4: OPTIMAL 탭 클릭
1. 사용자가 'OPTIMAL' 탭을 클릭한다
2. 시스템은 TabController의 인덱스를 3으로 변경한다
3. 시스템은 OPTIMAL 탭을 활성화 상태로 표시한다
4. 시스템은 OptimalGameListScreen()을 표시한다
5. 시스템은 최적가 게임 목록을 로드한다 (다른 탭과 레이아웃이 다름)

#### 시나리오 5: 탭 전환 애니메이션
1. 사용자가 탭을 클릭한다
2. 시스템은 TabBarView의 애니메이션을 실행한다
3. 시스템은 이전 화면을 좌/우로 슬라이드 아웃한다
4. 시스템은 새 화면을 좌/우로 슬라이드 인한다

## 2.2 GameListScreen (게임 목록)

### 화면 구성
- 상단에 배너 영역이 있다 (Purple → Blue 그라데이션)
- 배너 아래에 필터 바가 있다
- 필터 바에는 카테고리 필터 칩들이 있다 (ALL / Digital / Fashion / Gift / Food)
- 필터 바 하단에는 정렬 드롭다운과 게임 개수가 표시된다
- 하단에는 게임 카드 그리드가 표시된다

### 사용자 행동 시나리오

#### 시나리오 1: 게임 목록 최초 로딩
1. 사용자가 게임 목록 화면에 진입한다
2. 시스템은 배너를 표시한다
3. 시스템은 "PICK YOUR PRIZE, MAKE IT YOURS" 텍스트를 표시한다
4. 시스템은 중앙에 CircularProgressIndicator를 표시한다
5. 시스템은 gamesByTypeProvider를 watch한다
6. 시스템은 GraphQL API를 통해 게임 데이터를 요청한다
7. 시스템은 데이터 로드가 완료되면 게임 카드 그리드를 표시한다
8. 시스템은 필터 바에 게임 개수를 표시한다 (예: "12 games")

#### 시나리오 2: ALL 카테고리 필터
1. 사용자가 화면에 진입한다
2. 시스템은 기본적으로 'ALL' 카테고리를 선택 상태로 표시한다
3. 시스템은 ALL 칩을 파란색 배경, 흰색 텍스트로 표시한다
4. 시스템은 모든 카테고리의 게임을 표시한다

#### 시나리오 3: Digital 카테고리 필터 선택
1. 사용자가 'Digital' 카테고리 칩을 클릭한다
2. 시스템은 _selectedCategory를 'Digital'로 변경한다
3. 시스템은 Digital 칩을 선택 상태로 표시한다 (파란색 배경)
4. 시스템은 이전 선택 칩(ALL)을 선택 해제한다 (흰색 배경)
5. 시스템은 games.where((g) => g.category == 'Digital')을 실행한다
6. 시스템은 Digital 카테고리 게임만 필터링하여 표시한다
7. 시스템은 필터 바에 필터링된 게임 개수를 업데이트한다 (예: "5 games")

#### 시나리오 4: 정렬 드롭다운 클릭
1. 사용자가 정렬 드롭다운을 클릭한다
2. 시스템은 PopupMenuButton을 호출한다
3. 시스템은 4가지 정렬 옵션을 팝업 메뉴로 표시한다:
   - Most Popular (popular)
   - Newest (newest)
   - Ending Soon (ending_soon)
   - Price Low to High (price_low)
4. 시스템은 현재 선택된 옵션에 체크 표시를 한다

#### 시나리오 5: Newest 정렬 선택
1. 사용자가 'Newest' 옵션을 클릭한다
2. 시스템은 _selectedSort를 'newest'로 변경한다
3. 시스템은 팝업 메뉴를 닫는다
4. 시스템은 드롭다운 라벨을 'Newest'로 변경한다
5. 시스템은 sortedGamesProvider를 재계산한다
6. 시스템은 게임 목록을 최신순으로 재정렬하여 표시한다

#### 시나리오 6: 게임 카드 클릭
1. 사용자가 게임 카드를 클릭한다
2. 시스템은 GameCard의 onTap 콜백을 호출한다
3. 시스템은 console에 디버그 로그를 출력한다:
   - game.id
   - game.imageUrl
   - 이동 경로
4. 시스템은 context.go('/game/${game.id}')를 호출한다
5. 시스템은 GameScreen으로 이동한다

#### 시나리오 7: 로딩 중 상태
1. 시스템이 데이터를 로딩 중이다
2. 시스템은 gamesAsync.when의 loading 브랜치를 실행한다
3. 시스템은 화면 중앙에 CircularProgressIndicator를 표시한다
4. 시스템은 인디케이터 색상을 AppColors.blue로 설정한다

#### 시나리오 8: 에러 발생
1. 시스템이 게임 데이터 로드에 실패한다
2. 시스템은 gamesAsync.when의 error 브랜치를 실행한다
3. 시스템은 화면 중앙에 빨간색 alertCircle 아이콘을 표시한다
4. 시스템은 "Error loading games" 메시지를 표시한다
5. 시스템은 error.toString()을 표시한다
6. 시스템은 파란색 "Retry" 버튼을 표시한다

#### 시나리오 9: Retry 버튼 클릭
1. 사용자가 "Retry" 버튼을 클릭한다
2. 시스템은 ref.invalidate(gamesByTypeProvider)를 호출한다
3. 시스템은 Provider를 초기화한다
4. 시스템은 게임 데이터를 다시 요청한다
5. 시스템은 로딩 인디케이터를 표시한다

#### 시나리오 10: 빈 결과
1. 사용자가 특정 카테고리를 선택한다
2. 시스템은 filteredGames.isEmpty를 확인한다
3. 시스템은 _buildEmptyState()를 호출한다
4. 시스템은 중앙에 회색 inbox 아이콘을 표시한다
5. 시스템은 "No games found" 메시지를 표시한다
6. 시스템은 "Try changing your filters" 안내 메시지를 표시한다

### 게임 카드 정보 표시

#### 게임 카드 구성
- 시스템은 각 게임 카드에 다음 정보를 표시한다:
  - 상품 이미지 (16:9 비율, ClipRRect)
  - 게임 상태 배지 (좌측 상단): Active(녹색) / Drawing(보라) / Ended(회색)
  - 게임 타입 배지 (우측 상단): Daily(핑크) / Select(보라) / Vibe(파랑)
  - 게임 제목 (최대 2줄, overflow: ellipsis)
  - 참가자 수 (users 아이콘 + "명")
  - 총 블록 수 (grid 아이콘 + K/M 포맷)
  - 필요 Pick 수 (target 아이콘 + 숫자)
  - 당첨자 수 (trophy 아이콘 + "명")
  - 원가 (취소선, 할인 시만 표시)
  - 현재가 (파란색, 굵은 글씨, ₩ 기호)
  - 남은 시간 (clock 아이콘 + 텍스트, 빨간색)

#### 이미지 로딩 상태
1. 시스템은 Image.network()를 사용하여 이미지를 로드한다
2. 시스템은 로딩 중 loadingBuilder를 호출한다
3. 시스템은 회색 배경(blueWhite)과 CircularProgressIndicator를 표시한다
4. 시스템은 로드 완료 시 실제 이미지를 표시한다
5. 시스템은 로드 실패 시 errorBuilder를 호출한다
6. 시스템은 회색 배경과 image 아이콘을 표시한다

## 2.3 GameScreen (게임 플레이)

### 화면 구성
- 상단 우측에 미니맵이 있다
- 상단 좌측에 Pick HUD가 있다 (선택된 블록 수 / 최대 수)
- 우측 하단에 줌 컨트롤 버튼이 있다 (+ / -)
- 중앙에 게임 그리드가 있다 (CustomPaint)
- 하단에 선택된 블록 바텀시트가 있다 (블록 선택 시)
- 섹션 오버레이가 있다 (3x3 구역 라벨)

### 사용자 행동 시나리오

#### 시나리오 1: 게임 화면 최초 진입
1. 사용자가 게임 카드를 클릭하여 게임 화면에 진입한다
2. 시스템은 URL에서 gameId 파라미터를 추출한다
3. 시스템은 gameProvider(gameId)를 watch한다
4. 시스템은 로딩 인디케이터를 표시한다
5. 시스템은 GraphQL API를 통해 게임 전체 정보를 요청한다
6. 시스템은 데이터 로드가 완료되면 _fullGame과 _game을 설정한다
7. 시스템은 그리드 크기를 설정한다 (예: 1000x1000)
8. 시스템은 GridConfig를 생성한다
9. 시스템은 computeZoomSpec()을 호출하여 Zoom Spec을 계산한다
10. 시스템은 ZoomMapper를 생성한다
11. 시스템은 GridSectionManager.createSections()를 호출하여 3x3 섹션을 생성한다
12. 시스템은 그리드 중앙을 화면 중앙에 배치한다
13. 시스템은 초기 줌 레벨을 selectLevel로 설정한다
14. 시스템은 미니맵을 표시한다
15. 시스템은 Pick HUD를 표시한다 (0/5 picks)
16. 시스템은 줌 컨트롤 버튼을 표시한다
17. 시스템은 게임 그리드를 렌더링한다

#### 시나리오 2: 그리드에서 블록 탭
1. 사용자가 그리드의 특정 위치를 탭한다
2. 시스템은 GestureDetector의 onTapDown을 호출한다
3. 시스템은 탭 위치의 로컬 좌표를 가져온다
4. 시스템은 현재 zoom과 pan을 고려하여 그리드 좌표로 변환한다
5. 시스템은 _tapDebouncer.allow를 확인한다 (150ms 디바운스)
6. 시스템은 gridNotifier.toggleBlock(block)을 호출한다
7. 시스템은 해당 블록이 이미 선택되어 있는지 확인한다

#### 시나리오 3: 새 블록 선택
1. 시스템은 블록이 선택되지 않았음을 확인한다
2. 시스템은 selectedBlocks.length가 _pickMax 미만인지 확인한다
3. 시스템은 블록을 selectedBlocks 리스트에 추가한다
4. 시스템은 블록에 파란색 테두리를 그린다
5. 시스템은 Pick HUD를 업데이트한다 (예: 1/5 picks)
6. 시스템은 하단에 SelectedBlocksSheet를 표시한다
7. 시스템은 바텀시트를 40% 높이로 슬라이드 업한다

#### 시나리오 4: 이미 선택된 블록 재탭 (선택 해제)
1. 시스템은 블록이 이미 선택되어 있음을 확인한다
2. 시스템은 selectedBlocks 리스트에서 블록을 제거한다
3. 시스템은 블록의 파란색 테두리를 제거한다
4. 시스템은 Pick HUD를 업데이트한다 (예: 0/5 picks)
5. 시스템은 selectedBlocks.isEmpty를 확인한다
6. 시스템은 바텀시트를 숨긴다

#### 시나리오 5: 최대 Pick 수 초과 시도
1. 사용자가 이미 5개 블록을 선택한 상태에서 6번째 블록을 탭한다
2. 시스템은 selectedBlocks.length >= _pickMax를 확인한다
3. 시스템은 선택을 거부한다
4. 시스템은 _showSnackBar('최대 5개까지 선택 가능합니다')를 호출한다
5. 시스템은 빨간색 SnackBar를 표시한다

#### 시나리오 6: 줌 인 (+) 버튼 클릭
1. 사용자가 우측 하단의 '+' 버튼을 클릭한다
2. 시스템은 _zoomDebouncer.allow를 확인한다 (500ms 디바운스)
3. 시스템은 _currentZoomLevel >= _zoomSpec.maxLevel인지 확인한다
4. 시스템은 _currentZoomLevel을 1 증가시킨다
5. 시스템은 _snapToLevel()을 호출한다
6. 시스템은 gridBox.size를 가져와 뷰포트 중심을 계산한다
7. 시스템은 그리드 공간의 중심 좌표를 계산한다
8. 시스템은 새 줌 레벨의 스케일을 계산한다
9. 시스템은 뷰포트 중심이 유지되도록 새 pan 값을 계산한다
10. 시스템은 gridNotifier.setZoom()과 setPan()을 호출한다
11. 시스템은 그리드를 확대하여 표시한다
12. 시스템은 미니맵의 뷰포트 박스를 업데이트한다

#### 시나리오 7: 최대 줌 레벨에서 줌 인 시도
1. 사용자가 최대 줌 레벨에서 '+' 버튼을 클릭한다
2. 시스템은 _currentZoomLevel >= _zoomSpec.maxLevel을 확인한다
3. 시스템은 _showSnackBar('최대 확대입니다')를 호출한다
4. 시스템은 줌 레벨을 변경하지 않는다

#### 시나리오 8: 줌 아웃 (-) 버튼 클릭
1. 사용자가 우측 하단의 '-' 버튼을 클릭한다
2. 시스템은 _zoomDebouncer.allow를 확인한다
3. 시스템은 _currentZoomLevel <= _zoomSpec.minLevel인지 확인한다
4. 시스템은 _currentZoomLevel을 1 감소시킨다
5. 시스템은 _snapToLevel()을 호출한다
6. 시스템은 뷰포트 중심 기준으로 줌 아웃을 수행한다
7. 시스템은 그리드를 축소하여 표시한다

#### 시나리오 9: 최소 줌 레벨에서 줌 아웃 시도
1. 사용자가 최소 줌 레벨에서 '-' 버튼을 클릭한다
2. 시스템은 _currentZoomLevel <= _zoomSpec.minLevel을 확인한다
3. 시스템은 _showSnackBar('최소 축소입니다')를 호출한다
4. 시스템은 줌 레벨을 변경하지 않는다

#### 시나리오 10: 그리드 드래그 (팬)
1. 사용자가 그리드 위에서 드래그 제스처를 시작한다
2. 시스템은 GestureDetector의 onPanUpdate를 호출한다
3. 시스템은 details.delta를 가져온다
4. 시스템은 gridNotifier.updatePan(delta.dx, delta.dy)를 호출한다
5. 시스템은 현재 panX, panY에 델타를 더한다
6. 시스템은 그리드를 새로운 위치로 이동한다
7. 시스템은 실시간으로 그리드를 재렌더링한다
8. 사용자가 드래그를 종료한다
9. 시스템은 onPanEnd를 호출한다
10. 시스템은 최종 pan 위치를 저장한다
11. 시스템은 미니맵의 뷰포트 박스를 업데이트한다

#### 시나리오 11: 미니맵 탭
1. 사용자가 미니맵의 특정 위치를 탭한다
2. 시스템은 GridMinimap의 onTap 콜백을 호출한다
3. 시스템은 탭 위치를 미니맵 좌표에서 그리드 좌표로 변환한다
4. 시스템은 해당 그리드 좌표가 화면 중앙에 오도록 pan 값을 계산한다
5. 시스템은 Curve.easeInOut 애니메이션과 함께 그리드를 이동한다
6. 시스템은 미니맵의 뷰포트 박스 위치를 업데이트한다

#### 시나리오 12: 섹션 라벨 표시
1. 시스템은 현재 뷰포트 영역을 계산한다
2. 시스템은 뷰포트와 교차하는 섹션을 필터링한다
3. 시스템은 각 섹션에 대해 라벨 위치를 계산한다
4. 시스템은 GridSectionOverlay를 사용하여 라벨을 그린다
5. 시스템은 라벨을 반투명 배경과 함께 표시한다 (예: "A1", "B2")
6. 사용자가 다른 영역으로 이동한다
7. 시스템은 섹션 라벨을 실시간으로 업데이트한다

## 2.4 GameDetailScreen (게임 상세)

7. 시스템은 정보 패널을 표시한다
8. 시스템은 참가 버튼을 표시한다

#### 시나리오 3: 게임을 찾을 수 없음

2. 시스템은 중앙에 빨간색 alertCircle 아이콘을 표시한다

1. 사용자가 AppBar의 공유 아이콘을 클릭한다
2. 시스템은 공유 기능을 실행한다 (TODO: 미구현)

## 2.5 OptimalGameListScreen (최적가 게임 목록)

### 화면 구성
- 배경은 deepWhite 색상이다
- 게임 카드들이 세로 ListView로 표시된다
- 각 카드는 수평 레이아웃이다 (이미지 좌측, 정보 우측)
- 카드 내에 가격 범위가 표시된다
- 카드 내에 "최적가" 배지가 있다

### 사용자 행동 시나리오

#### 시나리오 1: 최적가 게임 목록 진입
1. 사용자가 홈 화면에서 "OPTIMAL" 탭을 클릭한다
2. 시스템은 TabController의 인덱스를 3으로 변경한다
3. 시스템은 OptimalGameListScreen을 표시한다
4. 시스템은 MockOptimalGameData.getAllGames()를 호출한다
5. 시스템은 게임 데이터를 가져온다
6. 시스템은 ListView.builder를 사용하여 게임 카드 리스트를 생성한다
7. 시스템은 각 게임에 대해 _buildGameCard()를 호출한다

#### 시나리오 2: 게임 카드 표시
- 시스템은 각 게임 카드에 다음 정보를 표시한다:
  - 좌측: 상품 이미지 (80x80, 12px borderRadius)
  - 우측 상단: 게임 제목 (최대 2줄, overflow ellipsis)
  - 우측 중간: 가격 범위 컨테이너
    - Light 그라데이션 배경 (EFF6FF → F9F5FF)
    - 보라색 텍스트
    - "5만원 ~ 10만원" 형식
  - 우측 하단: 정보 행
    - 참여자 수 (users 아이콘, 회색)
    - 남은 시간 (clock 아이콘, 노란색)
    - "최적가" 배지 (Blue-Purple-Pink 그라데이션)

#### 시나리오 3: 가격 포맷팅 (10,000 이상)
1. 시스템은 _formatPrice()를 호출한다
2. 시스템은 price >= 10000인지 확인한다
3. 시스템은 price ~/ 10000을 계산한다 (만 단위)
4. 시스템은 price % 10000을 계산한다 (나머지)
5. 나머지가 0이면: "5만원"
6. 나머지가 0이 아니면: "5.5만원" (소수점 1자리)

#### 시나리오 4: 가격 포맷팅 (10,000 미만)
1. 시스템은 price < 10000을 확인한다
2. 시스템은 정규식을 사용하여 3자리마다 콤마를 추가한다
3. 시스템은 "5,000원" 형식으로 반환한다

## 부록: 공통 동작 정의

### A. 로딩 상태
- 시스템은 데이터 로딩 중 CircularProgressIndicator를 표시한다
- 로딩 인디케이터는 파란색(#5C72F5)이다
- 로딩 인디케이터는 화면 또는 컴포넌트 중앙에 위치한다

### B. 에러 상태
- 시스템은 에러 발생 시 빨간색 아이콘을 표시한다
- 시스템은 에러 메시지를 사용자에게 표시한다
- 시스템은 가능한 경우 "Retry" 버튼을 제공한다

### C. 빈 상태
- 시스템은 데이터가 없을 때 회색 아이콘을 표시한다
- 시스템은 "No data found" 또는 유사한 메시지를 표시한다
- 시스템은 안내 메시지를 표시한다

### D. 네비게이션
- 시스템은 GoRouter를 사용하여 화면 간 이동을 처리한다
- context.go()는 스택을 교체하는 이동이다
- context.push()는 스택에 추가하는 이동이다
- context.pop()은 현재 화면을 닫는다

### E. 상태 관리
- 시스템은 Riverpod Provider를 사용하여 앱 전체 상태를 관리한다
- ref.watch()는 상태 변경을 감지하고 UI를 재빌드한다
- ref.read()는 상태를 한 번만 읽는다
- ref.invalidate()는 Provider를 리셋하고 재로드한다

### F. 애니메이션
- 시스템은 flutter_animate 패키지를 사용하여 애니메이션을 구현한다
- fadeIn(), slideY(), scale(), shake(), shimmer() 등의 애니메이션이 사용된다
- 애니메이션은 일반적으로 300-600ms 지속된다
